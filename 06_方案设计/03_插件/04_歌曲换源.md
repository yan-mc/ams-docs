# 插件 04：歌曲换源（RVC 离线换声）

> 版本：v1.0（2026-10-19）｜作者：vc-researcher｜状态：详细方案草案（待 Lead 评审）
> 依据：`00_总体设计与约定.md`（下称 00）、`05_新方案探讨/可行性探讨.md`（下称 可行性）、`05_新方案探讨/03_开源栈调研/报告.md`（下称 调研）。
> 适用：AMS 插件 `ams.music.song-convert`、服务 `ams-svc-rvc-infer`、任务类型 `convert.rvc`。
> 标注：【决策】=本方案已确定；【待定】=需评审/实验后定；【风险】=已知风险。

## 0. 摘要与决策速览

**一句话定位**：把「分离出的干声 + 目标音源」变成「目标音色的人声」——离线、可批量、可 A/B、可复用参数模板；与分离/工程/混音三个插件串成一条流水线。

**概念澄清（重要）**：本插件做的是 **RVC（VITS 系）音频→音频换声（SVC/VC）**；GPT-SoVITS 是「文本→语音」，不承担换声（可行性 §5.5）。「歌曲换源」= 分离 → 干声换声 → 与伴奏混合导出。

| 决策 ID | 决策 | 理由/依据 |
|---|---|---|
| C1 | 主引擎 = RVC 官方 **2.3.260718** 推理（MIT），复用插件 03 的参数模型与音源库 | 调研 §3；同一套参数降低学习成本 |
| C2 | 任务类型固定为 `convert.rvc`（00 第 8 节），批量 = 同类型的多个 Job，不做独立类型 | 00 任务命名约定 |
| C3 | **长音频由服务层切块**（默认 30 s/块、1 s 重叠、线性交叉淡化），模型/参数在同一 Job 内只加载一次 | 控制显存与取消响应；避免整首一次性推理的内存峰值【决策】 |
| C4 | 输出默认 24-bit/模型采样率 WAV；flac/mp3 为 P1；**默认不改变时长与对轨**（切块补偿采样点） | 后续混音对轨要求 |
| C5 | A/B 必须「响度匹配」后再对比（默认 -16 LUFS 短时匹配，误差 ≤ 0.5 LU） | 避免「响的听起来好」偏差 |
| C6 | 参数模板 + 每音源默认参数（按 voice_id+hash 存在应用 DB，不写音源目录） | 00 第 6 节：音源目录不强制旁车 |
| C7 | 质量检查只做「自动指标 + 警告」，不当场删除产物；用户可强制导出 | 避免误杀；指标留档 |
| C8 | 与分离/混音联动采用「产物引用 + 显式交接」，不自动串联执行 | 用户可控、可回溯 |
| C9 | 零样本 SVC（MeanVC2）/整曲生成（ACE-Step 等）P2，不作为本插件 P0 能力 | 可行性与调研结论 |

**Top 风险**：① 不同音源/参数下音质波动大，用户预期管理（§13）；② 切块接缝/对轨偏差（§5.4、§9）；③ 与训练/分离争 GPU（§7.5）。

## 1. 目标与非目标

### 1.1 目标（可验收）

| ID | 目标 | 量化/验收 |
|---|---|---|
| G1 | 单文件换声：选干声 + 音源 + 参数 → 输出目标音色干声 | 4 分钟歌曲 ≤ 60 s（4080 Laptop，待实测校准）；失败率 < 1% |
| G2 | 参数可解释、可复用：模板/每音源默认/最近使用；一键恢复 | 模板 CRUD 通过；应用模板 ≤ 1 次点击 |
| G3 | A/B 对比：原干声 / 换声后 / 换声+伴奏，响度匹配 + 盲听 | 响度差 ≤ 0.5 LU；切换无爆音 |
| G4 | 批量：多文件/多音源矩阵，队列可见、可取消、可重试 | 20 个文件批处理不崩；取消 ≤ 2 s 生效 |
| G5 | 质量检查：自动指标 + 警告 + 产物保留 | 指标写入 artifacts；静音/削波/长度异常 100% 检出 |
| G6 | 与工程/分离/混音联动：产物落工程目录、可一键交给混音 | 交接后工程 project.json 记录完整 |
| G7 | AI 可完整操作：提交/查询/取消/建议参数/A-B 报告 | 11 个 `music_convert_*` 工具（§8） |
| G8 | 许可干净且可追溯：RVC MIT；输出带 AI 标识与音源许可备注 | 许可矩阵 §10 通过；产物 metadata 可查 |

### 1.2 非目标

| 非目标 | 说明 |
|---|---|
| 不做分离 | 输入干声来自插件 02 人声分离或用户导入；本插件不内置分离（可用 RVC 内置 PyMSS 兜底，但产品路径走分离插件） |
| 不做 TTS/配音 | 文本→语音在插件 05 TTS；GPT-SoVITS 不用于换声 |
| 不做混音/母带 | 只输出换声干声 + 交接数据；混音在插件 08 |
| 不做实时换声 | 实时在插件 03 变声器 |
| 不做训练 | RVC 训练在插件 01 音源炼制；本插件只消费音源 |
| 不做音高/时值编辑（修音） | P1 仅在插件 08/评测联动；本插件只做「音高整体移调」 |
| 不做整曲生成/伴奏生成 | 见可行性 §7（ACE-Step 等 P3） |
| 不做 macOS/Linux | 00 第 1 节：Windows 10/11 x64 |

## 2. 用户与场景

### 2.1 用户角色

| 角色 | 诉求 | 关键差异 |
|---|---|---|
| 翻唱爱好者 | 拿分离好的干声换成喜欢的音源，导出带伴奏成品 | 想「一键」，不太看参数 |
| 调参型用户 | 反复对比不同 index/pitch/protect，找最佳 | 要 A/B、批量矩阵、模板 |
| 音频工程用户 | 与伴奏对轨、后续混音/母带 | 要时长/采样率一致、无接缝、可交接 |
| AI 协作用户 | 让 Agent 选音源、给参数建议、跑 A/B、批量 | 要工具化与可复现 |
| 批量创作者 | 多首歌/多个音源矩阵生产 | 要队列、吞吐、失败重试 |

### 2.2 场景表

| 场景 | 输入 | 目标 | 关键功能 | 验收点 |
|---|---|---|---|---|
| S1 单曲翻唱 | 分离干声 + 伴奏 | 目标音源干声 | 单文件、A/B、质量检查、导出 | 与伴奏时长一致；无爆音 |
| S2 音源试听 | 10–30 s 干声 | 判断音源像不像 | 快速预览（只跑前 30 s） | ≤ 15 s 出结果 |
| S3 批量生产 | 多首干声 | 同一音源批量 | 队列/并发上限/失败重试 | 20 文件可完成/可恢复 |
| S4 参数对比 | 同一干声 | 多组参数/多音源 | 批量矩阵 + A/B 面板 + 指标排序 | 一键生成 N 个版本 |
| S5 工程流水线 | 工程内的 stems | 进入混音 | 交接 + 对轨偏移 + 响度匹配 | project.json 记录 + 混音可读 |
| S6 AI 协作 | 自然语言 | 全流程 | 参数建议/提交/查询/取消 | 工具可审计 |

### 2.3 AI 操作场景

| 能做 | 不能做（需人确认） |
|---|---|
| 读工程/分离产物，自动建换源任务 | 删除原文件/覆盖已有产物（必须显式 overwrite=true） |
| 根据源 f0/性别推荐 pitch 与参数模板 | 承诺「一定像」（需 A/B 试听） |
| 跑预览（30 s）→ 给 A/B 指标 → 建议下一组参数 | 未经确认的批量付费级长任务（建议先确认上限） |
| 批量提交/查询/取消/重试 | 修改音源库文件 |
| 生成 A/B 报告与质量清单 | 直接把产物上传网络（默认不联网） |

### 3.2 参数（P0 完整表，与插件 03 共享命名）

| 参数 | 范围/默认 | 作用 | 备注 |
|---|---|---|---|
| voice_id | 音源库 | 目标音色 | 绑定 pth+index 与 hash |
| pitch | -24…+24，默认 0 | 整体移调（半音） | 男→女通常 +12；自动建议见 F-14 |
| f0_method | fcpe/rmvpe/harvest/pm/dio，默认 fcpe | 音高提取 | 歌曲建议 fcpe 或 rmvpe |
| index_rate | 0…1，默认 0.75 | 检索增强 | 无 index 强制 0 |
| protect | 0…0.5，默认 0.33 | 保护清辅音 | 齿音重时上调 |
| rms_mix_rate | 0…1，默认 0.25 | 响度包络混合 | 与原始音量一致性 |
| filter_radius | 0…7，默认 3 | 中值滤波 | 降破裂音 |
| resample_sr | 0/32000/40000/48000，默认 0（跟模型） | 输出重采样 | 与伴奏采样率对齐时用 |
| chunk_seconds | 10–60，默认 30 | 切块长度 | 长音频内存控制 |
| overlap_seconds | 0.2–2，默认 1 | 块间重叠 | 接缝交叉淡化 |
| output_format | wav/flac/mp3，默认 wav | 输出格式 | mp3 P1 |
| bit_depth | 16/24，默认 24 | wav 位深 | — |
| normalize | none/peak/lufs，默认 none | 输出归一 | 响度匹配在 A/B 层做 |
| overwrite | bool，默认 false | 覆盖已有产物 | 需显式确认 |

### 3.3 单文件与预览（P0 细节）

- 输入校验：存在/可读/时长 ≥ 1 s/采样率可解析/通道 ≥ 1；立体声默认降混单声道（提示）；超长（> 15 min）警告。
- 预览：固定截取「人声能量最高或用户选择的 30 s 片段」，用与正式任务相同参数，产物写缓存不进工程；预览结果可一键「用此参数正式跑」。
- 结果页：波形（原/新叠加或对比）、f0 曲线叠加（音高偏移可视化）、指标卡、A/B 播放器、导出按钮。

### 3.4 队列与批量（P1 细节）

- 队列字段：序号、输入文件、音源、模板、状态、进度、RTF、预计剩余、产物、错误。
- 并发：显存型任务**全局串行**（00 第 8 节 GPU 锁）；同一 Job 内单模型多文件可复用加载（参数一致时）。
- 批量矩阵：N 个干声 × M 个音源 × K 组参数 = 任务清单（去重）；页面按矩阵展示，支持只保留最佳（人工标记）。
- 取消：当前块完成后停止（≤ 2 s 响应），清理临时文件，保留已完成产物。
- 恢复：Job 持久化；服务崩溃后标记 `interrupted`，可「重跑此项」；已成功产物不重复生成（幂等 key = 输入 hash + 音源 hash + 参数 hash）。

### 3.5 参数模板（P0）

| 内置模板 | 场景 | 关键参数 |
|---|---|---|
| 男→女（+12） | 常见跨性别换声 | pitch +12、index 0.75、protect 0.33、rms 0.25、fcpe |
| 女→男（-12） | 反向 | pitch -12、protect 0.4、index 0.7 |
| 同性别微调（0） | 保持音域 | pitch 0、index 0.8、protect 0.3 |
| 高相似（像音源） | 优先相似度 | index 0.9、protect 0.4、f0=rmvpe、filter 3 |
| 稳健全曲 | 优先无爆音 | index 0.65、protect 0.5、rms 0.3、filter 4 |
| 气声/轻声 | 气声多 | protect 0.45、rms 0.4、index 0.7 |

- 模板字段与插件 03 预设同构（schema_version、params、适用场景、说明）；导入导出 JSON；**不绑定音源**。
- 每音源默认：首次成功任务后提示「是否保存为该音源默认参数」；存应用 DB（voice_id+hash），音源文件变化（hash 变）时提示重置（避免张冠李戴）。

### 3.6 质量检查（P0 指标表）

| 指标 | 算法 | 阈值（建议，可配） | 失败处理 |
|---|---|---|---|
| 静音/近静音 | 输出 RMS < -50 dBFS 占比 | > 90% → 警告 | 警告+拒绝导出（可强制） |
| 削波 | 峰值 ≥ 0 dBFS 样本数 | > 0.01% → 警告 | 建议 normalize/降增益 |
| 长度差 | 输出 vs 输入时长 | > ±50 ms → 警告 | 检查切块补偿/取消 |
| 音高偏差 | 输出 f0 vs 输入 f0+pitch（voiced 帧） | RMSE > 60 cents → 警告 | 建议换 f0 方法/protect |
| 相似度 | 输出 vs 音源参考样本（若有）余弦 | < 0.65 → 提示 | 提示 index/pitch 调整 |
| 漂移/接缝 | 块边界能量突变检测 | 突变 > 6 dB → 警告 | 增大 overlap/换参数 |
| 可懂度（可选） | DNSMOS/UTMOS（评测插件） | OVRL < 2.5 → 警告 | 建议降 index/查音源质量 |
| 时长一致性（A/B） | 与伴奏对比 | 偏移 > 10 ms → 警告 | 自动对轨建议（P2） |

【决策】质量检查在任务内自动执行；警告不阻塞导出，但导出对话框必须列出警告；「强制导出」需勾选确认。

### 3.7 联动（P0 细节）

| 联动 | 方式 | 数据 |
|---|---|---|
| 人声分离（插件 02） | 分离结果页「一键换源」→ 预填干声/伴奏/工程 | stems 路径、工程 ID、采样率 |

### 4.4 关键交互流程

| 流程 | 步骤 | 失败分支 |
|---|---|---|
| 单曲换源 | 选干声→选音源→套模板→提交→进度→质量检查→A/B 试听→导出/交接 | 模型/显存错误：错误卡+建议；可重试 |
| 预览 | 选中片段（默认能量最高 30 s）→ 同参数跑 preview → 听完点「用此参数正式执行」 | 预览失败不改正式任务 |
| 批量矩阵 | 勾选 N 干声 × M 音源 → 生成任务清单 → 队列执行 → 矩阵视图标记最佳 | 单条失败不影响其余；可重试 |
| 从分离导入 | 分离结果页点「一键换源」→ 自动填干声/伴奏/工程 → 页面待提交 | 缺伴奏：只做干声换源 |
| 交给混音 | 结果页「交给混音」→ 写交接清单 → 跳转混音页 | 工程未绑定：提示先绑定/另存 |
| 参数调优 | A/B + 指标卡 → 改参数 → 再次预览/正式跑（可复用上版模型缓存） | 无改善：提示音源/干声质量上限 |

### 4.5 任务状态与按钮映射

| Job 状态 | 页面表现 | 可用操作 |
|---|---|---|
| queued | 灰色「排队中（原因：GPU 被实时变声占用）」 | 取消、调优先级（P1） |
| running | 进度条+阶段+chunk i/n+RTF | 取消、看日志 |
| succeeded | 产物卡+质量卡+「A/B」「导出」「交给混音」 | 全部 |
| failed | 错误卡（错误码+建议+重试） | 重试、导出诊断包、改参数 |
| cancelled | 灰色+临时文件已清理 | 重跑 |
| interrupted（重启后） | 黄色「已中断」 | 续跑（P1）/重跑 |

## 5. 技术架构与依赖

### 5.1 进程与数据流（与 00 第 3 节 一致）

    Client 页面（convert）
       │ HTTP/SSE（Gateway API）
       ▼
    Gateway（任务队列 + GPU 锁 + 产物库 + project.json 维护）
       │ Job: convert.rvc → 拉起/复用服务进程
       ▼
    ams-svc-rvc-infer（Python，独立运行时，单任务进程可复用于同参数批量）
       ├─ 模型加载（pth + index，RVC 2.3.260718 推理代码）
       ├─ 预处理（解码/重采样/降混/切块/静音检测）
       ├─ 逐块推理（f0 → HuBERT 特征 → 检索 → 生成；GPU）
       ├─ 合并（重叠交叉淡化、采样点补偿、重采样到目标）
       ├─ 后处理（归一/限幅/质量指标）
       └─ 写产物 + 写 metrics.json + 回传 events
       ▼
    voices/<名称>/<名称>.pth(+.index)   ← 只读
    projects/<id>/vocals/…             ← 产物
    AMS_HOME/cache/convert/<job>/      ← 临时块/日志（成功后清理）

- 插件/页面**不直接**拉 Python；一切经 Gateway（00 第 3 节/第 8 节）。
- 服务支持「一次性 Job 模式」：每次 Job 独立进程（简单、隔离）或「常驻模式」批量复用模型；【决策】默认一次性，批量时由 Gateway 保持进程并传多个输入（优化 P1）。

### 5.2 RVC 推理调用（版本/接口边界）

| 项 | 约定 |
|---|---|
| RVC 版本 | 官方 **2.3.260718**（MIT）；推理入口以该版本 `infer/lib` 的推理 API 为准【待定：以子模块/包方式固定 commit】 |
| 模型格式 | RVC v2 `.pth`（含 config/info/sr/f0/version）；`.index`（faiss，v2=768 维） |
| 采样率 | 跟模型（通常 40k/48k）；输入任意采样率由服务重采样 |
| 参数映射 | 见 §7.2（与 RVC 官方推理参数一一对应） |
| 依赖 | PyTorch（cu121/cu128）、torchaudio、librosa、soundfile、faiss-cpu/gpu、numpy、scipy、ffmpeg（LGPL 构建） |
| GPU 需求 | 推理显存 ~2–3 GB（40k/48k v2 + index）；CPU 可跑但慢（RTF ≥ 1，明确提示） |
| 线程 | 单 Job 单推理线程；GPU 锁保证全局串行 |

### 5.3 切块、合并、对轨与采样率（C3/C4）

| 环节 | 规则 | 理由 |
|---|---|---|
| 切块 | 默认 30 s，重叠 1 s；在静音/低能量点优先切（若切点落在有声段则强制固定切点） | 降低接缝感；内存有界 |
| 推理 | 每块独立完整推理（不要用模型内部长序列），保证行为与官方单次推理一致 | 可取消、可并行（单 GPU 串行） |
| 合并 | 重叠区线性交叉淡化（total 1 s）；块边界采样点补偿，保证总时长 = 输入时长 | 避免接缝爆音与时长漂移 |
| 重采样 | 模型输出 → 目标采样率（默认跟模型/伴奏）；用 soxr/speexdsp 高质量 | 与伴奏对齐 |
| 对轨 | P0 保时长一致（零偏移）；P2 用互相关估计与伴奏的最佳偏移（±200 ms）并写交接数据 | 混音需要 |
| 降混 | 立体声输入默认均值降混单声道；提示用户（RVC 单声道输出） | 模型单声道 |
| 静音 | 全静音块跳过推理（直接输出静音），降低耗时 | 长曲效率 |

### 5.4 资源、并发与取消

- 显存型任务全局串行（00 第 8 节）；实时变声会话（插件 03）优先，换源 Job 排队。
- 同一 Job 内复用已加载模型（批量多文件、同音源参数一致时）→ 省 5–10 s/文件。
- 取消：置取消标志 → 当前块完成后停止 → 清理 cache → 若产物已部分写入，删除半成品（写临时文件+原子改名）。
- 断点：P1 支持「已完成块复用」（cache 按 输入hash+块序号+参数hash），网关重启后可续跑。
- CPU 兜底：GPU 不可用时允许 CPU 推理（RTF ≥ 1，页面明确提示预计耗时，可取消）。

### 5.5 依赖清单（版本/许可）

| 依赖 | 版本（2026-10） | 许可 | 用途 |
|---|---|---|---|
| RVC 推理代码 | 2.3.260718 | **MIT** | 主引擎 |

### 5.6 关键实现约束（不写代码，只约定）

1. 每个 Job 的产物必须**幂等**：相同（输入 hash+音源 hash+参数 hash）重复执行覆盖同一相对路径，不产生无限副本。
2. 所有中间文件在 `cache/convert/<job>/`，成功/失败后清理（保留日志与 metrics）。
3. 采样率/时长/通道的最终值写入 artifacts.meta，供混音插件直接消费。
4. 模型加载失败必须回滚并释放显存；不得让进程处于半加载状态。
5. 任何用户可见的「预计时间」用最近 RTF 移动平均估算，误差 ±30% 标注。

| `music_convert_export` | 导出（格式/覆盖/压缩包） | job_id 或产物、格式 | 60 s | 带 AI 标识 |

每个工具：JSON Schema、超时、错误码（00 第 9 节）；**只走 Gateway**；返回原始 job/artifacts 结构。

### 8.2 典型 Agent 流程

| 用户说 | 动作序列 |
|---|---|
| 「把这首翻唱换成爱莉希雅」 | 读工程 stems → list_voices → start（模板=男→女+12）→ 轮询 status → 质量检查 → 报告 |
| 「为什么不像」 | status → ab（相似度/音高指标）→ suggest（调 index/protect/pitch）→ preview → 建议下一组 |
| 「帮我跑 5 个音源对比」 | batch（1 干声 × 5 音源，模板统一）→ 等完成 → ab 汇总 → 推荐前 2 |
| 「批量处理这 10 首」 | batch → 队列监控 → 失败清单 → 重试 |
| 「交给混音」 | handoff_mix → 确认工程记录 → 打开混音页 |

### 8.3 Skills

| Skill | 内容 |
|---|---|
| `ams-翻唱工作流` | 分离 → 换声 → A/B → 混音 → 导出；参数模板与试听顺序；质量门限 |
| `ams-换声参数调优` | pitch/index/protect/rms 与听感的对应关系；常见问题（电音、齿音、闷、断续）排查表 |

## 9. 错误处理 / 降级 / 性能指标

### 9.1 失败模式矩阵

| 失败 | 检测 | 处理 | 用户可见 |
|---|---|---|---|
| 输入损坏/截断 | 解码失败 | 报错并定位文件 | 错误卡 |
| 音源与 index 不配 | 维度校验 | index_rate=0 或提示换 index | 警告 |
| 音源文件被替换 | hash 比对 | 提示重置默认参数 | 提示 |
| 显存不足 | OOM 异常 | 减小 chunk/CPU 兜底 | 建议 |
| 切块接缝爆音 | 能量突变检测 | 增大 overlap/换切点 | 警告 |
| 输出静音 | RMS 检查 | 失败并给排查（模型/参数/输入） | 错误卡 |
| 取消 | 用户操作 | 当前块后停止、清理 | 正常 |
| 服务崩溃 | 退出码/心跳 | Job 标 interrupted，可重跑 | 提示 |
| 磁盘满/文件锁 | 写入异常 | 报错+清理临时 | 错误卡 |
| 网关重启 | 启动扫描 | running→interrupted；可续跑（P1） | 任务列表显示 |

### 9.2 降级链

    GPU 全速（fcpe + index）
      → GPU 稳健档（chunk 30→20、overlap 1.5、index 降 0.6）
      → CPU 模式（明确 RTF≥1、预计时间翻倍以上）
      → 拒绝提交并说明原因（无可用执行单元/显存长期不足）
    采样率：模型原生 → 目标重采样（soxr 高质量）
    输出：wav24 → wav16 → flac（磁盘紧张时由用户选择）

### 9.3 性能指标（目标，待 S9/S8 实测校准）

| 指标 | P0 目标 | P1 目标 | 测量方法 |
|---|---|---|---|
| 单曲 RTF（4 min，40k，index 0.75，4080 Laptop） | ≤ 0.25（≤ 60 s） | ≤ 0.15（≤ 36 s） | 任务计时（含加载，不含队排） |
| 预览（30 s） | ≤ 15 s | ≤ 8 s | 任务计时 |
| 模型加载 | ≤ 10 s | ≤ 6 s（进程复用跳过） | 事件时间戳 |
| index 加载（130 MB） | ≤ 3 s | ≤ 2 s | 事件时间戳 |
| 显存峰值 | ≤ 3 GB | ≤ 2.5 GB | 服务上报 |
| 内存（15 min 长音频） | ≤ 2 GB 增长 | 同 | 采样 |
| 取消响应 | ≤ 2 s | ≤ 1 s | 事件时间戳 |
| 时长误差 | ≤ ±50 ms | ≤ ±10 ms | 产物 vs 输入 |
| A/B 响度匹配误差 | ≤ 0.5 LU | ≤ 0.3 LU | pyloudnorm |
| 幂等重复率 | 100% 不产生重复产物 | 同 | 重复提交同参数 |

### 9.4 日志与指标

- 结构化日志（JSONL）落 `logs/convert/`，按天滚动；产物旁放 `metrics.json`。
- 每次任务记录：阶段耗时、RTF、显存峰值、警告、参数快照、引擎版本、音源 hash——支撑复现与回归。
- 无遥测、无上传（00 第 12 节）。

- 产物写入用「临时文件 + 原子改名」，崩溃不留半成品。

## 11. 测试与验收

### 11.1 测试矩阵

| 维度 | 取值 | 用例（估） |
|---|---|---|
| 输入时长 | 5 s / 30 s / 4 min / 15 min | 8 |

| 批量 | 1×1 / 5×1 / 1×5 / 5×3（矩阵） | 6 |
| 异常 | 损坏文件/磁盘满/服务杀/取消/网关重启 | 8 |
| 联动 | 分离→换源、工程写入、混音交接 | 6 |
| 长稳 | 连续 20 首批量 | 2 |

### 11.2 夹具与自动化

- 固定夹具：3 段干声（男/女/童声，30 s 与 4 min）、1 段纯音乐（应被拒绝/告警）、1 个损坏 wav。
- 金标回归：固定音源+参数，断言「输出非静音、时长一致、峰值 ≤ -0.5 dBFS、f0 与源曲线形状一致（按 pitch 平移后 RMSE < 40 cents）」。
- A/B 自动化：响度匹配后计算两版 LUFS 差、时长差、相似度；阈值写进 CI 报告。
- 崩溃/恢复：kill 服务进程、重启网关，断言 Job 状态与可重跑。
- 幂等：同参数重复提交两次，产物数量不变。

### 11.3 验收标准（P0）

1. 4 分钟歌曲在 4080 Laptop 上 ≤ 60 s 完成，输出与伴奏时长一致（±50 ms），无爆音/静音。
2. 预览 ≤ 15 s；参数/模板/最近使用可复现同一产物（同参数同 hash 一致）。
3. A/B 三轨可切换，响度匹配误差 ≤ 0.5 LU；切换无点击声。
4. 质量检查指标全部落盘并展示；严重异常（静音/长度错）100% 拦截。
5. 批量 20 文件可完成；取消 ≤ 2 s；网关重启后任务可续跑/重跑（P1）。
6. 与分离/工程/混音联动各 1 条端到端用例通过。
7. AI 工具全部可调用，错误码/超时正确。
8. 许可与 AI 标识核对通过。

## 13. 风险与开放问题

### 13.1 风险

| ID | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | 不同音源/参数音质波动大，用户对「像不像」预期落空 | 满意度 | 预览先行 + A/B + 指标卡 + 模板；文案明确「音源决定上限」 |
| R2 | 切块接缝、时长漂移、对轨偏移 | 成品可用性 | 重叠+交叉淡化+采样点补偿；长音频专项测试；P2 自动对轨 |
| R3 | 与训练/分离/实时争 GPU，批量卡顿 | 稳定性/吞吐 | 全局 GPU 串行 + 队列 + 预计时间 + 允许夜间批处理（P1） |
| R4 | 取消/崩溃留下半成品/孤儿进程 | 数据一致性 | 临时文件+原子改名；网关扫描清理；幂等重跑 |
| R5 | 音源文件被替换（hash 变）导致参数失效 | 效果异常 | hash 校验 + 提示；默认参数按 hash 记忆 |
| R6 | 上游 RVC 升级接口变化 | 维护 | 锁版本 + 适配层 + 金标回归 |
| R7 | 长音频内存/显存峰值 | 崩溃 | 切块 + 内存上限 + 分块复用；显式限制 15 min |
| R8 | 输出许可/声音权问题（用户未授权音色） | 法律 | AI 标识 + 授权提示 + 音源许可展示；不内置音源 |
| R9 | 批量产物命名/覆盖冲突 | 数据丢失 | 默认不覆盖 + 唯一后缀 + 二次确认 |
| R10 | 评测指标（相似度）依赖外部模型/网络 | 功能降级 | 指标本地化；缺失时跳过并标注【待定】 |

### 13.2 开放问题【待定】

1. 长音频上限（15 min）是否可配？是否需要「整轨超长」模式（更低内存、更大接缝风险）。
2. 是否在 P1 引入「自动对轨 + 响度匹配」直接交给混音（需要与插件 08 对齐数据格式）。
3. 相似度指标用哪个本地模型（WavLM/ECAPA/3D-Speaker）及许可。
4. 批量矩阵是否需要「夜间队列/暂停/限时」策略。
5. 输出是否默认加入「AI 生成」文件名后缀（与混音/导出策略统一）。
6. 是否复用插件 03 的引擎进程常驻以省模型加载（复杂化 GPU 抢锁逻辑）。
