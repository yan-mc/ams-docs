## 0. 一页结论（TL;DR）

1. **本插件只做一件事：把用户素材“炼制”成 RVC v2 音源**，产物严格落到 00 第 6 节的音源库格式：AMS_HOME\voices\<名称>\<名称>.pth 与同名 <名称>.index；不做 TTS 微调、不做 SVS 声库、不做分离/换声/评测器本体（分属其它插件或共享服务）。【事实：任务范围】
2. **主后端固定为 RVC 官方 2.3.260718**（MIT，2026-08-03 发布，仍在活跃维护）：Python 3.12 + torch 2.7.1（N 卡 cu118 / 50 系 cu128，AMD·Intel·CPU 用 CPU 依赖包 + Windows DirectML）；2.3 原生支持“特征/训练/索引中断续跑、单卡不用 DDP、FCPE 音高提取”，正好覆盖本插件的断点续训与 FCPE 需求。【事实：03 调研 §3.1/§3.2 + RVC README 2.3 快照】
3. **形态 = Host 插件 ams.music.trainer（任务/工具/skill/页面）+ 独立后端服务 ams-svc-rvc-train（Python 3.12 训练运行时）+ 本地网关 Job（train.rvc）**；训练产物由本服务原子写入 voices/ 并调用 /voices/scan 注册到音色库；全程不直接操作 GPU 之外的系统环境（环境/驱动/模型下载由启动器负责）。【决策】
4. **P0 功能闭环**：素材导入（引用数据集）→ 与数据集插件联动校验（数据集快照 + 训练前预检）→ 配置向导/预设 → 一键训练（预处理→F0→HuBERT 特征→训练 G/D→建 index）→ 曲线/日志/进度 → 试听 A/B → 轻量评测 → 导出并注册音源库。P1：断点续训增强、失败诊断、提取小模型、模型融合；P2：多卡/多任务、32k/v1 兼容、批量训练、UVP 导出。【决策】
5. **数据要求**：单说话人、10–30 分钟干净人声（硬下限 5 分钟，低于则警告并要求确认）；推荐 15–30 分钟；训练默认 v2 + f0=1 + 48k（唱歌）/40k（说话）；20 epoch 起步，20–50 为常规区间，最大 1000。【推断：03 调研 §6.1 + RVC README“推荐至少 10 分钟”】
6. **资源基线**（RTX 4080 Laptop 16GB，03 调研 §10.3）：10 分钟数据 200 epoch 约 1–3 小时、显存 5–8 GB；10 分钟 20 epoch 约 10–20 分钟；显存不足时自动降 batch 重试；CPU 训练仅用于冒烟，不承诺可用时长。【推断】
7. **AI 可全流程操作**：G1–G5 五个阶段（预检/开训/监控/验收/导出）全部可由 music_train_* 工具 + Gateway API 完成；但“试听盲评、命名与授权声明、是否发布分享”三项必须人工确认并留痕（voice.json/审计）。【决策】
8. **最大技术风险**：2.3.260718 仍是 WebUI 单体工程（webui.py + gradio），需要把训练相关代码抽成 headless 调用；本方案采用“固定版本 vendored 代码 + 薄适配层”，并用 M0 Spike 验证 resume/FCPE/参数与产物格式。【风险+待定】

| 编号 | 决策 | 理由 |

## 1. 定位与非目标

### 1.1 一句话定位

**ams.music.trainer 是“音源工厂”**：把用户在数据集插件里准备好的干净人声，按 RVC 官方 2.3.260718 的流水线训练成可被换声/变声直接消费的 RVC v2 音源（pth+index），并完成质量评估、试听、导出与音源库注册；它既是给人用的向导式训练台，也是 AI Agent 可编排的“训练作业”能力。

### 1.2 非目标（明确不做什么）

| 非目标 | 归属 |
|---|---|
| TTS 音色微调（GPT-SoVITS / Qwen3-TTS 等） | TTS 插件（05/06 分册，独立 tts_voices 目录） |
| SVS 声库训练（DiffSinger/MakeDiffSinger 等） | V 家填词分册（svs_voicebanks，P1） |
| 人声分离/去混响/去和声 | 人声分离插件（pymss/MSST） |
| 换声/翻唱/实时变声推理 | 歌曲换源、变声器插件 + 共享 rvc-infer 服务 |
| 深度评测平台（SDR/DNSMOS 体系化 benchmark） | 评测器插件（本插件只做训练相关轻量指标） |
| 数据集切片/ASR/强制对齐/清洗的“重活” | 数据集工作室插件（本插件只做训练前预检） |
| 模型市场/下载/更新/驱动安装 | 启动器（模型目录组件） |
| 音频编辑/混音/母带 | 混音母带插件 |

### 1.3 与 00 及兄弟分册的边界（含一处【偏差】声明）

- 00 第 9 节把 trainer 描述为“RVC 训练（P0）；数据集校验/清洗”，同时另设 dataset 插件“素材导入/切片/ASR/对齐/质量报告/清洗”。为避免双头，本分册【偏差】定义为：**清洗与质检的权威实现归数据集插件；trainer 只消费“已就绪数据集快照”并做训练专属预检（时长/单说话人/采样率/电平/命名/显存/许可声明）**。若数据集插件不可用（P0 首版），trainer 可降级为“用户直接给文件夹+本地预检”。【决策】
- 00 第 6 节规定音源库唯一标准为该目录格式；UVP 只是可选导入格式（00 第 15 节术语）。因此本插件 **默认输出 voices/ 目录格式**，UVP 导出放 P2。
- 与变声/换源的接口是**文件契约**（voices/<名称>/<名称>.pth+.index），不引入私有元数据依赖；voice.json 仅为可选旁车。

## 2. 目标用户与场景

### 2.1 用户画像

| 用户 | 诉求 | 关键约束 |
|---|---|---|
| 创作者/翻唱爱好者（主） | 用自己的声音或授权音色训练 RVC 音源，用于翻唱/实时变声 | 不懂参数，需要向导、默认值、失败诊断 |
| 调音师/二创作者（次） | 批量试验不同 epoch/采样率，比较效果；融合模型 | 需要曲线、A/B、中间产物、可复现参数 |
| AI Agent（新） | 通过工具/任务 API 完成“选数据→训练→评估→导出”全流程 | 需要结构化状态、错误码、可续跑、可审计 |
| 管理员/高级用户（少数） | 管理底模、磁盘、队列、日志 | 需要目录/清理/诊断能力 |

### 2.2 典型场景

| 场景 | 输入 | 过程 | 输出/验收 |
|---|---|---|---|
| S1 一句话炼制（新手） | 一段 15 分钟干声（数据集插件已清洗） | 选“翻唱音色”预设 → 一键训练 → 看曲线 → 试听 A/B | voices/我的音色/我的音色.pth + .index；试听评分≥3 视为通过 |
| S2 老手调参 | 同一数据集，多组采样率/epoch/f0 方法 | 建 2–4 个训练任务排队 → 曲线对比 → 多模型 A/B | 选取最佳模型导出；其余进历史可清理 |
| S3 训练中断恢复 | 训练到 60% 断电/取消 | 重启应用 → 任务列表显示 resumable → 续训 | 从最近 checkpoint 继续，不重复预处理/特征（2.3 原生支持） |
| S4 效果不佳诊断 | 训练完成但电音/破音 | AI 调 music_train_diagnose → 读曲线/日志/指标 → 给建议（加 epoch/换数据/换 f0/降 index） | 诊断报告 + 重新训练任务 |
| S5 已有模型后处理 | logs 里的 G_*.pth 或多个音源 | 提取小模型 / 按 alpha 融合两个音源 | 新音源目录 + 校验/注册 |
| S6 AI 全自动 | 语音指令“用数据集 A 训一个爱莉希雅音色，20 分钟，训完给我试听” | Agent 串联 plan→preflight→start→status→preview→evaluate→export | 全部通过工具完成，人工只做试听确认 |

### 2.3 AI 全流程操作 vs 人工验收（强制分工）

| 阶段 | AI 可执行 | 人工必须确认 | 审计记录 |
|---|---|---|---|
| 数据选择与预检 | 推荐数据集、跑 preflight、指出问题 | 数据来源/授权声明 | job params + dataset snapshot |
| 训练配置 | 按预设/硬件/目标生成参数 | 命名、是否覆盖已有音源 | config 快照 |
| 启动与监控 | 开训/查进度/取消/续训 | 中断决策（是否续） | job 事件 |
| 试听 | 生成 A/B 样本、汇总指标 | 盲听打分（1–5） | voice.json preview |
| 评测 | 自动指标计算 | 阈值是否放行 | metrics.json |
| 导出/注册 | 写入 voices、扫描、校验 | 是否允许导出/分享（含声音权声明） | license 字段 + 操作日志 |

### 3.2 P0 功能要点

#### F01 素材导入
- 主路径：从数据集插件读取“就绪快照”（dataset_id + 切片清单 + 质量报告 + 授权声明），trainer 不复制音频，只记录引用与快照 hash（00 第 7 节“音源与基础模型只存引用”精神）。
- 降级路径：用户直接选择本地文件夹（P0 兜底），trainer 现场做最小扫描（数量/时长/采样率/可解码性），并提示“建议去数据集插件清洗”。
- 支持格式：wav/flac/mp3/m4a 等 ffmpeg 可解码格式；最终统一转 44.1k/48k 立体声临时参考（RVC 内部按目标采样率重采样）。

#### F02 联动校验（训练前预检，Preflight）
预检项与处理策略见 5.7 与 9.1；硬阻断项：总时长 < 5 分钟、单说话人判定失败、无法解码文件比例 > 10%、目标音源名非法/重名未确认、磁盘剩余 < 5 GB、底模缺失、未填写声音授权声明。

#### F03 配置向导
- 预设三档：【决策】翻唱音色（48k v2 f0=1 rmvpe 20–50 epoch）、说话音色（40k v2 f0=1 rmvpe 20 epoch）、快速试验（40k v2 8 epoch + save_every_weights，用于先听效果）。
- 高级参数：采样率、版本、f0 方法、epoch、batch、保存频率、缓存显存、只存最新、保存中间权重、CPU 进程数、底模 G/D、索引开关、随机种子。
- 参数模板可保存/复用（P2 共享）。

#### F04 一键训练（阶段与产物见 5.3）
- 一次点击 = 一个 Gateway Job（type=train.rvc, op=train），页面与 AI 都只通过 Job 操作。
- 阶段失败时保留现场（日志/中间产物），供续训或诊断；失败不自动删除工作区（除非用户选择清理）。

#### F05 断点续训
- 依据 2.3.260718 官方“特征提取/训练/索引可中断续跑”能力；服务在每阶段结束写“阶段完成标记”（manifest），续训时跳过已完成阶段（校验输入 hash 不变）。
- 训练阶段续训：复用工作区最新 G/D checkpoint（官方 train.py 支持自动 resume；具体语义待 M0 Spike 确认）。
- 取消/崩溃后 job 标记 resumable；网关重启后仍可查询（00 第 8 节）。

#### F06 曲线/日志/进度
- 阶段权重：预处理 10%、F0 10%、特征 20%、训练 55%、索引 5%（可按数据量动态调整，后台按实际步数细化）。
- 曲线指标：loss_g、loss_d、loss_mel、loss_kl、loss_fm、lr、epoch/step、每秒步数、显存峰值（若可采样）。
- 日志：结构化行（时间/级别/阶段/消息），保留最近 5000 行入 job ring，完整日志落工作区 log.txt。

#### F07 试听 A/B
- RVC 是“音频→音频”换声，不是文本→语音，试听必须给“源音频”。三种来源：【决策】
  1) 数据集保留切片（训练集自听，检验过拟合/音色像不像）；
  2) 项目内人声/用户上传一段源音频；
  3) 上一次成功任务用过的样本（复用对比）。
- 输出：A = 源音频原声；B = 该模型换声结果；可切换不同 epoch/不同模型；支持盲听（隐藏标签）+ 1–5 评分（相似/自然/清晰/杂音四项）。
- 试听调用共享 rvc-infer 服务（D6）；产物落任务工作区 artifacts/preview/，不写入 voices/。

#### F08 轻量评测
- 自动指标：训练收敛（loss 趋势/异常）、F0 一致性（源 vs 输出的 F0 相关性、RMSE cents）、说话人相似度（目标参考=训练集片段，输出音频的 embedding 余弦）、音质（DNSMOS/UTMOS 或替代指标）、可懂度（若源为说话，ASR 转写 CER；唱歌不强制）、推理耗时/RTF。
- 输出 metrics 表 + 结论建议（通过/可接受/建议重训），写入 voice.json 与工作区 metrics.json；深度评测交评测器插件（eval.run）。
- 阈值不写死在前端，配置化（默认值见 12.3）。

#### F09 导出与注册
- 严格按 00 第 6 节：先写 AMS_HOME\voices\.staging\<uuid>\<名称>.pth/.index → 校验（可被 RVC v2 加载、f0=1、version=v2、index 维度 768/ntotal>0、同名一致）→ 原子 rename 到 voices\<名称>\；失败清理 staging；覆盖需二次确认且旧版备份到 backups\voices\。
- 导出后调用 Gateway /voices/scan 注册（音色库插件消费）；写 voice.json 旁车（可选、删除不影响使用）。
- 训练工作区导出成功后可“保留/清理”让用户选（默认保留最近一次，超过 N 个任务按策略清理）。

#### F10 队列与 GPU 锁
- 训练为显存型任务，独占 GPU；队列展示“前面有几个任务、预计开始时间、当前 GPU 占用”。
- 实时变声会话优先并独占（00 第 8 节）：训练任务在**epoch 边界**让出（不中途杀进程）；若用户要求立即开实时，提示“暂停训练（可续训）”。
- 同一时刻只允许 1 个训练任务（16GB 档）；P2 根据显存允许 2 个小任务并发。

### 3.3 P1/P2 说明
- F11 失败诊断：建立“症状→证据→建议”知识库（见 9.1），AI 工具 music_train_diagnose 复用同一知识库。
- F12 提取小模型：对 logs/G_*.pth 指定 epoch 提取；输出仍需走 F09 的命名/校验流程。
- F13 模型融合：同版本/同采样率/同 f0 的 pth 才能融合；alpha 权重；融合后同样走 F09；记录两个来源音源与授权。
- F15 批量训练：P2，多用于夜间排队；失败隔离，不影响其他任务。
- F18 UVP 导出：UVP v0.1（03 调研 §8 与 voice_pack.schema.json）；主格式仍是 voices/ 目录。

### 4.4 训练队列/GPU 锁交互
- 队列卡片显示排队原因（GPU 被占用/等待实时变声结束/等待前序任务）。
- 取消：先置 stopping，服务在安全点（阶段边界/epoch 边界）退出并保留可续训标记。
- 暂停：仅训练阶段支持，epoch 边界生效；排队任务可“暂停”= 不调度。

### 4.5 训练曲线面板
- 默认画 loss_g/loss_d/loss_mel；可切换 loss_kl/loss_fm/lr/吞吐。
- 健康提示（【推断】经验值，可配置）：曲线整体下降；loss_d 不应长时间为 0/爆炸；出现 NaN/Inf 立即判失败；loss 平台期可提示“可停止并试听”。
- 支持与历史任务曲线叠加对比（同数据集/同参数）。

### 4.6 试听 A/B
- 播放器：单声道/立体声指示、波形、秒数；A/B 同步播放/切换；支持 0.5–2.0 倍速？不需要，保持原速。
- 盲听模式：隐藏 A/B 标签与 epoch 信息，评分后才揭示。
- 评分：相似度/自然度/清晰度/杂音 1–5；备注；保存到 voice.json preview。
- 【风险】试听源音频本身若含伴奏/混响，会误导试听结论 → 提示使用“干声片段”。

### 4.7 失败诊断面板
- 失败卡片：错误码 + 一句话原因 + 证据（日志片段/峰值显存/阶段）+ 建议操作按钮（降 batch 重试/清理缓存/去数据集处理/重新下载底模/改名）。
- 支持“复制诊断报告”，AI 工具返回同结构 JSON。

### 4.8 通知与审计
- 任务完成/失败通知（内核通知 + 可选系统通知）；页面角标。
- 审计：每次训练/导出写 project.json（若从项目发起）或 voice.json（来源/参数/时间/操作者/授权）；日志按天滚动到 AMS_HOME\logs\svc-rvc-train\。

### 5.5 采样率/版本决策
- 【决策】P0 只训练 v2+f0=1；40k 走 RVC 官方“40k 用 v1/40k 配置”的既有分支（旧版行为；2.3 是否变化待 Spike），48k 使用 v2/48k 配置；32k 仅在 P2 开放。
- 唱歌优先 48k（高频/齿音更好），说话优先 40k（训练快、稳定）；同一音源先训 40k 试听，再上 48k 精修是推荐路线。

### 5.6 底模与模型管理
- 目录（与 2.3 README 一致）：AMS_HOME\models\rvc\assets\{hubert_base\,rmvpe\rmvpe.pt,pretrained\,pretrained_v2\,weights\,indices\} 与 AMS_HOME\models\rvc\logs\mute\。
- 由启动器“模型组件”下载并校验 sha256；服务启动时检查完整性，缺则拒绝训练并提示一键安装。
- 训练服务只读模型目录；用户音源模型只在 voices/；不允许把 logs/G_*.pth 直接当音源分享（RVC 只读报告/FAQ 的教训）。
- 【风险】底模/HuBERT/rmvpe 权重的再分发许可需启动器法务清单确认（VCTK 数据许可、ContentVec/HuBERT 权重许可）。

### 5.7 数据要求（Preflight 判据）

| 项 | 硬性要求（阻断） | 推荐 | 说明 |
|---|---|---|---|
| 总时长 | ≥ 5 分钟 | 10–30 分钟（唱歌 15–30） | RVC 官方推荐至少 10 分钟；> 60 分钟需长数据策略（kmeans/分批） |
| 说话人 | 单一音色 | 同一人、同一录音条件 | 多人/多音色会污染；由数据集插件拆分 |
| 采样率/带宽 | 可解码且有效带宽 ≥ 16 kHz | ≥ 40 kHz 源 | 源 16k 只适合 32k 模型，需警告 |
| 底噪/混响 | SNR ≥ 15 dB（警告线），≥ 20 dB 推荐 | 干声、低混响 | 阈值可配置；由数据集插件报告 |
| 削波/爆音 | 削波样本比例 < 1% | 0 | 明显爆音需重录/修复 |
| 静音/空白 | 有效语音占比 ≥ 60% | — | 长静音会被 slicer 丢弃，但浪费时长 |
| 切片数 | ≥ 30 片（警告线） | 100–500 片 | 3–15 秒/片 |
| 授权声明 | 必填（来源/用途/是否商用） | 详细 | 见第 10 节 |
| 目标音源名 | 合法且不重名（或确认覆盖） | 1–64 字符 | 见 6.2 |

### 5.8 资源与容量估算（【推断】，基于 03 调研 §10.3 与 RVC 只读报告实测）

| 场景 | 数据量 | GPU | 预计显存 | 预计耗时 | 备注 |
|---|---|---|---|---|---|
| 冒烟测试 | 1–2 分钟 | 任意 8GB+ / CPU | 2–4 GB | 2–10 分钟 | 只验证流水线通不通 |
| 快速试听 | 10 分钟 | 4080 16GB | 5–6 GB | 8–15 分钟（8 epoch） | 先听音色再决定是否长训 |
| 常规翻唱 | 15 分钟 | 4080 16GB | 6–8 GB | 30–60 分钟（20–30 epoch） | 推荐默认档 |
| 精细翻唱 | 20 分钟 | 4080 16GB | 6–8 GB | 1–3 小时（200 epoch） | 03 调研基线 |
| 说话音色 | 10 分钟 | 3060 12GB | 4–6 GB | 20–50 分钟（20 epoch） | 40k |
| 50 系显卡 | 同上 | 需 cu128 运行时 | 同上 | 同上 | 启动器选择 cu128 变体 |
| CPU 训练 | 1 分钟 | CPU | 内存 4–8 GB | 30–120 分钟 | 仅冒烟/应急，不建议正式训练 |

参考实测（RVC 只读报告）：旧版 4.3 万条 768 维特征索引 129 MB、4.5 万条 134 MB；小模型 pth 约 55 MB。

### 5.9 GPU 锁与并发
- 训练任务申请独占 GPU 锁（00 第 8 节）；排队显示原因与 ETA。
- 实时变声会话优先：训练在 epoch 边界让出；用户可“立即让出（暂停训练）”。
- 同 GPU 同时只跑 1 个训练（16GB）；≥24GB 且小数据可 P2 允许 2 并发（需实测显存）。
- 训练期间禁止同时跑换源批量/分离重任务（GPU 锁自然串行）；CPU 任务（预处理/F0 CPU 模式）可与 GPU 训练并行但受 n_cpu 限制。

### 5.10 官方代码 headless 化策略（关键工程决策）
- 【决策】采用 **“固定版本 vendored 子集 + 适配层”**：把 RVC 2.3.260718 的 infer/（train 相关）、configs、必要工具复制进 ams-svc-rvc-train 的第三方目录（保留 LICENSE/NOTICE），由适配层以 headless 入口调用（不启动 gradio/webui.py）。
- 适配层职责：参数映射（我们的 JSON → 官方函数/命令行参数）、阶段编排与进度上报、日志解析（loss/epoch）、产物定位、异常归一化。
- 升级策略：RVC 新版本先跑“适配层回归”（M0 里的 golden 流程），通过才升级；pin 版本记录在 job.engine。
- 【风险】官方代码与 WebUI/路径/全局 config 耦合较深，抽取时需最小 patch（记录下来形成 patches 清单）；若耦合无法接受，备选方案是 fork 仓库维护 headless 分支（成本更高）。
- 【待定】M0 Spike 需确认：官方 2.3 是否提供不依赖 gradio 的训练 CLI；train.py 参数与旧版差异；resume 的真实语义；FCPE 在训练端是否可选；特征/索引中断续跑的文件级行为。

## 7. Gateway 接口与任务

### 7.1 任务类型与子操作

- 任务类型：**train.rvc**（00 第 8 节命名），一次训练 = 一个 Job；通过 params.op 区分 5 种子操作：

| op | 用途 | P0/P1 | 说明 |
|---|---|---|---|
| train | 全流程训练（预处理→F0→特征→训练→索引→导出→轻量评测） | P0 | 默认 |
| resume | 断点续训 | P0 | 复用同一工作区与阶段标记 |
| build_index | 仅重建索引 | P0 | 训练完成但 index 失败/关闭时补建 |
| extract | 提取小模型（P1） | P1 | 从 logs G_*.pth 指定 epoch 导出 |
| merge | 模型融合（P1） | P1 | 两个同构音源按 alpha 融合 |

- 关联任务类型（不由本插件实现但会调用/被调用）：dataset.validate（数据集插件）、eval.run（评测器插件）、convert.rvc（换源插件，试听复用其推理服务）。

### 7.6 状态机与续训语义

- 状态：queued → running → stopping → cancelled；running → succeeded / failed；failed/cancelled 且工作区完整 → resumable=true。
- 续训条件（全部满足）：工作区存在且未被清理；job.params 与阶段标记 hash 一致；数据快照 hash 一致；底模版本一致；RVC 版本一致。任一不满足 → 提示“需新建任务（不可续）”。
- 续训实现：POST /jobs/{id}/resume 将任务重新入队（attempt+1），服务读取阶段标记跳过已完成阶段，训练阶段自动加载最新 checkpoint（官方 2.3 原生行为）。
- 取消：置 stopping；服务在安全点（文件边界/epoch 边界）退出并落阶段标记；不允许硬杀导致工作区损坏（除非超时强杀并标记不可续）。
- 网关重启：任务记录在 SQLite（00 第 8 节）；运行中的训练服务重连后上报状态，无法恢复则标记 failed+resumable。

| code | 含义 | 典型 hint |
|---|---|---|
| TR-001 | 数据不足/过短 | 补充到 ≥10 分钟或确认降级 |

| TR-004 | 目标音源名非法/重名 | 修改名称或确认覆盖 |
| TR-005 | 底模/HuBERT/RMVPE 缺失或损坏 | 去启动器安装模型组件 |
| TR-006 | 授权声明缺失 | 填写声音来源与用途 |
| TR-007 | 显存不足（OOM） | 自动降 batch 重试；仍失败则减小数据/采样率 |
| TR-008 | 训练 NaN/发散 | 降 lr/减 epoch/换数据；检查音频爆音 |
| TR-009 | F0 提取失败（全静音/异常） | 检查音频与 f0 方法 |
| TR-010 | 索引构建失败 | 关闭 index 或减小数据（kmeans） |
| TR-011 | 磁盘空间不足 | 清理工作区/换 AMS_HOME |
| TR-012 | 文件被占用/权限不足 | 关闭杀软扫描/检查目录权限 |
| TR-013 | 服务/GPU 不可用 | 检查驱动/服务状态 |

| TR-015 | 导出校验失败 | 查看详情（同名/维度/加载失败） |

| music_train_diagnose | 失败/效果诊断 | job_id 或 metrics+log 引用 | 原因、证据、建议操作（可一键重试参数） | 本地知识库 + 日志 | 30s |
| music_train_cleanup | 清理工作区/历史 | job_id 列表/保留策略 | 释放空间、保留列表 | 本地文件操作（审计） | 60s |
| music_train_extract_small_model | 提取指定 epoch 小模型（P1） | ckpt_path/epoch、voice_name | 产物路径/校验 | POST /jobs（op=extract） | 300s |
| music_train_merge | 融合两个音源（P1） | source_voice_ids、alpha、voice_name | 产物路径/校验 | POST /jobs（op=merge） | 300s |

要求：每个工具必须有 JSON Schema、错误码（见 7.8 映射）、超时与幂等说明；长任务只返回 job_id，不阻塞；工具执行失败返回结构化错误，不终止 Agent 轮次。

### 8.2 关键工具返回约定

- 统一返回信封（与其他分册一致）：{ ok, data, error?, warnings? }；error 使用 7.8 的错误码；warnings 用于降级/许可/质量提示。

- music_train_status 返回“人话摘要 + 结构化字段”：例如“训练中 epoch 12/20（预计 8 分钟），loss 正常；可续训”。字段：status/phase/percent/epoch/total_epoch/eta_sec/latest_metrics/warnings/resumable/next_actions[]。
- music_train_preflight 返回 blocking/warnings/suggestions 三级；blocking 非空则 Agent 不得继续开训，需向用户确认或转 data 插件处理。
- music_train_export 返回最终绝对路径、校验清单（pth/index 长度/维度/能否加载）、是否注册成功；失败给 code+hint。
- music_train_diagnose 返回 {root_cause, evidence[], suggestions[{action, params_patch?, risk}], can_resume}。

### 8.3 AI 典型操作流程（SOP 摘要）

- **全自动开训**：plan → 向用户确认命名与授权声明 → preflight（blocking 为空）→ start → 轮询 status/订阅事件 → 完成 → preview → 向用户要试听评分 → evaluate → export → 告知音源库路径与换源入口。
- **失败诊断**：status 显示 failed → diagnose → 若 OOM：建议 params_patch{batch_size 减半} 或 services 降采样率 → 用户确认 → start（新任务）；若可续：resume。
- **中断恢复**：list 查 resumable → status 确认阶段 → resume → 汇报“从 epoch N 继续”。
- 约束：【决策】Agent 不得替用户填写“已授权”声明；不得自动覆盖已有音源；不得在 blocking 未清时强行开训；导出/分享前必须人工确认。

## 9. 错误处理、降级与性能

### 9.1 失败模式与处理

| 症状 | 诊断信号 | 自动处理 | 用户可操作 | 错误码 |
|---|---|---|---|---|
| CUDA OOM | 日志 “out of memory”、显存峰值 | 降 batch 重试（最多 2 次：auto→减半→1） | 降采样率/减数据/关缓存 | TR-007 |
| 训练 NaN/Inf | loss 出现 nan/inf | 立即停止，保留现场 | 检查爆音/降 lr/减 epoch | TR-008 |
| 数据不足 | 预检时长/切片数 | 阻断（<5 分钟）或警告（5–10 分钟） | 补数据/确认降级 | TR-001 |
| 多说话人 | 数据集校验/embedding 聚类（若可用） | 阻断 | 去数据集拆分 | TR-002 |
| 音频坏文件 | ffmpeg 解码失败统计 | 跳过坏文件，>10% 阻断 | 修复/剔除 | TR-003 |
| F0 全静音/异常 | F0 统计（有声帧比例） | 失败并建议换 f0 方法/检查静音 | 检查音频 | TR-009 |
| 索引失败 | faiss 异常/内存 | 允许“无 index 导出”或 kmeans 压缩后重试 | 关闭 index/减少数据 | TR-010 |
| 路径/编码问题 | 日志 Unicode/FileNotFound | 统一工作区为短英文路径；拒绝非法名 | 改名/迁移 AMS_HOME | TR-004/TR-012 |
| 底模缺失/损坏 | 启动检查 sha256 | 阻断并给启动器入口 | 重新下载底模 | TR-005 |
| 进程崩溃/被杀 | 退出码非 0、无收尾日志 | 标记 failed+resumable，保留工作区 | 续训/诊断 | TR-014 |
| 磁盘不足 | 启动前/训练中检查 | 训练前阻断；训练中安全停止 | 清理/换盘 | TR-011 |
| 服务/GPU 不可用 | 健康检查/驱动错误 | 排队/重试；提示启动器诊断 | 检查驱动/服务 | TR-013 |
| 导出校验失败 | 加载失败/维度不符/同名 | 拒绝注册，保留 staging 供诊断 | 修正配置后重导 | TR-015 |

### 9.2 降级策略

| 场景 | 降级 | 代价/提示 |
|---|---|---|
| 显存不足 | batch auto→减半→1；仍不足则建议 40k/32k 或减数据 | 训练更慢/质量略降 |
| 无 FCPE/2.3 异常 | 回退 rmvpe | 稍慢但稳定 |
| 无 index | index_rate 失效（推理侧自动 0 或提示） | “无检索增强”，像不像靠模型本身 |
| 数据集插件不可用 | 本地目录+最小预检 | 清洗能力缺失，质量风险上升 |
| 无网络 | 只用已安装底模；不自动下载 | 缺底模无法训练 |
| CPU 环境 | 仅允许“冒烟/1 分钟数据”任务并强提示 | 不承诺可用时长 |
| 2.3 升级回归失败 | 回滚上一 vendored 版本，任务 pin engine 版本 | 功能回退，数据兼容 |
| 实时变声需要 GPU | 训练在 epoch 边界暂停（可续） | 训练总时长变长 |

### 9.3 性能与 SLA（目标值）

| 指标 | 目标 | 说明 |
|---|---|---|
| 页面首开（Trainer） | < 1.5 s | 前端懒加载曲线图 |
| 开训到 running | < 3 s（不含排队） | 预检+启动子进程 |
| 进度事件延迟 | < 2 s | SSE 心跳 |
| 日志可见延迟 | < 1 s | 批量聚合 |
| 训练成功率 | ≥ 98%（合规数据） | 失败必须可诊断/可续 |
| 导出耗时 | < 30 s（pth+index） | 含校验与注册 |
| 续训恢复可见 | < 10 s | 网关重启后 |
| 服务自身内存 | < 2 GB（不含训练子进程） | 评分/日志流控 |
| 训练 GPU 利用率 | ≥ 85%（官方 2.3 单卡无 DDP 优化目标） | 实测为准 |

### 9.4 性能优化要点
- 特征/F0 多进程按 n_cpu，避免与训练争 CPU；2.3 允许中断续跑 → 不重复计算。
- 训练 fp16（默认）、可选缓存到显存、只保存最新 checkpoint（磁盘 IO 是长训瓶颈之一）。
- index 分批 add（RVC 旧版即 8192/批），大数据先 kmeans 压缩（>20 万帧）。
- 日志/指标降采样（每 N step 落库一次），SSE 批量推送。
- 导出 pth/index 用同盘 rename 保证原子，避免跨盘复制。

### 10.2 训练数据授权（强制）
- 向导必填：声音来源类型（本人/已授权/未确认）、是否允许商用、备注、声明人；写入 job.params.license 与 voice.json。
- “未确认”允许本地训练与试听，但**导出/分享**时提示为“来源未声明，禁止对外分享”；AI 工具不得自动代填“已授权”。
- 数据集快照中的 license 字段作为上游证据；trainer 记录快照 hash，防止事后替换数据。
- 【风险】用户用名人/角色声音训练并公开传播 → 产品不能完全免责；通过声明、AI 标识、导出提示降低风险。

### 10.3 AI 生成标识
- 导出音源与试听/换源产物在元数据中标记“AI 生成/合成声音”（voice.json、导出文件命名可选、换源链路沿用）。
- 依据：《互联网信息服务深度合成管理规定》（2023-01-10 施行）、《生成式人工智能服务管理暂行办法》（2023-08-15 施行）、《人工智能生成合成内容标识办法》（2025-09-01 施行）——法规名与生效日以官方文本最终核对（沿用 03 调研 §11.2 的谨慎表述）。
- 本插件只保证“能力与记录”，不构成法律意见。

### 10.4 隐私与本地优先
- 除“用户显式触发的模型/组件下载”外不联网；训练音频不上传、不打遥测（00 第 12 节）。
- 日志脱敏：包含用户主目录的路径打码；导出诊断报告前提示可能含路径。
- 删除任务时清理工作区与试听产物；不进入 backups（仅音源库备份）。
- 训练子进程环境剔除凭据（由内核/网关统一注入规则）。

### 14.4 关键契约（给其他分册引用）

1. 任务：train.rvc（op=train/resume/build_index/extract/merge），params 见 §7.2；产物 artifacts kind=pth/index/voice_json/config/metrics/preview/log/checkpoint。
2. 音源产物：voices/<名称>/<名称>.pth + 同名 .index（可选，无则 voice.json 记录并明示）；校验规则见 §6.2。
3. 工具返回：{ ok, data, error?, warnings? }；错误码 TR-001…TR-016；长任务只返回 job_id。
4. GPU：训练任务 resource={gpu:true, vram_estimate_mb, disk_estimate_mb, can_resume:true}；由 Gateway 串行调度，实时变声优先。
5. 数据集：只消费 dataset 快照字段（§6.4），记录 dataset_id+hash；不复制音频、不写数据集目录。
6. 音源库：导出后调用 /voices/scan；voice.json 为可选旁车；不把必需信息只放旁车（00 §6）。
7. 环境版本：job.engine 记录 rvc=2.3.260718、python=3.12、torch 变体、cuda；voice.json 同步记录，供复现与升级回归。
