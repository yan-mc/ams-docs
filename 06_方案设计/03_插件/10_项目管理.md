## 0. 一页结论

| 维度 | 结论 |
|---|---|
| 定位 | 全部作品的“文件系统骨架 + 元数据 + 步骤时间线 + 可复现快照 + 生命周期管理”；训练的模型、分离的 stem、换声的人声、混音成品都归档到工程里 |
| P0 范围 | 工程 CRUD（新建/重命名/复制/归档/回收站删除）、按 00 第 7 节生成目录、`project.json` schema v1、步骤时间线（含参数快照）、产物登记/浏览/试听、引用记录（音色/模型/工具版本）、备份与恢复、迁移/路径重定位、完整性校验、搜索/标签 |
| 真源与索引 | **文件系统是唯一真源**（`project.json` + 目录内容）；Gateway 维护 SQLite 索引只为“快”，损坏可一键重建 |
| 写入模型 | 所有写操作走 Gateway **单一写入者**（project 模块）；插件不直接写 `project.json`，任务完成由 Gateway 回调登记 step |
| 可复现 | 每 step 记录 inputs/params/params_hash/引擎版本/起止时间；重跑生成新 step（append-only），可对比参数 diff |
| 引用而非复制 | 音源（RVC pth+index）、基础模型、工具只存**引用**（id+version+hash），不复制大文件；工程可整体移动 |
| 互操作 | 目录结构严格按 00 第 7 节；可选导出 `.amsproj` 包（zip，可脱敏、默认不含权重）与迁移向导 |

【决策】不新增工程顶层目录：`source/ stems/ vocals/ tts/ singing/ mix/ exports/ logs/` 保持 00 第 7 节原样；索引放 `AMS_HOME/cache/project-index.db`，备份/回收站放 `AMS_HOME/backups/`。
【决策】删除 = 移入 `AMS_HOME/backups/trash/<project-id>-<ts>/`（保留 30 天，可手动清空）；归档（archive）只是状态位，不移动目录。
【决策】步骤 append-only；修改历史参数只能“复制 step 重跑”或“另存快照”，不原地改。
【待定】是否新增 Job 类型 `project.backup` / `project.scan`（00 第 8 节任务类型列表未含，见 13.2）。

## 5. 技术架构与依赖

### 5.1 组件与数据流

~~~text
Client 页面（工程列表/详情/时间线）
   │ HTTP + SSE（127.0.0.1:<port> + token，00 第 3 节）
   ▼
Gateway（FastAPI）
   ├─ project 模块（唯一写入者）：CRUD/step/产物/备份/迁移
   ├─ jobs：任务完成回调 → 登记 step + artifacts
   ├─ artifact 库：产物 id ↔ 相对路径 ↔ sha256
   └─ SQLite 索引：列表/搜索（可重建）
   ▼
文件系统：AMS_HOME/projects/<project-id>/（真源，00 第 7 节）
备份/回收站：AMS_HOME/backups/projects/、AMS_HOME/backups/trash/
~~~

### 5.2 职责边界

| 组件 | 职责 | 不做什么 |
|---|---|---|
| project 模块（Gateway） | 单一写入者、schema 校验、原子写、索引、备份/迁移 | 不做音频处理、不管理音源本体 |
| 各插件（Host） | 提交任务、调 `music_project_add_step` 登记 | 不直接写 `project.json` |
| core Jobs | 任务生命周期、产物生成、完成事件 | 不解释工程语义 |
| voice-library | 音源本体与标签、元数据解析 | 不拥有工程 |
| Client 页面 | 展示与操作入口 | 不直接读写文件 |

【决策】“Job 完成 → 登记 step”由 Gateway 在任务成功回调里完成（同一请求内），保证“有产物必有 step”；插件失败重试不得产生重复 step（以 `job_id` 幂等）。

### 5.4 project.json 设计原则

- `schema_version` 显式；任何不兼容变更必须提供迁移脚本（见 6.6）。
- 只存元数据与相对路径，**不存二进制/base64**；大字段（歌词、频谱）放独立文件并引用。
- 写入原子化：同目录临时文件 → `fsync` → `rename`；保留最近 5 个自动备份 `project.json.bak.N`。
- `steps[]` 只追加不修改；修改历史用“复制 step 重跑”或“快照回滚”。
- 所有 hash 用 sha256（大文件可先分块）；时间统一 ISO 8601 带时区。
- 中文路径允许；内部 id 用 `p_<yyyymmdd>_<seq>`，与显示名解耦（改名不改 id）。

### 5.5 一致性与恢复策略

| 场景 | 策略 |
|---|---|
| 正常写 | 单写入者 + 文件锁 + 原子写 + revision 递增 |
| 并发写冲突 | 客户端带 `If-Match: revision`；冲突返回 PROJECT_E_CONFLICT |
| 崩溃/断电 | 临时文件残留忽略；启动扫描 `*.tmp` 清理；旧文件始终可用 |
| 索引不一致 | `reconcile`：按 project.json 与磁盘重建索引（幂等） |
| project.json 损坏 | 依次尝试 `.bak.N`；再失败则“只读恢复模式”+ 从 step 日志重建 |
| 文件被外部改动 | 校验 hash/mtime 变化 → 标 `dirty` 并在详情提示，不自动覆盖 |

### 5.6 路径与迁移

- 工程内路径一律**相对工程根**；`AMS_HOME` 可移动，工程目录可改名。
- 外部素材（用户选择工程外文件）存绝对路径 + `external: true` + hash；迁移时提示“外部引用可能失效”。
- 盘符变化：迁移向导支持“旧前缀 → 新前缀”映射，批量替换并先备份。
- 文件名大小写/中文/空格：保留原名，但内部查找用规范化键（NFC）避免 macOS/网盘同步差异。
- 跨机器迁移：导出 `.amsproj`（元数据 + manifest）+ 可选素材打包；导入时校验 hash，缺失给“跳过/重新定位”。

### 5.7 备份与回收站

| 项 | 规则 |
|---|---|
| 备份位置 | 默认 `AMS_HOME/backups/projects/<id>/<ts>/`；可指定外部路径 |
| 备份内容 | 必含 `project.json` + `logs/`；可选 `source/ stems/ vocals/` 等大目录 |
| 校验 | 备份完成生成 manifest；还原前校验，可“只还原元数据” |
| 删除 | 移入 `AMS_HOME/backups/trash/<id>-<ts>/`；保留 30 天；彻底删除需确认 |

## 6. 数据模型与目录

### 6.1 目录结构（严格按 00 第 7 节）

~~~text
AMS_HOME/
├─ projects/<project-id>/
│  ├─ project.json          # 唯一工程清单（见 6.2）
│  ├─ source/               # 原始素材（引用或副本，按设置）
│  ├─ stems/                # 分离结果
│  ├─ vocals/               # 换声后人声
│  ├─ tts/                  # 配音片段
│  ├─ singing/              # 填词/演唱结果
│  ├─ mix/                  # 混音工程与渲染（见 08 分册）
│  ├─ exports/              # 成品
│  └─ logs/                 # 任务日志/参数（含 audit.jsonl）
├─ cache/project-index.db   # 列表/搜索索引（可重建，不属于工程）
└─ backups/
   ├─ projects/<id>/<ts>/   # 工程备份
   └─ trash/<id>-<ts>/      # 回收站（30 天）
~~~

### 6.2 project.json 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| schema_version | string | `project/1`；迁移依据 |
| id / name | string | 稳定 id（`p_20261019_003`）/ 显示名（可改） |
| created_at / updated_at | string | ISO 8601 带时区 |
| status | string | active / archived / trashed（索引态，trash 实际已移走） |
| source | object | 原始素材：路径、类型、时长、hash、来源说明 |
| target_voice | object? | 目标音源：voice_id、name、version、hash |
| tags[] / favorite | array/bool | 标签、收藏 |
| notes | string | 用户备注 |
| steps[] | array | 步骤时间线（见 6.3，append-only） |
| artifacts[] | array | 产物清单（id/kind/path/hash/size/created_at/step_id） |
| references[] | array | 依赖引用（见 6.4） |
| settings | object | 工程级设置（默认导出格式/响度目标/采样率等） |

### 6.3 steps[] 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | `s_0007`（单调递增，append-only） |
| type | string | import/separate/convert/train/tts/singing/mix/eval/export/other |
| title | string | 人可读标题（可自动生成） |
| job_id | string? | 对应 Gateway Job（幂等键） |
| status | string | succeeded / failed / cancelled / skipped |
| started_at / finished_at | string | 时间 |
| duration_sec | number | 耗时 |
| inputs[] | array | `{kind, ref}`：引用 source/产物 id/外部文件+hash |
| params | object | 该步参数（完整快照） |
| params_hash | string | 参数规范化后的 sha256（判断等价步骤） |
| engine | object | `{service, version, models[]}`（含模型 hash） |
| artifacts[] | string[] | 产物 id 列表 |

### 6.4 references[] 字段

| 字段 | 说明 |
|---|---|
| kind | voice / model / tool / service / plugin / dataset |
| id / name | 标识与显示名 |
| version | 版本（如 `2.3.260718`、`v2Pro`） |
| hash | 文件 sha256（音源/模型必填；工具可选） |

### 6.6 版本与迁移规则

- 读：遇到更高 `schema_version` → 只读模式 + 提示升级应用；不静默降级。
- 写：迁移前自动备份 `project.json` → 运行迁移脚本 → 校验 → 替换；失败回滚备份。
- 迁移脚本随 Gateway 发布，`project/m1→m2` 幂等；每条记录在 `logs/migration.log`。
- 删除字段只在主版本升级时做（保留一版兼容读取）。
- 任何迁移不得改动素材文件；只改元数据并写审计日志。

## 7. 接口与任务

### 7.1 Gateway REST API（前缀 `/api/v1`，鉴权见 00 第 3 节）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/projects?status=&q=&tag=&sort=&page=` | 列表/搜索/筛选/排序（走索引） |
| POST | `/projects` | 新建工程（名称/模板/位置/可选导入素材） |
| GET | `/projects/{id}` | 工程详情（含 steps/artifacts/references 摘要） |
| PATCH | `/projects/{id}` | 改名/标签/备注/settings（`If-Match: revision`） |
| POST | `/projects/{id}/archive`、`/delete`、`/restore` | 归档/删除到回收站/恢复（delete 需确认） |
| POST | `/projects/{id}/steps` | 登记步骤（`job_id` 幂等；step+artifact 同事务） |
| GET | `/projects/{id}/timeline`、`/artifacts`、`/references` | 时间线/产物/引用 |
| POST | `/projects/{id}/backup`、`/restore-backup`、`/relocate`、`/validate` | 备份/还原/迁移/完整性校验 |
| POST | `/projects/import`、`/projects/{id}/export`、`/projects/index/rebuild` | 导入/导出包/重建索引 |

### 7.2 步骤登记与幂等

- 任务完成由 Gateway 回调登记 `steps[]` + `artifacts[]`；**同一 job_id 只登记一次**（重复回调返回既有 step）。
- 写接口带 `expected_revision`；冲突返回 `PROJECT_E_CONFLICT`，调用方重读后重试。
- 步骤 append-only：不改历史参数；修正走“复制 step 重跑”（新 step，parent_step_id 指向原 step）；产物登记必须经 artifact 库。

## 8. AI 工具与 Skills

### 8.1 工具清单（前缀 `music_project_*`）

| 工具 | 作用 | 关键参数 | 超时 |
|---|---|---|---|
| `music_project_list` / `_search` | 列表与搜索 | status、q、tag、limit | 5 s |

| `music_project_update` | 改名/标签/备注/settings | project_id、patch、expected_revision | 5 s |
| `music_project_archive` / `_delete` / `_restore` | 归档/删除到回收站/恢复 | project_id、confirm | 10 s |

### 8.2 契约与确认

- 破坏性工具（`_delete`、`_restore`、覆盖式备份/导入）必须 `confirm: true`，页面同步二次确认。
- 工具返回精简摘要（steps ≤20 条），完整时间线走 REST 分页；工具不直接访问文件系统。
- 工具调用与页面操作写同一审计日志（谁/何时/改了什么）。

### 8.3 Skills

- `ams-工程整理`（新增）：扫描最近工程 → 建议归档/备份/清理 → 生成清单，不自动删除。
- `ams-翻唱工作流`（01/03 引用）：每步完成要求 `music_project_add_step`，保证可追溯。

## 9. 错误处理/降级/性能

### 9.1 错误处理

| 类别 | 策略 |
|---|---|
| 参数/schema 非法 | 拒绝写入并返回字段级错误；旧文件不动 |
| 并发冲突 | `If-Match` 校验，冲突让调用方重读重试 |
| 文件缺失/外部引用失效 | 标 `missing`/`stale`，不阻断打开，提供重定位 |
| project.json 损坏 | 依次尝试 `.bak.N`；失败进入只读恢复模式 |
| 索引不一致 | 标记 → 提供 `rebuild`（幂等） |

### 9.2 降级矩阵

| 缺失/异常 | 降级行为 | 用户可见 |
|---|---|---|
| SQLite 索引损坏 | 列表走目录扫描（慢），提示重建 | “索引异常，已临时扫描” |
| 音源/模型被删 | 引用标红；步骤仍可查看参数 | “引用缺失，可重新绑定” |
| 服务离线 | 页面只读（最近列表缓存） | “服务未启动”+ 重启 |

### 9.3 性能指标

| 指标 | 目标 |
|---|---|
| 工程列表（10k 工程） | ≤ 300 ms（索引） |
| 搜索（名称/标签） | ≤ 200 ms |
| 打开详情（时间线 100 步） | ≤ 500 ms |
| 索引重建（10k 工程） | ≤ 60 s |
| 完整性校验（1 GB 工程） | ≤ 15 s（hash 复用 mtime/size） |

- 大目录扫描异步入队（可观测进度）；哈希并发限 2，避免占满磁盘。

## 10. 安全/许可/合规

| 项 | 规则 |
|---|---|
| 写入授权 | 只有 Gateway project 模块写工程；插件/CLI 通过 API |
| 路径安全 | 解析后必须在 `AMS_HOME/projects` 或用户显式目录内，禁止 `..`/符号链接逃逸 |
| 隐私 | 导出包不写用户名/绝对路径（默认脱敏） |
| 删除 | 进回收站保留 30 天；彻底删除二次确认并记审计 |
| 许可记录 | references 保存 license_note；导出报告列出音源/模型版本 |
| AI 标识 | 成品导出记录 generating_chain（哪些 step 由 AI 产生），对齐 00 第 12 节 |

- 备份可加密（P1 可选口令）；工程包默认不含音源权重与基础模型，只含引用信息。
