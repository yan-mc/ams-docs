## 0. 摘要与决策速览

**一句话定位**：把 pymss 的「现代 MSS 模型 + 分块推理 + workflow + ensemble」封装成 AMS 的**本地分离服务 + 分离队列页面 + 一组 AI 工具**：用户（或 Agent）导入音频/视频/文件夹，选择模型与目标 stem，产出多轨结果（vocals/instrumental/drums/bass/other/去混响/去和声/单乐器），可批量、可 A-B 对比、可继续送换源/混音/训练数据集清洗。

**技术基座（2026-10-19 版本）**：
- 主后端 **pymss 2.1.9**（2026-10-16，**MIT**）+ **pymss-core 0.1.11**（MIT）：统一 10 类模型架构（BS/Mel-Band Roformer、HyperACE、SCNet、HTDemucs、MDX23C、Bandit、Apollo、VR/旧 Demucs），内置 catalog **326 个模型**、自动下载（默认 ModelScope，可切 HuggingFace/hf-mirror）、分块 overlap-add、TTA、8 种 ensemble、YAML workflow、进度回调。【事实：pymss 报告】
- 运行时：独立 **Python 3.12** + **PyTorch 2.7.1（cu128 / cpu / ROCm）**（BSD-3-Clause）+ PyAV（BSD-3-Clause）+ ffmpeg（LGPL 构建）。与 RVC（torch 2.0/py3.9）、GPT-SoVITS 等后端**运行时隔离**。【决策 D2】
- 备选/补充：**audio-separator 0.47.0**（MIT，嵌入式轻依赖）、**MSST**（MIT，SOTA 模型来源/训练）、**UVR 5.6**（MIT，需署名；只作模型与交互参考，不嵌入）。【事实：调研 §7】
- 不含/不使用：pymss-studio（**AGPL-3.0**，不引入代码）、任何需 GPL 的音频组件（pedalboard/matchering 等）。

| 决策 ID | 决策 | 理由/依据 |
|---|---|---|
| D1 | 分离能力做成独立服务 **`ams-svc-pymss`**（Python 子进程），Gateway 拉起并监管；页面/Agent 只走 Gateway | 00 §3/§8；避免 Node 里跑推理 |
| D2 | 后端运行时独立（Python 3.12 + torch 2.7.1 cu128），与 RVC/GPT-SoVITS 环境隔离 | 可行性 §2.2 原则 4；pymss 要求 py≥3.10/torch≥2.7.1 |
| D3 | 任务以 **Job** 形式进队列（`separate.pymss`），GPU 锁串行；**取消=终止服务进程树并自动重启**（P1 优化为可取消子进程） | 00 §8；pymss 无中断 API |
| D4 | 模型缓存：默认同一服务进程**只常驻 1 个模型**；显存/内存允许时 P1 支持 LRU 常驻 2 个 | 16GB 显存约束；pymss 模型单例 |
| D5 | 模型下载复用 **pymss 自带下载器**（ModelScope/HF/hf-mirror、sha256/大小校验、断点、代理），启动器只做镜像配置与磁盘管理 | pymss 报告 §2.1；避免重复实现 |
| D6 | 一期内置「模型推荐清单」（人声/4 轨/6 轨/去混响/去和声/单乐器/去噪/清理），**不内置权重**，首次使用时按需下载 | 00 §1 音源/权重不分发；许可策略 §10 |
| D7 | 多轨/专用能力通过「模型 + stem 选择」实现，不做固定 4 轨假设（stems 来自模型 YAML `training.instruments`） | pymss 报告 §3.8 |
| D8 | 支持 **A-B 对比**（同曲两模型/两参数，盲听随机顺序）与**无参考质检**（残留/泄漏/削波/相位）；SDR 需参考 stem，交给评测器插件 | §3.5；避免伪造指标 |
| D9 | 支持 **批量 + workflow**（YAML 串联「分离→去混响→去和声」，也支持 pymss 原生 workflow 导入） | pymss 报告 §2.1.8 |
| D10 | 输出统一落 `AMS_HOME\projects\<id>\stems\`（工程内）或用户指定目录（独立任务）；格式 wav/flac/mp3/m4a，默认 wav FLOAT | 00 §7；pymss audio_params |
| D11 | 不提供「云端分离」；默认离线，联网仅用于模型下载/更新 | 00 §12 本地优先 |
| D12 | UI 只做主页面 + 工具卡片；不做 DAW 级波形编辑器（编辑/混音在混音插件，DAW 用户走 pymss-ara 思路的 VST 插件 P2） | 边界控制 |

**Top 风险**：① 16GB 显存下大模型（4stems XL 6.1GB、Mel-Band big）OOM 与长音频耗时（§9、§13）；② 326 个模型质量/许可参差，需要推荐清单与许可标注（§10）；③ 取消/崩溃后的服务恢复体验（§9.2）。

## 2. 用户与场景

### 2.1 用户角色

| 角色 | 典型诉求 | 关键差异 |
|---|---|---|
| 翻唱/换源用户 | 从原曲提取干净人声（最好去混响/去和声），再交给 RVC | 关心人声质量与残留 |
| 混音/重编曲用户 | 4/6 轨 stem、单乐器提取（mega-53） | 关心多轨完整性与相位 |
| 播客/视频作者 | 去背景音乐、去混响、降噪、人声增强 | 关心对话清晰度与批量 |
| AI 协作用户 | 「帮我把这 10 首歌分离出人声，去掉混响，导出 48k wav」 | 关心工具化、可批处理、可解释 |
| 开发者/排障 | 看模型、参数、显存、日志 | 诊断面板与复现参数 |

### 2.2 场景表

| 场景 | 输入 | 输出 | 关键功能 | 验收点 |
|---|---|---|---|---|
| S1 翻唱前处理 | 1 首歌 | vocals + instrumental（可选 dereverb） | 人声模型、去混响、去和声、48k 导出 | 人声残留 < 可感知；导出可被换源插件直接消费 |
| S2 4 轨重混 | 1 首歌 | drums/bass/other/vocals | 4 轨模型（SCNet/HTDemucs/MBR） | 4 文件齐全、相位一致、时长一致 |
| S3 6 轨/单乐器 | 1 首歌 | 6 轨或指定乐器（吉他/钢琴/弦乐…） | mega-53、MDX23C-DrumSep | 目标乐器可听、其它轨可接受 |
| S4 去混响/去回声 | 人声/对白 | dry / No Reverb / No Echo | dereverb/deecho 模型 | 混响尾巴明显减少、无明显失真 |
| S5 批量专辑 | 文件夹 50 首 | 每首一套 stems | 批量队列、失败重试、命名规则 | 无泄漏、失败可定位 |
| S6 数据集清洗 | 训练素材目录 | 干净干声片段 | 去伴奏+去混响+降噪，输出给数据集插件 | 指标达标（SNR/DNSMOS） |
| S7 AI 批处理 | 自然语言 | 同上 | Agent 解析→建 Job→汇报 | 工具全部可审计/可取消 |
| S8 A-B 选型 | 同一首歌 | 两模型结果对比 | 盲听、波形/频谱差异、耗时/显存对比 | 用户可在 3 分钟内选定模型 |

### 2.3 AI 操作场景（Agent 能做/不能做）

| 能做 | 不能做（必须人确认） |
|---|---|
| 检查音频（时长/采样率/声道/响度/削波）并推荐模型与参数 | 删除用户原始音频/覆盖已有产物 |
| 创建/查询/取消分离 Job，批量建任务 | 下载超过阈值（默认 5GB）的模型（需确认） |
| 跑 A-B 对比、汇总耗时/显存/无参考指标 | 修改工程 `project.json` 的既有步骤（只追加） |
| 失败诊断（OOM→建议降参/换模型） | 上传音频到任何云端服务 |
| 把结果送换源/混音/数据集 | 更改全局模型缓存目录/删除缓存（需确认） |

【决策】Agent 创建的每个分离任务必须记录：`agent_session_id`、自然语言意图摘要、使用的模型版本与参数快照，可在任务详情查看与回滚。

### 3.3 参数与显存/速度（P0）

| 参数 | 默认 | 范围 | 影响 | 备注 |
|---|---|---|---|---|
| batch_size | 模型 YAML（通常 1–4） | 1–16 | 吞吐↑、显存↑ | 16GB 下大模型固定 1–2 |
| chunk_size | 模型 YAML（如 352800/480000） | 8k–1M 采样 | 显存↑、边界连续性 | 显存不足时 0.75× 递减 |
| overlap_size | 模型 YAML 或 chunk 的 5% | 0–chunk/2 | 质量↑、速度↓ | 默认沿用 YAML；手工可设 5% 快/50% 稳 |
| use_tta | false | bool | 质量↑、耗时 3× | 只对最终成品开启 |
| standardize | 模型 YAML inference.normalize | bool | 输入标准化 | 一般保持默认 |
| normalize | false | bool | 输出峰值 -0.01 dBFS | 多轨联动归一化，保持相对比例 |
| 输出格式 | wav FLOAT | wav/flac/mp3/m4a | 体积/兼容 | 训练/换源建议 wav 48k |
| attention 后端 | auto | auto/cudnn/flash/efficient/math | 速度/兼容 | cuDNN flash 在 40 系可用 |

**显存预估模型**【推断】：显存 ≈ 权重（fp32 约 = 参数体积）+ 激活（≈ chunk_size × batch × 常数）+ 框架开销（~0.8–1.5 GB）。首屏用该公式给「预计显存」，任务完成后回填实测值校准。

### 3.4 批量与 workflow（P0/P1）

- **批量**：支持「文件列表」与「目录递归」；命名规则模板（`{name}_{stem}`、`{index:03d}_{name}`）；失败重试（默认 2 次）；跳过已存在产物（可关）；任务内串行（GPU 锁），多文件进度聚合。
- **workflow（P1）**：内置模板
  1. `人声清洗链`：BSR 人声 → dereverb → 输出 dry；
  2. `翻唱素材链`：BSR 人声+伴奏 → karaoke（拆分主唱/和声）→ 输出 lead/back/inst；
  3. `4 轨重混链`：SCNet/HTDemucs 4 轨 → 每轨可选去混响；
- 兼容 pymss 原生 workflow YAML：用户可导入 `pymss workflow init` 生成的 YAML，在 AMS 内编辑步骤/模型/输入引用（`input` / `<step>.<stem>`）并执行。【事实：pymss 报告 §2.1.8】
- 【决策】workflow 执行仍落为 `separate.workflow` Job（新增任务类型，见 §7），内部逐步调用 pymss 推理；每步产物作为 artifact 记录。

### 3.5 A-B 对比与质量指标（P0/P1）

| 能力 | 说明 | 指标 |
|---|---|---|
| 盲听 A/B | 随机顺序、同增益、可无限次切换，最后揭晓 | 主观偏好记录 |
| 波形/频谱差异 | 差值波形、频谱图、残差能量时间线 | 差异时间轴 |
| 无参考指标（P1） | 削波率、LUFS、峰值、静音比、DC offset、相位相关（立体声）、频谱缺口 | 数值 + 阈值告警 |
| 参考指标（P2，联动评测器） | 有参考 stem 时算 SDR/SI-SDR；无参考不伪造 | SDR/SI-SDR |
| 性能对比 | 每模型耗时、RTF、显存峰值、加载时间 | 表格 |

**无参考「残留/泄漏」检测思路**【推断】：① 用第二个模型对 outputs 交叉分离（伴奏里再跑人声模型，检测残留能量）；② 对 vocals 估计「伴奏泄漏」用谱平坦度/周期性检测；③ 只作提示，不作绝对结论。P2 再考虑训练专门的判别器。

### 3.6 导出（P0）

- 目录：工程内 → `AMS_HOME\projects\<id>\stems\<stem>\<原名>_<stem>.<ext>`；独立任务 → 用户指定目录（默认 `AMS_HOME\exports\separate\<timestamp>\`）。
- 格式参数：wav（FLOAT/PCM_24/PCM_16）、flac（PCM_24/PCM_16）、mp3（128/192/256/320k）、m4a（256/512k，AAC）。
- 命名模板：`{name}`、`{stem}`、`{model}`、`{index}`、`{date}`；非法字符自动替换。
- 元数据：可选写 ID3/BWF? 【待定】；至少在 `project.json`/artifact 记录模型、参数、版本、时间。
- 【决策】「送换源（插件 04）」交接契约：传递 `{stems 路径列表, 采样率, 工程 ID, 模型/参数摘要, 是否有去混响}`；换源插件据此预填干声/伴奏与工程（对齐 `04_歌曲换源.md` 的「从 stems 一键创建」）。

### 5.2 pymss 调用方式（【决策 D1/D3】细节）

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 直接把 pymss 当库，在 `ams-svc-pymss` 内单进程跑 | 模型可常驻、进度回调直接、无协议开销 | 取消需杀进程、崩溃影响服务 | **采用**（默认）；崩溃由 Gateway 自动重启并恢复队列 |
| B. 用 `pymss serve`（FastAPI）作为后端 | 现成 HTTP/OpenAI 风格 | 单模型、功能面向通用 API、不好嵌入 GPU 锁/任务模型 | 不采用（仅作参考/调试） |
| C. 每次任务起独立子进程调用 pymss CLI | 取消简单、隔离好 | 每任务重载模型（2–10 s）、无法复用缓存 | P1 作为「可取消/隔离模式」可选 |

**实现要点**（不写代码，只列契约）：
1. 服务内部维护「当前模型」状态：`{model_name, model_type, device, vram_mb, loaded_at}`；加载用 `MSSeparator.from_model_name(...)`，卸载用 `close()`。
2. 分离调用：`separator.separate(np_audio, stems=[...])` 或 `process_folder()`（批量时由服务逐文件循环，便于进度与取消检查）。
3. 进度：pymss 的 `progress_callback(done_seconds, total_seconds, message)` → 转成 Job 百分比（按文件时长加权）；保存阶段单独报进度。
4. 取消：Gateway 发 SIGTERM/Job 取消 → 服务收到后终止当前推理（杀掉整个服务进程树），Gateway 重启服务并把 Job 标记 `cancelled`；已写出的文件保留并清理 `.part`。
5. 模型参数覆盖：服务把 Job 的 `inference_params` 合并到模型默认值（pymss 支持 `inference_params` 覆盖）。
6. 采样率：pymss 内部自动重采样到模型采样率（通常 44.1k）；**输出保留模型采样率**，导出时按用户目标格式/采样率（可重采样 44.1k→48k，用 ffmpeg 或 PyAV）。【事实：pymss 报告 §3.2】
7. 音频输入解码：优先用 pymss 的 PyAV 解码；视频文件由 ffmpeg 先抽音轨到临时 wav（`-vn -ac 2`）再交给 pymss。
8. 批量并发：文件级串行（GPU 锁），IO 与保存可流水线（pymss `process_folder` 已有加载/保存线程池，服务层只控制并发度 1）。

### 7.5 SSE 事件与错误码

| 事件/字段 | 说明 |
|---|---|
| `progress` | `progress 0–100`、`stage`（queued/loading_model/loading_audio/demix/saving/postprocess）、`file_index/file_count`、`done_sec/total_sec`、`eta_sec` |

| `status` | `queued/running/stopping/succeeded/failed/cancelled` + 统计（rtf/vram） |

| 错误码 | 场景 | 处理 |
|---|---|---|
| `SEP_MODEL_NOT_FOUND` | 模型不存在/未下载 | 提示下载或选择其它模型 |
| `SEP_MODEL_DOWNLOAD_FAILED` | 下载/校验失败 | 切镜像/代理/手动导入 |

## 9. 错误处理 / 降级 / 性能

### 9.1 错误处理原则

1. **可恢复优先**：能自动降级/重试的不弹错；重试有上限（2 次），每次记录原因。
2. **失败不阻塞批量**：单文件失败 → 记入汇总报告，继续下一个；用户可一键重试失败项。
3. **错误可解释**：错误码 + 人话建议 + 「一键诊断」；日志脱敏（用户目录/密钥）。
4. **产物完整**：保存用临时文件 + 原子改名；取消/崩溃不产生半截文件（pymss 保存失败清理临时）。
5. **可复现**：任务详情展示完整参数与「等价命令」（pymss CLI 形式），便于上报。

### 9.2 OOM 自动降级序列（【决策】）

| 步骤 | 动作 | 预计成功率（S8 校准） |
|---|---|---|
| L0 | 原参数 | — |
| L1 | `batch_size=1` | 高 |
| L2 | `chunk_size × 0.75`（不低于 32k） | 高 |
| L3 | `overlap_size × 0.5` + 关闭 TTA | 中 |
| L4 | 换轻量模型（映射：BSR→SCNet/HTDemucs；Mel-Band big→BSR；4stems XL→SCNet 4 轨） | 中 |
| L5 | CPU 推理（最慢，明确警告；仅当用户允许） | 高（能跑但极慢） |
| L6 | 失败并给建议（升级硬件/改分段/选更小模型） | — |

- 每次降级都要向 SSE 推 `warning`（原因/新参数），任务详情记录 `degrade_history[]`。
- 降级会改变质量（尤其 overlap/TTA），因此**最终产物旁车必须记录实际参数**。
- 【待定】是否默认允许 L5 CPU：建议默认禁止（避免用户误以为卡死），由设置项开启。

### 9.3 长音频与超长任务

| 时长 | 策略 |
|---|---|
| ≤ 10 分钟 | 直接单任务；进度按秒报 |
| 10 分钟–1 小时 | 单任务；提示预计耗时/磁盘；可选低内存参数 |
| 1–3 小时 | 单任务但强制 `batch_size=1`；提示风险；支持后台继续（关页面不影响 Job） |
| > 3 小时 | 建议「分段任务」：按 10 分钟切段（段间 5 s 重叠）→ 逐段分离 → 拼接（重叠区交叉淡化）；实现 P2【待定】 |
| 超长对白/播客 | 可只导出 vocals（减少磁盘）；或先 VAD 切片（复用数据集插件能力） |

- 分块本身由 pymss 内部完成（chunk_size/overlap_size），进度回调以 `done_seconds/total_seconds` 换算百分比。【事实：pymss 报告 §3.4】
- 磁盘预估：输出总大小 ≈ 输入时长 × 采样率 × 声道 × 位深 × stem 数；启动前检查剩余空间 ≥ 1.5× 预估。

### 9.4 性能目标（4080 Laptop 16GB，【推断】待 S8 校准）

| 指标 | 目标 | 备注 |
|---|---|---|
| 模型加载（本地缓存） | ≤ 8 s（大模型 ≤ 15 s） | 含权重读取与 eval |
| 分离 RTF（人声 BSR HyperACE） | ≥ 20×（1 小时音频 ≤ 180 s） | pymss README 5090 231×，按 1/5–1/3 折算保守值 |
| 分离 RTF（SCNet 4 轨） | ≥ 40× | 轻量模型 |
| 显存峰值 | ≤ 14 GB（大模型 ≤ 15 GB，允许降级） | 留 1–2 GB 给系统 |
| 进度 SSE 延迟 | ≤ 1 s | Gateway 直推 |
| 页面波形加载 | 4 分钟音频 ≤ 2 s（峰值预计算） | 与编辑器共用波形服务 |
| 服务重启恢复 | ≤ 15 s | 取消/崩溃后 |
| 批量 50 文件稳定性 | 无内存泄漏（RSS 波动 < 10%） | 2 小时连续跑 |

### 10.2 模型权重许可策略（【决策 D6】细化）

- 【事实】pymss catalog 326 个模型来自 HuggingFace/ModelScope 的 `baicai1145/pymss` 仓库（HF cardData 标注 apache-2.0），但**该声明不等于每个权重都可商用**；社区 Roformer/MDX 权重来源与条款各异。【风险】
- 策略：
  1. 应用**不内置任何权重**，运行时按需从官方/镜像下载，用户确认；
  2. 模型卡片展示 `license_tag`（已知：MIT/Apache/CC-BY/CC-BY-NC/自定义/未知）+ 来源链接；
  3. 首次使用「许可未知」模型时弹提示：「仅限本地个人使用，商用请自行核实」；
  4. 导出/发布功能不自动携带模型信息，但 `artifact` 旁车记录模型名（可追溯）；
  5. 建立内部模型许可维护表（P1），优先推荐许可明确的模型。
- 【待定】是否引入「仅显示许可明确模型」的严格模式（默认关闭）。

### 10.3 安全

| 项 | 措施 |
|---|---|
| 网络 | 服务与 Gateway 只绑 127.0.0.1；token 鉴权；不监听公网 |
| 路径 | 只允许读用户选中的输入路径（文件对话框授权）与 AMS_HOME；禁止 `..` 路径穿越 |
| 模型文件 | 只接受 catalog/用户显式导入的权重；校验大小/sha256；拒绝可执行文件扩展名 |
| 进程 | 服务由 Gateway 拉起；禁止插件自行 spawn Python；取消/重启有审计记录 |
| 日志 | 脱敏用户路径/代理凭据/API Key（不记录） |
| 隐私 | 音频默认不外传；联网只用于模型下载/更新；无遥测（00 §12） |
| AI 生成标识 | 导出时可选写入「AI 分离/AI 生成」元数据（ID3v2 TXXX / 文件名后缀），默认开启提示 |

### 10.4 合规

- 分离他人版权音乐需用户自行取得授权；应用只处理用户本地文件、不提供下载源。
- 声音/人格权：若用于换声/合成，后续插件需记录声音授权（见插件 01/06 的 `VOICE_SOURCE.txt` 机制）。
- 【事实】中国监管：《互联网信息服务深度合成管理规定》（2023-01-10 施行）、《生成式人工智能服务管理暂行办法》（2023-08-15 施行）、《人工智能生成合成内容标识办法》（2025-09-01 施行）——产品需提供 AI 生成标识与来源记录能力（00 §12）。
- 不内置/分发任何音源、模型权重、第三方 GUI 代码。

### 11.3 验收清单（P0 完成时逐项打勾）

1. 首次分离全流程 ≤ 3 分钟、0 命令行；

5. 取消/崩溃后服务自动恢复 ≤ 15 s，任务状态正确；
6. 所有产物可追溯到模型版本+参数快照；
7. `music_separate_*` 14 个工具全部可用、Schema 校验通过；
8. 许可矩阵/模型许可标注 UI 上线；无 AGPL 代码引入；
9. 与换源/混音/数据集/评测器联调通过；
10. 诊断包可一键导出且不含敏感信息。

### 14.2 关键契约（给其他分册引用）

1. **任务**：`separate.pymss` 的 params 见 §7.2；产物统一 `artifacts[]`（kind=stem/zip/report），路径在 `AMS_HOME\projects\<id>\stems\` 或 `exports/separate/`。
2. **模型**：模型名用 pymss catalog 名称；版本用 `catalog-YYYY-MM` 快照 + 权重 sha256（下载时记录）。
3. **指标**：无参考指标字段固定（`peak_dbfs`、`lufs`、`clipping_ratio`、`silence_ratio`、`phase_corr`、`residual_score`），供评测器/工程统计复用。
4. **GPU**：任务声明 `resource: {gpu: true, vram_estimate_mb}`；由 Gateway 串行调度（00 §8）。
5. **Agent**：所有工具返回 `{ok, data, error?, warnings?}`；`warnings` 用于降级/许可提示。
