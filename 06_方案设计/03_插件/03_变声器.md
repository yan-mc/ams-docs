## 0. 摘要与决策速览

**一句话定位**：把「RVC 官方实时变声」做成 AMS 的一个**独立本地音频服务 + 一块控制台页面**：音频设备、路由、延迟、热切换全部由服务处理；页面/Agent 只通过 Gateway 控制；DAW 场景可选 RVC 官方 VST2/VST3。

**技术基座（调研结论）**：
- RVC 官方 **2.3.260718**（2026-08-03 发布，MIT，约 38.8k★）：实时 GUI 支持 **CUDA Graph**（官方在 RTX 4090D 实测算法延迟最高 4.7× 加速、GPU 利用率 20–30%），提供官方 **VST2/VST3（Win64）** 与实时配置项（block_time/crossfade/extra context/FCPE 等）。【事实】
- 备选引擎：**VCClient v2.1.4-alpha**（MIT，cuda/dml 版支持 RVC+Beatrice；v2.2.2-beta 的 std 版仅 Beatrice）；**MeanVC2**（Apache-2.0，流式零样本 VC）作 P2；**Seed-VC / so-vits-svc 已归档，明确排除**。【事实】
- 实时音频必须放在**外部本地服务**（可行性 §5.4：浏览器/Electron 渲染进程无原生音频设备通道；DSH 只做控制面板）。【决策 D1】

| 决策 ID | 决策 | 理由/依据 |
|---|---|---|
| D1 | 实时音频 I/O + RVC 推理放在独立服务 `ams-svc-vc`（Python，单进程音频线程 + 推理线程），页面仅控制 | 可行性 §5.4；00 第 3 节 进程模型 |
| D2 | 主引擎 = RVC 官方 2.3.260718 实时推理（CUDA Graph 开），引擎以「适配器」接口封装，预留 vcclient/meanvc2 | 调研 §4；后续可换引擎不动页面/API |
| D3 | 会话用 `vc.session` 资源登记（非 Job 队列），但**必须登记 GPU 租约**且实时优先/独占；会话结束释放 | 00 第 8 节 任务类型与 GPU 锁 |
| D4 | 默认音频后端 **WASAPI**（共享→独占可切）；**ASIO P1**；虚拟声卡不内置安装包，先做**检测 + 官方下载引导** | 00 第 16 节（待决策 6） 待决策；VB-Cable 再分发条款【风险】 |
| D5 | 模型热切换：不中断音频线程，淡出→加载→淡入；失败自动回滚旧模型 | 实时体验要求 |
| D6 | 效果链/降噪只用 **MIT/BSD** 组件自研最小 DSP；GPL 的 pedalboard 不入进程（如需由用户自装独立进程） | 许可隔离 |
| D7 | 全局快捷键 P1 且需用户显式开启；页面内快捷键 P0 | Windows 全局热键需钩子，合规/安全风险 |
| D8 | 录音落盘默认 `AMS_HOME\recordings\vc\<时间戳>\`；关联工程时写工程 vocals 目录 | 00 第 7 节 |
| D9 | VST 路线作为「DAW 用户可选」：启动器安装官方插件 + 内置图文教程；AMS 不代管 VST 宿主 | 官方插件分发许可【待定】 |
| D10 | 端到端延迟 P0 目标 ≤ 300 ms p95（4080 Laptop / WASAPI 共享）；P1 ≤ 200 ms；stretch ≤ 150 ms | 见 §9.3，待 S9 Spike 实测校准 |

**Top 风险**：① 虚拟声卡/驱动/独占占用导致「没声音」类支持成本（§9、§13）；② VB-Cable/VST3 SDK 再分发许可（§10）；③ 与训练/分离任务争 GPU（§7.5）。

### 3.2 设备与路由（P0 细节）

- 枚举字段：设备 ID（WASAPI endpoint GUID）、名称、方向、驱动类型（WASAPI/ASIO/WDM-KS/DirectSound）、默认设备标记、采样率列表、通道数、是否虚拟声卡（按名称/驱动/端口启发式识别）。
- 虚拟声卡识别启发式：名称包含 CABLE/Voicemeeter/VBCABLE/虚拟/虚拟音频 等；显示「检测到虚拟声卡：VB-Cable Input/Output」。
- 路由方案模板：
  - 方案 A（直播）：麦克风 → RVC → VB-Cable Input；OBS 麦克风选 CABLE Output。
  - 方案 B（监听）：麦克风 → RVC → 耳机（同时可开录音）。
  - 方案 C（DAW）：DAW 内 VST 插件（绕过本服务）。
- 设备匹配约束：输入/输出采样率必须一致（或由服务重采样，P1）；通道：单声道输入默认，立体声输出可复制；设备切换需重建流（状态机到 reconfiguring）。

### 3.3 变声参数（P0 细节，与 RVC 官方实时 GUI 对齐）

| 参数 | 范围/默认 | 作用 | 备注 |
|---|---|---|---|
| 音高 pitch | -24…+24 半音，默认 0 | 变调（男↔女常用 ±12） | 与「自动建议音高」联动（§8.2） |
| f0 方法 | fcpe（默认）/rmvpe/harvest/pm/dio | 音高提取 | RVC 2.3 新增 FCPE；GPU 上 fcpe 快 |
| index_rate | 0–1，默认 0.75 | 检索增强强度 | 无 index 时置 0 |
| protect | 0–0.5，默认 0.33 | 保护清辅音/呼吸 | 过高会「电子味」 |
| rms_mix_rate | 0–1，默认 0.25 | 响度包络混合 | 输入底噪大时调低 |
| filter_radius | 0–7，默认 3 | 中值滤波 | 降破裂音 |
| block_time | 0.05–0.5 s（默认 0.15） | 实时块长 | 越小延迟越低、越易欠载 |
| crossfade_length | 0.02–0.2 s（默认 0.08） | 块间交叉淡化 | 与 block 联动 |
| extra context (left/right) | 0–0.5 s（默认右 0.05） | 上下文提升稳定 | 越大延迟越高 |
| 输入/输出降噪 | 开/关 | RVC 内置/RNNoise | 2.3 修复了降噪+CUDA Graph 的 bug |
| 采样率 | 40k/48k（跟模型） | 输出采样率 | 与设备采样率不同时服务重采样 |

### 3.4 会话控制与热切换（P0 细节）

- 状态机：`idle → preparing（设备+模型）→ warmup（首块）→ running → reconfiguring（换设备/换模型/改缓冲）→ stopping → idle`，异常分支 `failed`。
- **热切换模型**（D5）：`running →（淡出 50 ms）→ 加载新 pth/index（后台线程）→ 预热 1 块 → 交叉淡化 100 ms 切入`；失败自动回退旧模型并把错误码推给页面；切换期间事件 `model_switching`。
- **热改参数**：音高/index_rate/protect/rms/filter 下个 block 生效；block/crossfade/extra context 需内部重建缓冲（短暂 `reconfiguring`，目标 ≤ 500 ms）。
- **设备热切换**：重建流；若输出设备切换失败，保留输入并把输出切到默认设备（可配置）。
- **bypass**：输入直通输出（不经模型），用于对比/排障；bypass 时仍保留电平与录音。
- **静音/增益**：输出增益 -40…+12 dB，限幅保护（-1 dBFS）。

### 3.5 监听/录音/快捷键/预设

- 监听：默认关（虚拟声卡路由下容易回授）；耳机方案建议开；检测「输入设备 == 输出设备」时强提示。
- 录音：文件格式 wav（PCM 24-bit，采样率跟模型或设备，默认 48k）、双轨（干/湿）可选；写入时用临时文件 + 完成后原子改名，崩溃不产生半截文件。
- 快捷键（P0 页面内）：空格=bypass，M=静音，1–9=加载预设，↑/↓=音高 ±1 半音。
- 全局快捷键（P1）：注册表式快捷键（如 Ctrl+Alt+1…），冲突检测 + 用户确认；不默认开启。
- 预设内容：引擎+音源（voice_id+hash）+所有参数字段+设备偏好（可选，不强制绑定设备）+效果链；导出为 `.json`（带 schema_version）。

| 效果 | 实现（MIT/BSD） | 参数 | 备注 |
|---|---|---|---|
| 输入降噪 | RNNoise（BSD-3）或 DeepFilterNet（MIT，较重） | 强度 | P1 先 RNNoise |
| EQ | 双二阶（RBJ）3–6 段 | 频率/增益/Q | 自研最小 DSP |
| 压缩器 | 前馈压缩 | threshold/ratio/attack/release | 防爆音 |
| 限幅器 | peak limiter | ceiling | 默认开 |
| 混响发送 | Schroeder/FDN 简易 | size/mix | 仅监听，不写干声 |
| 变声后音色微调 | formant/共振峰（可选） | shift | 【待定】RVC 无 formant，需要重采样近似；先放入 P2 |

【决策】效果链默认全部旁路，只有限幅常开（保护输出）；效果链的开关与参数进预设。

### 3.7 诊断与自检（P0）

- 自检项：设备打开/关闭、采样率支持、缓冲可用性、输入是否有信号、输出是否有声（可选用环回）、GPU 可用性/显存、模型加载耗时、端到端延迟估算、xrun 统计。
- 「一键自检」输出结构化报告（JSON）+ 人类可读建议；Agent 用 `music_vc_selftest` 读取。
- 诊断包：`AMS_HOME\logs\vc\diagnose-<ts>.zip`（版本、设备树、参数快照、最近 500 行日志、指标摘要），不含音频内容（除非用户显式勾选）。

## 5. 技术架构与依赖

### 5.1 进程与数据流（与 00 第 3 节 一致）

    Client 页面 (React slot, vc-console)
       │ HTTP/SSE（Gateway API，Bearer token）
       ▼
    Gateway (ams-gateway, FastAPI)
       │ 拉起/监管 + 本机 HTTP（127.0.0.1，动态端口）
       ▼
    ams-svc-vc（Python 服务，单进程）
       ├─ 控制线程：会话状态机、参数、预设、SSE 事件生产
       ├─ 音频线程：WASAPI/ASIO 输入 → 环形缓冲 → [降噪/EQ/压缩/限幅] → 输出
       ├─ 推理线程：按 block 取数据 → RVC 引擎（CUDA Graph）→ 回填
       └─ 工作线程：模型加载/热切换、录音落盘、指标聚合
       ▼
    RVC 引擎适配器（rvc-rt / vcclient / meanvc2 / passthrough）
       ▼
    CUDA（PyTorch 2.x cu121/cu128 按显卡分支）/ CPU 降级

关键点：
- **音频线程与推理线程解耦**：音频线程只做环形缓冲读写，绝不加载模型/分配大对象；推理线程欠载时音频线程补静音或上一块残响并累计 xrun。
- **服务只绑 127.0.0.1**，端口写入 `runtime/ports.json`；Gateway→服务的鉴权用同一 token（00 第 3 节）。
- **服务不直接读写音源库**：启动时向 Gateway 请求音源清单/路径；模型文件只读打开。

### 5.2 引擎适配器

| 适配器 | 引擎/版本 | 许可 | 输入 | 输出 | 能力 | 优先级 |
|---|---|---|---|---|---|---|
| `rvc-rt` | RVC 官方 2.3.260718 实时推理（CUDA Graph 开） | **MIT** | 16k/44.1k/48k 单声道 float32 块 | 模型采样率（40k/48k） | 任意 RVC v2 音源；低延迟；热切换 | **P0 主引擎** |
| `vcclient` | VCClient v2.1.4-alpha（cuda/dml；RVC+Beatrice） | **MIT**（代码；Beatrice 模型另有许可） | 由 VCClient 自己采设备 | 由其输出设备 | 外部进程模式：AMS 只检测/启动/经其 REST 调参 | P1 备选/对照 |
| `meanvc2` | MeanVC2（Apache-2.0，流式零样本 VC） | **Apache-2.0** | 参考音频 + 实时语音 | 22.05k/48k（以其实现为准） | 零样本、无需训练；语音为主 | P2 |
| `passthrough` | 直通 | — | — | — | 排障/设备链路测试 | P0（诊断用） |

【决策】适配器契约（服务内部）：`prepare(config) / process(block) -> block|empty / set_params(patch) / load_voice(voice) / release() / stats()`；新增引擎不改 Gateway/页面。
【风险】VCClient 是外部 GUI/服务，其 REST 稳定性与版本绑定较强（v2 与 v1 差异大），仅作对照/兜底，不作默认。

### 5.3 音频 I/O 层

| 项 | P0 方案 | P1/P2 方案 | 说明 |
|---|---|---|---|
| 后端 | **WASAPI**（共享/独占可切） | ASIO（P1）；WDM-KS/DirectSound 兜底 | WASAPI 覆盖直播/游戏主流场景 |
| 实现库 | PortAudio（MIT）经 sounddevice（MIT）封装 | ASIO 需 PortAudio 带 ASIO 构建（ASIO SDK 许可）【待定】 | 避免自研驱动层 |
| 采样率 | 跟设备（44.1k/48k）；模型 40k/48k，服务内重采样 | 自适应设备切换 | 重采样用 soxr（LGPL）/ speexdsp（BSD）【待定选型】 |
| 缓冲 | 128/192/256/512/1024 帧可选，默认 256 | 自适应（xrun 时自动升档，P1） | 页面显示等效毫秒 |
| 通道 | 输入单声道（取 1 声道或降混）；输出可单/双声道复制 | 多通道（P2） | 麦克风通常 1–2ch |
| 独占 | 可选；被占用时给「谁占用了」提示（尽力枚举） | 设备占用检测增强 | 常见冲突：OBS/Discord/DAW 已开独占 |
| 热插拔 | 监听默认设备变化/设备移除，自动暂停并重连 | 自动重建流 | 3 s 内刷新设备列表 |

【待定】是否自研 C++ 音频小服务（RtAudio/JUCE）以取得更稳的 ASIO/独占：Python+PortAudio 先验证延迟与稳定性（S9），若不达标再评估 C++ helper（工作量 +2–3 周）。

### 5.4 实时线程模型与缓冲策略

- 环形缓冲：输入 4 块、输出 4 块；块长 = block_time。
- 调度：音频回调绝对不阻塞、不加锁（无锁环形缓冲 + 原子指针）；推理线程结果用双缓冲交接。
- 欠载（xrun）策略：优先复用上一块尾部做 crossfade 淡出，避免爆音；xrun 计数进指标；连续 10 次自动降档（升缓冲/降 block）。
- 漂移处理：输入/输出时钟不同源（尤其虚拟声卡）→ 动态重采样（P1）或周期性插入/丢弃 1 帧（P0，需静音处）。
- 线程优先级：音频回调线程提升到「高」；推理线程「中高」；文件/录音「普通」。

## 7. 接口与任务（Gateway API / SSE）

### 7.1 vc.session 资源模型（00 第 8 节 `vc.session`）

- 实时会话**不是 Job**：不排队、不进 Job 列表；但：
  1. 创建时向 Gateway 申请 **GPU 租约**（`lease.type=realtime`，exclusive=true，priority=high）；
  2. 在 `GET /health`/`GET /jobs` 之外单独 `GET /vc/sessions` 可查；
  3. 会话异常退出由 Gateway 检测心跳（1 s）并在 5 s 内释放租约、写错误记录；
  4. 同一时刻**只允许一个** vc.session（多实例 P2），否则返回 `VC_SESSION_EXISTS`（可配置抢占：先停旧的再开新的，需用户确认）。
- 与 Job 的冲突：当有训练/分离任务在跑（GPU 租约被占），创建会话返回 `GPU_BUSY`，页面提示「可停止任务后继续 / 排队等待（P1）/ 以 CPU 模式启动（音质/延迟下降）」。

### 7.5 GPU 锁与 Job 交互

| 情形 | 行为 |
|---|---|
| 创建会话时无 GPU 租约 | 申请 realtime 独占租约；若被训练/分离占用 → 返回 GPU_BUSY，页面提示可停止任务或 CPU 模式 |
| 会话运行中提交训练/分离 Job | Job 排队并显示原因「实时变声占用 GPU」；会话结束自动放行 |
| 会话运行中需要热切换模型 | 不释放租约（同会话内）；模型加载在工作线程 |
| 服务崩溃 | Gateway 心跳超时 → 强制释放租约、清理子进程、写 `vc_session.error` |
| 用户强杀 | 同上；下次启动时清理孤儿服务进程（按 pid 文件） |

## 9. 错误处理 / 降级 / 性能指标

### 9.1 失败模式矩阵

| 失败 | 现象 | 检测 | 处理 | 用户可见 |
|---|---|---|---|---|
| 设备被独占 | 打开失败/无声 | 打开错误码 | 改共享；提示占用程序 | 错误卡+建议 |
| 设备消失（拔麦） | 音流中断 | 设备回调错误 | 暂停→重连→恢复会话 | 「设备已断开」 |
| 采样率不匹配 | 声音变调/断续 | 打开/回调校验 | 服务重采样或切设备 | 采样率提示 |
| 模型损坏 | 加载失败 | 加载异常 | 回滚旧模型/提示重新导入 | 错误卡 |
| index 维度不符 | 加载/检索报错 | 维度校验 | 自动 index_rate=0 并提示 | 警告 |
| 显存不足 | OOM | 异常 | 降 block/CPU 模式 | 建议 |
| 推理跟不上 | xrun 增长 | xrun 计数 | 自动升缓冲/降 block/关效果 | 延迟上升提示 |
| 回授/回声 | 啸叫/自激 | 输入输出设备相同/监听开 | 强制关监听+告警 | 告警 |
| 服务崩溃 | 无声+状态断 | 心跳/退出码 | 自动重启（退避 1/2/4 s，最多 3 次）+ 会话不自动恢复 | 提示 |
| 驱动/端口冲突 | 打开失败 | 错误码 | 换端口/换设备/重启服务 | 建议 |

### 9.2 降级链

    GPU 实时（CUDA Graph）
      → GPU 实时（无 CUDA Graph，兼容性模式）
      → GPU 小模型/低 block（降质量换稳定）
      → CPU 实时（音源不换，仅降级可用性；RTF 可能 >1，明确提示）
      → passthrough（只保设备链路/录音）
    设备：WASAPI 独占 → WASAPI 共享 → WDM-KS/DirectSound 兜底
    缓冲：128 → 256 → 512 → 1024（xrun 时自动升；连续稳定 60 s 可提示降档）

### 9.3 性能指标（目标值，待 S9 Spike 实测校准）

| 指标 | P0 目标 | P1 目标 | 测量方法 |
|---|---|---|---|
| 算法延迟（block 0.15/crossfade 0.08/fcpe） | ≤ 220 ms p50 / ≤ 280 ms p95 | ≤ 160 ms p95（block 0.1） | 服务内部时间戳：块入→块出 |
| 端到端延迟（WASAPI 共享 48k/256） | ≤ 300 ms p95 | ≤ 200 ms p95 | 环回自检：输出接输入（虚拟声卡）+ 脉冲互相关 |
| 首音延迟（点开始到出声） | ≤ 5 s（模型已缓存） | ≤ 3 s | 事件时间戳 |
| 模型热切换 | ≤ 3 s（index 已缓存） | ≤ 2 s | 事件时间戳 |
| xrun | ≤ 1 次/10 min（稳态） | 0 次/小时 | 回调计数 |
| CPU | ≤ 1 核 40%（服务总计） | ≤ 1 核 25% | 进程 CPU 采样 |
| GPU | ≤ 45%（4080 Laptop） | ≤ 30% | nvidia-smi/服务上报 |
| 显存 | ≤ 3 GB（40k/48k v2 + index） | 同 | 服务上报 |
| 内存增长（4 h） | < 5% | < 2% | 采样 |
| SSE 状态延迟 | ≤ 100 ms | ≤ 50 ms | 事件打点 |
| 崩溃率 | 4 h 压测 0 崩溃 | 12 h 0 崩溃 | 长稳测试 |

【风险】官方「4090D 4.7× CUDA Graph」不等于 4080 Laptop 上同样延迟；block/crossfade 需在本机网格测试（S9），目标值可能需下调/上调，见 §13。

## 13. 风险与开放问题

### 13.1 风险

| ID | 风险 | 影响 | 概率 | 缓解 |
|---|---|---|---|---|
| R1 | Python/PortAudio 端到端延迟/稳定性不达标（尤其独占/ASIO） | 核心体验 | 中 | M0 先测；不达标则 C++ helper（RtAudio/JUCE）或改用 VCClient 引擎 |
| R2 | 虚拟声卡生态碎片化 + 用户不会配 | 支持成本高 | 高 | 模板化向导、检测、一键自检、图文/视频教程；不承诺支持所有软件 |
| R3 | VB-Cable/VST3 SDK 再分发许可 | 法务/分发 | 中 | 不内置、外链+用户安装；商业化前取得许可（00 第 16 节（待决策 6）） |
| R4 | 与训练/分离争 GPU 导致 OOM/掉帧 | 稳定性 | 中 | GPU 独占租约 + 优先级 + 明确提示；CPU 降级 |
| R5 | 模型格式/版本碎片（40k/48k、v1/v2、异常 pth） | 加载失败 | 中 | 音源库校验（core/voice-library）+ 明确错误码 + 回滚 |
| R6 | 回声/啸叫 | 体验 | 中 | 默认关监听；路由校验；P2 AEC |
| R7 | 上游 RVC 升级（2.4+）改实时接口 | 维护 | 中 | 适配器隔离 + 版本锁定 + 回归夹具；保持 2.3.260718 可用 |
| R8 | 全局快捷键与直播软件冲突 | 体验 | 低 | 可改键 + 默认关闭 |
| R9 | 杀软误报（音频钩子/子进程） | 安装/运行 | 低 | 代码签名 + 不注入进程；文档说明 |
| R10 | 4 h+ 长稳内存/句柄泄漏 | 稳定性 | 中 | 长稳测试 + 资源监控 + 自动重启 |

### 13.2 开放问题【待定】

1. ASIO 获取路径：自编译 PortAudio+ASIO SDK 分发合规？还是依赖用户装 ASIO4ALL？

7. 全局快捷键实现层（Host 插件用 Node 原生模块 vs 服务内 Win32）。

## 14. 与启动器 / 内核 / 其他插件的集成点

### 14.1 启动器

| 交互 | 说明 |
|---|---|
| 服务生命周期 | 启动器安装 `service.ams-svc-vc`（独立运行时），Gateway 按需拉起；启动器页显示版本/健康/日志 |
| 组件 | `tool.vb-cable`（检测/引导安装）、`tool.rvc-vst`（下载/校验/安装/教程）、`tool.ffmpeg` |
| 硬件检测 | 启动器提供显卡/驱动/CUDA 信息（服务读数兜底） |
| 更新 | 服务/插件独立更新；更新前检查是否有运行中会话（有则提示/禁止） |
| 提权 | 仅虚拟声卡/驱动安装时 UAC，由启动器发起 |

### 14.2 内核

| 交互 | 说明 |
|---|---|
| 页面/导航/设置 | Client 插件注册（§4.1） |
| AI 工具 | Host 插件注册 `music_vc_*`（§8.1） |
| Skills | `ams-实时变声配置` 等随插件分发 |
| 任务中心 | 会话不显示在 Job 列表，但任务中心显示「实时会话占用 GPU」状态（来源 `/vc/sessions`） |
| 权限/审批 | 安装虚拟声卡、全局快捷键需审批卡 |

### 14.3 其他插件

| 插件 | 集成 |
|---|---|
| 01 音源炼制 | 消费其产出的 `voices/` 音源；页面「去炼制一个音源」跳转 |
| 02 人声分离 | 不直接依赖；实时场景不分离 |
| 04 歌曲换源 | 共享参数对象/预设；「把当前实时参数套到离线换源」 |
| 08 混音母带 | 录音/导出文件进混音；响度对齐 |
| 评测器 | 录音质量/相似度评估可调评测器 |
| 音色库 | 提供音源列表/metadata/hash；实时页音源下拉复用其组件 |
| 项目 | 会话可绑定 project，录音落 `vocals/`，写 project.json steps |

### 14.4 服务（`ams-svc-vc`）

| 项 | 约定 |
|---|---|
| 入口 | `ams-svc-vc --host 127.0.0.1 --port 0 --token <runtime/gateway.token>` |
| 健康 | `GET /health` → {ok, version, engine, device_state} |
| 就绪 | `GET /ready` → 设备/模型是否可交互 |
| 停止 | SIGTERM/HTTP `POST /shutdown`：先停音频流、再释放模型、最后退出（≤2 s） |
| 日志 | stdout JSONL + 文件；由 Gateway 收集 |
| 版本 | 独立 SemVer；插件在 `ams.services` 声明最低版本 |
