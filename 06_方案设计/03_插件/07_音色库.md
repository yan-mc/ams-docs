## 1. 目标与非目标

### 1.1 目标

| # | 目标 | 说明 |
|---|---|---|
| G1 | **严格格式零歧义** | 唯一标准：`AMS_HOME/voices/<名称>/<名称>.pth`（+ 同名 `.index` 可选），见 00 第 6 节；不引入第二套"必需"格式 |
| G2 | **扫描即资产盘点** | 启动/手动/监听三种触发，秒级列出全部音源，丢失/新增/改名自动发现 |
| G3 | **校验有依据** | 解析 pth 元数据（version/sr/f0/说话人数/epoch）与 index 维度，给出「可用/警告/错误」三级结论与修复建议；**绝不执行不可信代码** |
| G4 | **导入无痛** | 支持"已经是标准格式的文件夹"、"散装 pth+index"、"ZIP 包"、批量目录、以及 TTS/SVS 声库分类导入；冲突有策略 |
| G5 | **试听即所得** | 用内置示例干声跑一次真实换声（RVC），缓存成试听片段；不用打开别的软件就能判断"像不像" |
| G6 | **可组织可检索** | 自动标签 + 用户标签 + 收藏 + 评分 + 全文搜索 + 多维排序/筛选；1000+ 音源仍流畅 |
| G7 | **可追溯可关联** | 来源/许可备注、hash、解析缓存；同一角色的 RVC/TTS/SVS 资产互相关联 |
| G8 | **AI 可操作** | `music_voice_*` 工具 + `/voices/*` API，AI 可"扫描→校验→整理标签→试听→选音色" |

### 1.2 非目标

| 不做 | 归属 |
|---|---|
| 训练/微调音源 | `插件 01 音源炼制`（RVC 训练）、`插件 05 TTS`（GPT-SoVITS 微调） |
| 下载基础模型/底模 | `启动器 组件中心 / models 目录`（00 第 5 节）；音色库只展示依赖状态 |
| 音源分发/上传/市场 | 00 第 6 节「音源不上传、不打包进安装包」；本项目不做社区分发 |
| 音频内容编辑（切片/降噪/变调） | 数据集插件 / 混音插件 |
| 实时变声会话 | `插件 03 变声器`（音色库只提供选择器与预览） |
| MSVC 格式逆向/转换实现 | 启动器 MsvcConverter（本插件仅提供入口按钮并调用 `msvc.convert` 任务） |

## 2. 用户与场景

### 2.1 用户画像

| 用户 | 需求 | 关键路径 |
|---|---|---|
| 新手 | 把下载来的音源丢进软件就能用 | 拖拽/导入 → 自动规整 → 校验通过 → 试听 |
| 玩家（多音源） | 几十上百个音源，按角色/用途管理 | 标签/收藏/搜索/排序、同名冲突处理、重复检测 |
| 音源炼制者 / 配音创作者 | 训练产物自动入库、同角色关联；在不同插件里快速选同一角色 | 训练回调入库 → 解析 → 自动标签 → 关联建议；统一音色选择器跨插件一致 |
| AI 操作者 | "把音色库整理一下/找 XX 的音色/试听前 5 个" | `music_voice_*` 工具 + `ams-音色库整理` skill |

### 2.2 典型场景（验收导向）

| 场景 | 输入 | 输出 | 验收要点 |
|---|---|---|---|
| S1 首次启动 | 已有 `voices/爱莉希雅/爱莉希雅.pth+.index` | 网格中显示 1 张卡片，元数据完整 | 首次扫描 ≤ 2 s/10 个文件；卡片含版本/采样率/index 角标 |
| S2 导入散装文件 | `manbo.pth` + `manbo.index`（不同目录） | `voices/曼波/曼波.pth+.index` | 3 步向导完成；原文件不动（复制模式） |
| S3 导入 ZIP | 一个含 pth+index 的 zip | 规整入库 | 拒绝 zip slip/超大/非白名单文件；冲突按策略处理 |
| S4 校验坏文件 | 截断的 pth / v2 pth 配 v1 index | 错误/警告卡片 + 原因 | 不崩溃、不阻塞其它音源、可一键定位文件 |
| S5 试听对比 | 3 个音源候选 | 各 1 段 8 s 试听 | 首次每个 ≤ 15 s（GPU），缓存后 < 0.5 s |
| S6 大库 | 1000 个音源（含混杂） | 增量扫描 + 搜索 | 增量 ≤ 3 s；首屏 ≤ 1 s；搜索 ≤ 200 ms |
| S7 跨用途关联 | 同角色的 RVC 音源 + TTS 音色 | 详情页"其他用途"互链 | 一处关联，两端可见；不移动文件 |
| S8 AI 整理 | "给未打标签的音源按角色归类" | 标签建议清单（AI 提议） | AI 只能提议，用户确认后写入 |

## 3. 功能清单（P0/P1/P2 + 验收标准）

## 5. 技术架构与依赖

### 5.1 组件划分

~~~text
Client 插件(React) ──► Gateway /api/v1/voices/*  ──►  voices-service(Python, 由网关内置)
                                                        ├─ 扫描器（walk + 规则）
                                                        ├─ 解析器（子进程沙箱：pth/index）
                                                        ├─ SQLite 索引（含 FTS5）
                                                        └─ 预览编排（提交 voice.preview → rvc-infer 服务）
Host 插件(Node) ── 注册 music_voice_* 工具、SSE 订阅、监听目录变更事件
~~~

- 扫描/解析**不放在 UI 进程**，也不放在 kernel：由 Gateway 内的 voices-service 负责（性能与安全隔离）。
- 预览需要 GPU → 由 Gateway 提交 `voice.preview` 到 `rvc-infer` 服务（复用插件 04 的后端），本插件不直接跑模型。
- 解析必须**隔离**：单独子进程（可设内存/时间上限），在禁止网络与写入的用户态执行；主进程只收 JSON。

### 5.2 依赖与版本/许可

| 组件 | 版本 | 许可 | 用途 |
|---|---|---|---|
| Python | 3.10+ | PSF | 服务运行时 |
| torch（CPU 版即可） | 2.6.0+cpu | BSD-3-Clause | 仅用于 **weights_only=True** 安全读 pth；不加载到 GPU |
| faiss-cpu | 1.8+（或 1.7.2） | MIT | 只读解析 .index（d/ntotal/nlist/nprobe） |
| fastapi / pydantic | 0.115 / 2.10 | MIT | Gateway（00 第 3 节 已定） |
| watchdog | 6.0.x | Apache-2.0 | voices 目录实时监听 |
| Pillow | 11.x | HPND | 封面缩略图 |
| SQLite | 内置（3.40+） | Public Domain | 索引/搜索（FTS5） |
| soundfile/librosa | 0.13 / 0.10 | BSD-3/ISC | 示例音频与预览校验（时长/响度） |

> 说明：解析 pth 只需 CPU 版 torch；**不允许**为此插件安装 CUDA/大模型依赖（00 第 5 节 组件独立更新）。

### 5.3 安全解析方案（本插件最关键的技术决策）

【决策】pth 元数据解析采用「**强约束 + 子进程 + 失败即弃**」三步：

| 步骤 | 做法 | 理由 |
|---|---|---|
| 1 | `torch.load(path, map_location="cpu", weights_only=True)`（torch ≥ 2.6 默认） | `weights_only=True` 只允许张量/基础类型，**不执行任意类构造函数**，避免 pickle RCE |
| 2 | 在独立子进程运行：无网络、只读挂载目标目录、RLIMIT/超时（30 s）、内存上限（1.5 GB） | 兜底防"恶意/异常文件"拖垮主服务 |
| 3 | 只读取白名单字段：`config/f0/info/sr/version/weight(仅键名与 emb_g 形状)`；**不**反序列化到显存、不 eval、不导入第三方模块 | 最小信息面 |
| 失败 | 标记 `parse_status=unparsed` + 原因；卡片仍可展示/删除/试听（试听走引擎时会再报错）；**绝不回退到 weights_only=False** | 安全 > 完整 |

【待定】是否自研 restricted unpickler（只允许 `collections.OrderedDict / torch.Tensor / torch._utils._rebuild_tensor_v2 / 基础类型`）以兼容个别老 ckpt；若实现，需独立 fuzz 测试（M2 前定）。

**index 解析**：faiss 读取不执行代码；解析项 = `d / ntotal / nlist(faiss.IndexIVF) / nprobe`。若 faiss 不可用 → 只按 pth 版本推断期望维度并标注「未校验」【决策】。

## 6. 数据模型与目录

### 6.1 严格格式（P0，唯一标准，来自 00 第 6 节）

~~~text
AMS_HOME\voices\
├─ 爱莉希雅\
│  ├─ 爱莉希雅.pth        # 必需；能被 RVC v2 推理加载
│  ├─ 爱莉希雅.index      # 可选；有则同名；无 = 无检索增强（index_rate 无效）
│  └─ voice.json          # 可选旁车（应用生成/可删）
└─ 曼波\
   ├─ 曼波.pth
   └─ 曼波.index
~~~

| 规则 | 判定 | 违规处理 |
|---|---|---|
| 文件夹名合法 | 非 Windows 非法字符 `<>:"/\|?*`、非保留名（CON/PRN/AUX/NUL/COM1-9/LPT1-9）、不以空格/点结尾、长度 1–96 | 导入时自动清洗或拒绝 |
| 同名 pth 存在 | 与文件夹名一致（扩展名大小写不敏感） | 缺 → error（「缺少同名 pth」） |
| index 可选 | 有则必须同名；多出的其它 index 视为"未关联" | warn（「存在未关联 index」） |
| 大小写 | Windows 不敏感；DB 存实际名 | — |

### 6.2 旁车 `voice.json`（可选，schema `ams-voice/1`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `schema` | string | ✅（若存在） | `"ams-voice/1"` |
| `uid` | uuid | ⭕ | 应用写回的内部标识（非音源 ID）；缺失时按路径/hash 生成 |
| `display_name` | string | ⭕ | 仅当与文件夹名不同（提示用户可改名） |
| `tags` | string[] | ⭕ | 用户标签 |
| `favorite` / `rating` | bool / 0–5 | ⭕ | 收藏/评分 |
| `notes` | string | ⭕ | 备注（来源、听感、适用场景） |
| `source` | object | ⭕ | `{type: self/trained/imported/web, author?, url?, added_at?}` |
| `license` | object | ⭕ | `{voice_source: own/authorized/unknown, commercial_use: true/false/unknown, evidence?, note?}` |
| `link` | object | ⭕ | `{tts_voice_ids: [], svs_voicebank_ids: []}`（同角色） |
| `parsed` | object | ⭕ | 缓存：`{version, sr, f0, n_speakers, epoch, step, index_d, index_ntotal}`（DB 为准，可重建） |
| `hash` | object | ⭕ | `{pth, index, algo:"sha256"}` |
| `updated_at` | string | ⭕ | 冲突合并依据 |

规则：**删除 voice.json 不影响使用**（00 第 6 节）；应用可重建；只读目录不写回，只记 DB；写入采用"临时文件 + 原子替换"；用户手工编辑以 `updated_at` 较新者为准并在 UI 提示差异。

### 6.3 标识策略（遵循 00 第 6 节）

| 概念 | 定义 | 用途 |
|---|---|---|
| **音源 ID（voice_id）** | **`voices/` 下的文件夹名**（00 第 6 节定义；中文/空格允许，URL 时编码） | API 路径参数、项目引用、其它插件选择器（03/04 同口径） |
| 内部 `uid` | UUIDv7：DB 主键，仅供改名追踪/关联表外键 | 改名后重定位；不对外作为音源 ID |
| 快照 | 项目/任务记录 `{voice_id, uid, pth_sha256_first16}` | 可复现；改名后按 uid+hash 找回并提示"原名 XX" |

【决策】改名 = 「改文件夹名 + 改同名 pth/index」的原子操作（DB 按 uid 更新 + 备份 voice.json），改名后音源 ID 随之变化，项目引用按 uid/hash 兜底。

### 7.3 解析字段（校验输出，事实依据见 01 报告 §7.2/§7.3）

**pth 元数据**

| 字段 | 取值 | 来源 | 说明 |
|---|---|---|---|
| `exists/parse_status` | ok/unparsed/error | 文件系统/解析 | — |
| `version` | `v1` / `v2` | 顶层 `version` 字段或 config | v1=256 维 HuBERT，v2=768 维 |
| `sr` | 32000 / 40000 / 44100 / 48000 | 顶层 `sr` 与 `config[-1]` | 采样率必须与推理参数一致 |
| `f0` | 0/1 | 顶层 `f0` 或 config | 是否带音高输入 |
| `n_speakers` | int | `emb_g.shape[0]`（可能覆盖 config[-3]） | 官方底模为 109；异常值提示第三方底模 |
| `gin_channels` | 256 | `config[-2]` | 结构校验 |
| `epoch/step` | int | `info` 字符串（如 `e15`、`epoch_8_step_1336`） | 训练线索；解析失败则 `unknown` |
| `size` | bytes | 文件 | 正常小模型 50–60 MB；> 150 MB 疑似 G_/D_ |
| `sha256` / `sha256_quick` | hex | 计算 | 全量/快速指纹（前 1 MB + 尾 1 MB + size） |

**index 元数据**

| 字段 | 取值 | 说明 |
|---|---|---|
| `index_d` | 256 / 768 | v1↔256、v2↔768；与 pth 不匹配 → warn |
| `index_ntotal` | int | 训练特征条数（越多越"像"但可能更慢） |
| `index_nlist / nprobe` | int（IVF 时） | 检索质量/速度线索 |
| `index_size` | bytes | 常见 30–140 MB |

### 7.4 校验规则与三级结论

| 检查 | ok | warn | error |
|---|---|---|---|
| 文件夹/同名 pth | 齐备 | — | 缺 pth / 名称不合法 / 层级不对 |
| pth 可解析 | 成功 | 解析超时（unparsed） | 损坏/截断/非 pth |
| version 与文件大小 | v2 且 50–60 MB | v2 但 >150 MB（疑似训练权重） | 大小 < 20 MB（大概率不是模型） |
| index 维度匹配 | d 与 version 一致 | 缺 index / d 不匹配 / 无法解析 | — |
| emb_g 说话人数 | 109（官方底模）或可解释 | ≠109（第三方底模，能力可能受限） | — |
| 重复 | 无重复 | 同 hash 不同名（重复副本） | 同目录内重名文件 |
| 基础模型误放 | — | — | 命中基础模型特征（G_/D_/rmvpe/hubert/s2G） |

校验结论写入 `voices.status`，并保留最后一次报告（详情页可查看/导出 CSV）。

## 9. 错误处理、降级与性能

### 9.1 降级链

| 故障 | 降级 | 提示 |
|---|---|---|
| faiss 不可用 | 只解析 pth + 推断 index 维度（标"未校验"） | 「索引校验不可用，已降级」 |
| torch 解析失败/超时 | 卡片标 `unparsed`，不阻塞全库 | 「解析失败，可查看文件或删除」 |
| GPU/预览服务不可用 | 试听按钮禁用/排队 | 「试听需要 RVC 服务，去启动/安装」 |
| 大库（>5000） | 只做增量；深度 hash 延后到空闲 | 「后台计算中，稍后可查」 |
| 网络盘 | 超时 30 s + 重试 1 次；建议本地盘 | 明确路径与磁盘类型 |
| 目录无权限 | 只读展示、不写 voice.json | 「目录只读，元数据仅存本地库」 |

### 9.2 性能目标

| 操作 | 目标 | 说明 |
|---|---|---|
| 增量扫描（1000 音源） | ≤ 3 s | mtime+size 快速比对；仅新增/变更解析 |
| 首次全量（1000） | ≤ 30 s（不含 hash） | 解析并发 4；hash 异步 |
| 单条深度解析 | ≤ 1 s（pth）/ ≤ 0.3 s（index 头） | CPU 只读 |
| UI 首屏 | ≤ 1 s（1000 条） | DB 分页 + 虚拟滚动 |
| 搜索 | ≤ 200 ms | FTS5 + 索引 |
| 试听（首次） | ≤ 15 s/条（GPU） | 8 s 干声换声；缓存命中 < 0.5 s |
| 试听（缓存） | < 0.5 s | previews 表 + 静态文件 |
| 预览预热（批量） | 100 条 ≤ 8 min（GPU，低优先级） | 空闲时段 |

> 资源与队列：解析任务 CPU 密集（最多 4 并发、单条超时 30 s、内存上限 1.5 GB/子进程）；预览走 GPU 锁与低优先级队列；watch 事件 debounce 2 s，同根目录扫描与用户操作互斥。

## 10. 安全、许可与合规

| 主题 | 规则 |
|---|---|
| **不执行** | 禁止 `torch.load(weights_only=False)`；禁止加载/执行任何 pth 内代码；解析在沙箱子进程；index 只读解析 |
| **不修改原文件** | 默认复制导入；只有用户显式"移动/改名"才写；所有写入先备份（回收站/临时文件原子替换） |
| **路径安全** | 只允许 AMS_HOME 与用户显式选择的根；防目录穿越（zip slip）；Windows 长路径用 `\\?\`；禁止符号链接逃逸 |
| **ZIP 安全** | 单包 ≤2 GB；解压后总量 ≤4 GB；条目白名单（`.pth/.index/.json/.txt/.png/.yaml`）；拒绝绝对路径/`..`/NTFS ADS/可执行文件 |
| **删除** | 软删除进回收站（默认保留 30 天）；永久删除需二次确认；不触碰回收站以外的用户文件 |
| **隐私** | 不联网、不上传；解析结果只本地存 |
| **许可备注** | voice.json/DB 记录音源来源与使用授权状态（own/authorized/unknown）；未知状态在导出/使用时提示 |
| **合规** | 音源版权与声音权由用户负责（00 第 1 节）；音色库不提供下载/分发功能；发现疑似真人未授权素材仅提示风险 |
| **审计** | `voice_events` 记录扫描/导入/校验/删除/试听，便于回溯 |
