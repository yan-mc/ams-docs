## 0. 一页结论

| 维度 | 结论 |
|---|---|
| 定位 | 换声/分离/合成之后的“最后一公里”：对轨 → 增益/EQ/压缩/混响 → 响度标准化 → 参考母带 → 导出成品；**不做编曲、不做 MIDI、不做实时录音** |
| P0 范围 | 多轨导入、波形/播放、对轨（偏移/延迟补偿/BPM 网格）、增益/声像/静音独奏、3 段 EQ、单段压缩、轻量混响、响度测量与归一、真峰值限幅、wav/flac/mp3 导出、工程快照、`mix.render` |
| 技术路线 | 内部统一 48 kHz / float32 / 立体声；**默认 DSP 全部自研**（RBJ biquad、前馈压缩、卷积混响、前瞻限幅），零 GPL 依赖；pedalboard（GPL-3.0）与 matchering（GPL-3.0）只作**可选独立子进程组件** |
| 响度 | 测量 **pyloudnorm 0.2.0（MIT，调研 §9）**＋自研真峰值表；流媒体归一用 **ffmpeg loudnorm 双 pass**；默认 -14 LUFS / -1 dBTP，可切预设 |
| 最大风险 | ①GPL 组件分发合规；②混音质量难以客观保证（AI 只建议、不代改参数）；③长音频波形/播放的内存与解码压力 |

【决策】P0 不内置 pedalboard/matchering 二进制；默认链路 100% 为 MIT/Apache/BSD 依赖，可随安装包分发。
【决策】`mix/mix.json` 是混音工程唯一真源；渲染产物落 `mix/renders/<render-id>/`，发布成品落 `exports/`（见 00 第 7 节）。
【待定】是否提供 GPL 组件的“一键安装 + 源码获取页”（需法务确认，见第 10 章）。

## 1. 目标与非目标

### 1.1 目标

| # | 目标 | 验收口径 |
|---|---|---|
| G1 | 换声/分离/合成后的素材能快速拼成可发布成品 | 从导入到导出 ≤ 6 步；新手 10 分钟内出第一版 |
| G2 | 对轨准确、听感无相位/延迟问题 | 自动对轨误差 ≤ ±5 ms；手动步进 1 ms；对轨后 null-test 残差 ≤ -60 dBFS |
| G3 | 响度标准化符合平台要求 | 集成响度误差 ≤ ±0.2 LU；真峰值 ≤ -1.0 dBTP；无削波 |
| G5 | 全过程可回溯 | 每次渲染写 `render.json` + 工程快照，可从快照一键重渲 |
| G6 | AI 可协作 | Agent 能建档/导入/套模板/量响度/渲染/对比/导出；不静默修改音质参数 |
| G7 | 许可干净 | 默认安装不含 GPL/AGPL 组件；GPL 组件隔离、声明、源码入口齐备（见第 10 章） |

### 1.2 非目标

| # | 非目标 | 原因/去向 |
|---|---|---|
| N1 | 编曲、MIDI 编辑、虚拟乐器（VSTi） | 与“换声/填词/混音”主线无关；编曲交给外部 DAW 或 P3 的 ACE-Step 方案 |
| N2 | 实时录音、多轨实时监听、低延迟 overdub | 需要原生音频驱动与独占设备，属变声器插件域（见 05 变声器方案） |
| N3 | 黑箱“一键出歌”的自动混音决策 | 质量无法保证且不可解释；只做模板 + 建议 + 人工确认 |
| N4 | 完整 DAW 工程编辑（dawproject 仅导出，不反向导入编辑） | 范围过大；P1 只做导出互操作（调研 §9 工程格式） |

## 2. 用户与场景

### 2.1 角色

| 角色 | 特征 | 关注点 |
|---|---|---|
| 普通用户（翻唱/换声玩家） | 不懂压缩/EQ，只想“听起来像成品” | 预设模板、响度自动达标、一次性导出 |
| 进阶用户（会调参） | 懂 LUFS/压缩比/侧链 | 精细增益、总线、效果链顺序、A/B、stem 导出 |
| AI 操作者（Agent） | 通过工具调用完成全流程 | 工具契约稳定、可预检、可回滚、进度可订阅 |

### 2.2 典型场景

| # | 场景 | 输入 | 用户/Agent 操作 | 产物 | 验收 |
|---|---|---|---|---|---|
| S1 | 换声后合成 | 换声人声 + 原伴奏 | 导入两轨 → 自动对轨 → 套“人声突出”模板 → 量响度 → 渲染 → 导出 wav | `exports/<name>.wav` | 人声与伴奏对齐 ≤ 5 ms；-14 LUFS |
| S2 | 分离后重混 | 分离出的人声/伴奏/和声 | 三轨 + 和声降 3 dB + 声像展开 → 渲染 mp3 | 成品 + stem | 和声不糊、无相位抵消 |
| S3 | 配音叠乐 | TTS 念白/台词 + 配乐 | 旁白总线压缩 + 音乐 ducking（P1）→ 导出 | 有声书/视频配音 | 旁白清晰、音乐不抢 |
| S4 | 填词成歌收尾 | SVS 干声 + 伴奏 | 干声 EQ/压缩 + 轻混响 → 母带 | 成品 | 与参考曲听感接近 |
| S5 | 参考母带 | 自己混的成品 + 商业参考曲 | 参考匹配（可选 matchering）→ 对比 → 微调 | 母带版 | 响度/频谱接近参考，不失真 |

### 2.3 AI 操作场景

| # | 用户对 AI 说 | Agent 工具链 | 人工确认点 |
|---|---|---|---|
| A1 | “把 vocals.wav 和伴奏合成 -14 LUFS 的成品” | `music_mix_create_project` → `music_mix_import_tracks` → `music_mix_apply_chain(template)` → `music_mix_analyze_loudness` → `music_mix_render` → `music_mix_export` | 模板选择、最终响度目标 |
| A3 | “这 10 个工程按同一模板批量出 mp3” | 循环 `music_mix_apply_chain` + `music_mix_render`（批量任务） | 批量前确认磁盘与目标目录 |
| A4 | “为什么限幅后还是削波/失真” | 读 `render.json` 的 true-peak 曲线与 limiter 日志 → 解释 | 无（只读解释） |

### 4.3 波形与播放策略

- 峰值缓存：服务端按“每像素 min/max + RMS”生成多级（LOD 1×/4×/16×）JSON，缓存到 `mix/peaks/`，源文件 mtime+size+hash 变化则失效。
- 播放：P0 用浏览器 WebAudio 解码导出的 48 kHz 预混版本（`mix/proxies/preview-<hash>.wav`），不实时跑 DSP，保证低延迟与一致听感。
- 采样率：内部统一 48 kHz；44.1/96 kHz 输入用 ffmpeg 或 scipy 多相重采样（P0 用 scipy，BSD 许可），并在 mix.json 记录原采样率。

### 4.4 状态与异常

| 状态 | 表现 | 处理 |
|---|---|---|
| 空工程 | 引导卡片“导入第一条轨道” | 提供“从工程产物导入”入口 |
| 渲染中 | 导出禁用、进度条、可取消 | 取消后清理临时文件 |
| 服务离线 | 页面降级只读 | 显示“服务未启动”，提供重启按钮（经启动器） |

### 5.3 GPL 组件隔离方案（pedalboard / matchering）

| 组件 | 隔离方式 | 通信契约 | 默认是否随包 | 缺失时降级 |
|---|---|---|---|---|
| pedalboard（GPL-3.0） | 独立 venv + 独立进程；不 import 到 service.mixer | argv 参数 + 输入 wav + 输出 wav + stdout JSON | 否（可选组件） | 自研 biquad/压缩/卷积混响 |
| matchering（GPL-3.0） | 独立 venv + 独立进程（CLI） | argv：target/reference/out + 参数；退出码 + stdout | 否（可选组件） | 频谱匹配 + 响度匹配近似（P1） |

【决策】隔离必须满足 6 条硬约束：
1. 不静态/动态链接、不同进程 import、不共享内存或对象句柄；
2. 只通过命令行参数、音频文件、stdout JSON 交换数据（“文件 + 进程”边界）；
3. 安装到 `services/optional/<name>/<version>/`，独立版本号、可单独卸载；
4. 分发时附完整 LICENSE 文本与源码获取 URL（GPLv3 §6 义务）；
5. 用户首次启用弹出“GPL 组件”说明并二次确认；
6. 渲染配置记录 `effects_engine: builtin|pedalboard`，保证可复现。
【风险】FSF 对“进程隔离=独立作品”持否定态度；上述方案是工程惯例，不是法律保证；若法务不认可，则改为“用户自装、应用不随包分发”。

### 5.4 渲染引擎设计

| 阶段 | 实现（P0） | 关键点 |
|---|---|---|
| 解码 | ffmpeg → float32 48 kHz | 记录源采样率/位深/声道；失败给源码错误 |
| 重采样 | scipy.signal.resample_poly | 有理近似（44100→48000 用 147/160），质量可配 |
| 对轨 | FFT 互相关（1–5 s 窗口） | 偏移取整样本；<0.5 ms 忽略；可手动覆盖 |
| 轨道处理 | 常数功率声像、余弦淡入淡出 | 增益在发送端应用，效果前/后可选 |
| 效果（builtin） | RBJ biquad EQ、前馈 RMS 压缩、合成 IR 卷积混响 | 每效果参数写入 mix.json；旁通不计算 |
| 总线 | 求和 + 总线效果 | 人声/伴奏/主三级；总线可旁通 |
| 母带 | 可选 EQ → 压缩 → 前瞻限幅 | 限幅 4× 过采样检测真峰值 |
| 输出 | float32 → TPDF dither（16 bit）→ ffmpeg 编码 | 固定随机种子，保证可复现 |

- 分块渲染：65536 样本/块，效果链维护跨块状态（滤波器 zi、压缩包络、混响 tail）。
- 内存预算：`样本数 × 声道 × 4 B × 活跃系数`；超过 1.5 GB 自动切“流式块处理”（不整段载入）。

### 5.5 响度与真峰值

- 测量：pyloudnorm `Meter`（ITU-R BS.1770-4，-70/-10 LUFS 门限）给集成/短时/瞬时值；真峰值按 BS.1770-4 Annex 2 的 4× 过采样实现。
- 归一策略 A（默认）：渲染后整体增益到目标 LUFS → 再过限幅；动态基本保留。
- 归一策略 B（可选）：ffmpeg `loudnorm` 双 pass（`linear=true` 尽量保动态），用于“流媒体版”。
- 目标预设：流媒体 `-14 LUFS / -1 dBTP`；广播 `-23 LUFS / -1 dBTP`（EBU R128）；短视频/车载 `-9…-11 LUFS`；Apple 系 `-16 LUFS`【待核实平台策略】。
【决策】默认 A；B 只在“导出流媒体版本”勾选时使用，两个版本分别登记产物。

### 5.6 导出编码

| 格式 | 编码器 | 参数 | 许可 | 备注 |
|---|---|---|---|---|
| wav | PCM | 16/24 bit、32 bit float | 无 | 母带与交付首选；float32 仅内部/进阶 |
| flac | ffmpeg flac | 压缩级 5 | BSD（libFLAC） | 无损归档；带 Vorbis comment |

命名：`<工程名>_<版本>_<响度目标>_<yyyyMMdd-HHmmss>.<ext>`；同名冲突自动加序号。

## 6. 数据模型与目录

### 6.1 目录结构（在 00 第 7 节的 `mix/`、`exports/` 内展开，不改顶层结构）

~~~text
projects/<project-id>/
├─ mix/
│  ├─ mix.json                      # 混音工程唯一真源
│  ├─ renders/<render-id>/
│  │  ├─ mix.snapshot.json          # 渲染时工程快照
│  │  ├─ render.json                # 参数/指标/产物/耗时/引擎版本
│  │  ├─ output.wav                 # 中间结果（float32 或 24bit）
│  │  └─ render.log
│  ├─ snapshots/<ts>.json           # 手动快照（P0）
│  ├─ peaks/<source-hash>/<lod>.json
│  └─ reference/<ref-id>.wav        # 参考曲（P1，用户确认后复制）
├─ exports/<name>_<target>_<ts>.<ext>
└─ logs/
~~~

### 6.2 mix.json 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| schema_version | string | `mix/1`；升级走迁移（见 10 章） |
| project_id | string | 与 project.json 一致 |
| sample_rate | int | 固定 48000（内部）；源采样率记录在 track.source |
| tracks[] | array | 轨道（见 6.3） |
| buses[] | array | 人声/伴奏/主总线；增益、效果链、旁通 |
| master | object | 母带链（EQ/压缩/限幅）、目标 LUFS/TP、是否参考匹配 |
| loudness | object | target_lufs、target_true_peak、tolerance、preset 名 |
| reference | object? | 参考曲路径、匹配强度、matchering 版本 |
| revision | int | 每次保存 +1；渲染记录该值（乐观并发） |

### 6.3 track / clip / effect 字段

| 对象 | 字段 | 说明 |
|---|---|---|
| track | id、name、role、mute、solo、gain_db、pan、bus、effects[]、clips[] | role ∈ vocal/instrumental/harmony/score |
| clip | source、start_sec、offset_sec、duration_sec、fade_in、fade_out、gain_db | offset 为对轨偏移（正=延后） |
| effect | type、enabled、order、params{} | type ∈ eq3/comp/reverb/limiter/eq8/deesser（P1） |

### 6.4 mix.json 节选（数据模型示例，非实现代码）

~~~json
{
  "schema_version": "mix/1",
  "project_id": "p_20261019_001",
  "tracks": [{ "id": "t1", "name": "人声", "role": "vocal", "gain_db": 0, "pan": 0, "bus": "vocal" }],
  "master": { "limiter": { "ceiling_dbtp": -1.0, "lookahead_ms": 5 } },
  "loudness": { "target_lufs": -14, "target_true_peak": -1.0, "preset": "streaming" },
  "revision": 7, "updated_at": "2026-10-19T20:30:00+08:00"
}
~~~

### 6.5 快照与版本规则

- 每次渲染把当时的 mix.json 完整复制为 `mix/renders/<render-id>/mix.snapshot.json`，并记录 `render.json.revision`。
- 恢复快照 = 以快照内容覆盖 mix.json（写前备份到临时文件，写后 +1 revision）；渲染中的工程禁止恢复。
- mix.json 采用原子写（同目录临时文件 + rename + fsync），并保留最近 5 个自动备份（`mix/.backup/`）。

## 7. 接口与任务

### 7.1 Gateway REST API（前缀 `/api/v1`，鉴权见 00 第 3 节）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/projects/{pid}/mix` | 取 mix.json（含 revision/etag） |
| PUT | `/projects/{pid}/mix` | 保存 mix.json（If-Match revision 乐观锁） |
| POST | `/projects/{pid}/mix/import` | 导入轨道（路径/工程产物 id），返回解析信息 |
| GET | `/projects/{pid}/mix/peaks/{track_id}` | 波形峰值（LOD 参数） |
| POST | `/projects/{pid}/mix/analyze/loudness` | 量响度/真峰值/短时曲线（不渲染） |
| POST | `/projects/{pid}/mix/render` 或 `/jobs` | 提交 `mix.render` Job |
| POST | `/projects/{pid}/mix/snapshots` | 手动快照 |
| GET | `/presets/mix` | 效果链/母带预设列表 |
| POST | `/projects/{pid}/mix/export` | 从指定 render 导出成品到 exports/ |

### 7.2 Job `mix.render` 参数

| 参数 | 必填 | 说明 |
|---|---|---|
| project_id | 是 | 工程 id |
| mix_revision | 否 | 指定快照版本；缺省用当前 revision |
| snapshot_id | 否 | 用某个快照渲染 |
| format | 是 | wav16/wav24/wav32f/flac/mp3_320… |
| loudness_target | 否 | lufs + true_peak；缺省用 mix.json 设置 |
| effects_engine | 否 | `builtin`（默认）/`pedalboard`（未安装则失败并提示） |
| reference | 否 | 参考曲 id（P1） |
| output_dir | 否 | 默认 `mix/renders/<id>`；发布版由 export 走 `exports/` |
| seed | 否 | dither 随机种子（默认 0） |

### 7.3 SSE 事件（`GET /jobs/{id}/events`）

| 事件 | 载荷 | 说明 |
|---|---|---|
| progress | `{percent, stage}` | stage：decode/align/render/master/encode |
| warning | `{code, message}` | 非致命（如 limiter 频繁触发、单声道源） |
| artifact | `{artifact_id, kind, path}` | 渲染产物登记 |
| status | `{status, error?}` | succeeded/failed/cancelled |

### 7.4 错误码

| 码 | 含义 | 用户提示/处理 |
|---|---|---|
| MIX_E_001 | 源文件缺失/不可读 | 重新定位源文件 |
| MIX_E_002 | 解码失败/编码不支持 | 建议转码为 wav |
| MIX_E_003 | mix.json 校验失败 | 提供备份恢复入口 |
| MIX_E_004 | revision 冲突 | 提示重载/另存快照 |
| MIX_E_005 | 磁盘空间不足 | 显示所需/可用空间 |
| MIX_E_006 | 可选组件未安装 | 指引安装 pedalboard/matchering 或切 builtin |
| MIX_E_008 | 真峰值超上限（不可达） | 建议降低目标响度 |

### 7.5 幂等、并发与超时

- 渲染幂等：同 `mix_revision + 参数 + seed` 命中已有 render（hash 相同）则直接复用，不重复计算。
- 工程级串行：同一 project 同时只允许一个渲染；第二个进入 queued 并显示原因。
- 超时：单次渲染默认 30 min（>30 min 音频自动放宽到 60 min），超时标记 failed 并保留日志。

### 8.2 契约要点

- 每个工具都有 JSON Schema、明确超时、错误码；参数非法在工具层即拒绝（不落到服务）。
- 写接口必须带 `expected_revision`（除创建），冲突返回 `MIX_E_004` 让 Agent 重读。
- 破坏性操作（restore/export 覆盖）要求 `confirm: true`；导出默认不覆盖同名文件。

### 8.3 AI 建议边界

- AI 只输出“建议卡片”（问题、证据、建议参数、预期影响），**不自动写 mix.json**；用户/AI 显式调用 apply 才生效。
- 建议必须引用客观数据（频谱/响度/动态 + 数值），禁止“凭感觉”给参数。
- 每次应用建议记录 `advice_applied`（来源、时间、旧值/新值），可一键回滚。

### 8.4 Skill `ams-混音质检`（随插件分发）

1. 读工程与 mix.json，确认轨道角色齐全（至少人声+伴奏）；缺失则提示先补。
2. 量响度：集成 LUFS、真峰值、短时曲线；与目标预设对比。
3. 检查关键风险：削波、DC 偏移、单声道人声、负延迟对轨、和声相位。
5. 输出质检报告（表：项目/实测/阈值/结论/建议），不达标给 1–3 条可执行建议。
## 9. 错误处理/降级/性能指标

| 类别 | 典型错误 | 统一策略 |
|---|---|---|
| 输入类 | 解码失败、采样率异常、0 时长、>2 声道 | 渲染前预检；MIX_E_002 + 转码建议 |
| 资源类 | 磁盘不足、内存超限、CPU 满载 | 预检 + 排队 + 流式块处理；MIX_E_005 |
| 并发类 | revision 冲突、重复提交、同工程并行 | 乐观锁 + 幂等键 + 工程级串行；MIX_E_004 |
| 组件类 | ffmpeg/GPL 组件缺失或版本不符 | 启动前健康检查；MIX_E_006 引导安装 |

| 缺失/异常 | 降级行为 | 用户可见 |
|---|---|---|
| pedalboard 未安装 | 强制 builtin 引擎并在 render.json 标注降级 | 提示可选组件未安装 |
| matchering 未安装 | 参考母带不可用（P1 可切“频谱+响度”近似） | 按钮禁用 + 安装指引 |
| ffmpeg 缺失/损坏 | 无法解码/编码，service 健康检查失败 | 顶部红条 + 启动器修复入口 |

| 性能指标 | 目标（i9-13900HX / RTX 4080 Laptop） | 测量方式 |
|---|---|---|
| 导入 10 min 48k 立体声 | ≤ 5 s（解码+峰值） | 阶段计时 p50/p95 |
| 首屏波形 / 起播 | ≤ 2 s / ≤ 300 ms | 前端 Performance API |
| 渲染 5 min × 4 轨（builtin） | ≤ 15 s | Job 耗时 |
| 母带（限幅+响度）5 min | ≤ 5 s | 阶段耗时 |

- 监控：阶段耗时、内存峰值、ffmpeg 子进程数写入 render.json；CPU 队列 >4 时降低并发并提示。

## 10. 安全/许可/合规

| 组件 | 许可 | 可否随包分发 | 义务/备注 |
|---|---|---|---|
| numpy/scipy/soundfile | BSD-3 | ✅ | 保留版权与许可文本 |
| pyloudnorm | MIT | ✅ | 保留声明 |
| ffmpeg（LGPL 构建） | LGPL-2.1+ | ✅ | 附源码/构建脚本入口与许可文本 |
| libmp3lame | LGPL-2.1 | ✅ | 专利已过期；随 ffmpeg 构建说明 |

- GPL 合规：可选组件独立目录/版本/安装；关于页列组件、版本、许可、源码 URL；首次启用需确认；渲染配置记录引擎类型；发版跑依赖许可扫描（白名单）。

- 文件与进程安全：路径白名单（仅 AMS_HOME/projects 与用户显式目录，禁止 `..` 穿越）；子进程显式 argv/env、可杀进程树、不继承凭据；临时文件成功即清理，失败保留 24 h。
