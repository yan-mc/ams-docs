## 0. 摘要（先看结论）

### 0.1 一句话

**Kernel = fork 自 MIT 开源的 DeepSeek Harness（DSH）桌面应用，只改"品牌/构建/裁剪/组合/壳级契约"，不含任何音乐业务代码；音乐能力全部以 profile 插件（Host+Client）与本地 Python 服务存在，由启动器安装、更新与监管。**

### 0.2 关键结论

| # | 结论 | 依据/说明 |
|---|---|---|
| 1 | fork 而不是依赖官方安装 | 产品要控制品牌、默认组合、隐私（关遥测）、更新链路与体积；官方 DSH 是 developer preview，不能假设用户机器上已有且版本合适。见 §1、§4 |
| 2 | 最小 diff 可行 | DSH 的 profile/bundle/patch 机制允许"不改源码加业务"；需改的只有品牌（壳/安装器）、构建（签名/产物）、裁剪（Office/Python 等）、组合（music profile 模板 + 内核级 patch 层）、壳级契约（启动器控制面）。文件级清单见附录 A |
| 3 | 业务代码 0 行进 ASAR | 所有 @ams 插件放在 profile（AMS_HOME/profiles/music/node_modules），内核只放"DSH 运行时 + 产品 patch + 启动器控制面"；插件由启动器按组件独立安装/更新（与 00 第 5、11 节一致） |
| 4 | 内核更新由启动器负责 | 关闭 DSH 内置 electron-updater 与强制更新策略；内核以 zip 整包分发，启动器负责下载/校验/快照/切换/健康检查/回滚。避免双更新链与官方域名依赖 |
| 5 | 默认组合 = dsh-base + dsh-web-app + @ams/music-bundle + 内核级 product.patch.yml | product.patch 层优先级最高（--patch overlay），负责关遥测/禁危险行/设默认值；music-bundle 负责插入音乐插件行 |
| 6 | 隐私默认值必须在"内核层"强制 | 即使 profile 插件尚未安装，product.patch 也要关闭 session-log-deepseek / session-telemetry-otel / product analytics 与账号登录；详见 §5.4 与 §12 |
| 7 | 体积可裁剪到约 620–650 MB 安装、内核包约 250–320 MB | 移除 LibreOffice 引擎（约 182–191 MB）、Python 运行时（146 MB）、inspector（23.5 MB）、documentpreview（14.7 MB）、plugin-market（5.6 MB）、cot-translation（5.5 MB）、sherpa（22.4 MB）等；见 §5.3 |
| 8 | 与上游同步是长期成本 | 上游 0.2.1-rc.2（2026-10-17）、近两月 6 个升级指南版本；采用"钉版本 + 双周同步 + 冲突优先保留上游结构 + 品牌/裁剪集中目录"策略；见 §4.4、§14 |

## 1. 目标与非目标

### 1.1 定位

Kernel 是 AMS 的"**大脑 + 壳**"：

- 一个 Windows x64 的 Electron 桌面应用（独立安装/独立进程），内置与官方版本精确对应的 DSH 运行时；
- 提供 Agent 会话、工具、Skills、权限/审批、任务（jobs）、设置、页面槽位等 DSH 能力；
- 通过 profile 组合出"音乐工作站"的默认界面（整页、导航、设置、任务中心、工具卡片）；
- 通过本地 HTTP 调用 ams-gateway，把 AI/页面动作映射为统一的 Job；
- 对启动器暴露进程级控制面（启动参数、健康检查、优雅退出、版本注入、RPC 通道）。

### 1.2 目标

| ID | 目标 | 验收方式 |
|---|---|---|
| G1 | 用户安装后无需系统 Python/Node/CUDA 即可启动（AI 能力只需用户自己的 DeepSeek Key） | 干净 Win10/11 VM 安装启动 |
| G2 | 不依赖用户已安装的 DSH；不读写用户家目录下的 DeepSeek Harness 残留数据（默认） | 安装/运行后检查无其它 DSH 数据写入；DSH_HOME 指向 AMS_HOME |
| G3 | 默认组合打开即"音乐工作站"：首页/任务/各功能页/设置齐全 | §15 A3/A4 验收 |
| G4 | 所有耗时操作通过 Gateway Job，AI 与页面共享同一任务模型 | §8、§15 A6 |
| G5 | 默认零遥测、零自动上传；用户 Key 只存本地 | §12、§15 A9 |
| G6 | 内核可被启动器独立安装/更新/回滚；更新可选不阻塞 | §10、§15 A11 |
| G7 | 与上游 DSH 保持可同步（最小 diff），升级上游有固定流程 | §4、§15 A12 |

### 1.3 非目标

| # | 非目标 | 说明 |
|---|---|---|
| N1 | 不重写 DSH UI 外壳/不做完全自有前端 | 保留 DSH AppFrame（聊天 + 侧栏 + 右栏）；只加整页与 slot 贡献。要做"完全自有界面"需走 SDK/自研前端，见 04_DSH架构 报告 |
| N2 | 不把训练/推理/音频 I/O 放进 Node/Electron 进程 | 全部在本地 Python 服务（Gateway 拉起），Kernel 只做编排与展示 |
| N3 | 不分发任何音源/模型权重 | 00 第 1/6 节；只做导入/校验/管理/转换 |
| N4 | 不替代启动器做环境/组件/驱动安装 | 提权与系统级操作只在启动器（00 第 3、12 节） |
| N5 | 首发不做 macOS/Linux、不做多用户/云同步/协作 | 00 第 1 节 |
| N6 | 不在首版做内核差分更新、插件热更新到"无需重启" | P1/P2 再评估；Electron 客户端插件 HMR 仅 Web 传输可用 |
| N7 | 不提供任意 shell/终端给 AI（默认） | 降风险；仅保留受控工具与诊断工具，见 §8.4 |

## 3. 总体架构与职责边界

### 3.1 在 00 架构中的位置

~~~text
AMS Launcher（Tauri2）  ──启动/健康检查/组件/更新/诊断──►  Kernel（本册：Electron + fork DSH）
        │ 本地 RPC（token）                                   │
        ▼                                                     │ HTTP（127.0.0.1 + token）
AMS Gateway（Python FastAPI，唯一任务/服务/产物入口）◄──────────┘（Host 插件 @ams/plugin-core）
        │ 拉起/监管（GPU 锁、端口、日志、SSE）
        ▼
后端服务进程（rvc-train / rvc-infer / voice-changer / pymss / gptsovits / tts / diffsinger / mixer / evaluator …）
~~~

- 依据：00 第 3 节进程归属；本册只负责 Kernel 进程内的所有内容与 Kernel↔Launcher/Gateway 的契约。
- 【决策】Kernel 不直接 spawn Python 后端；所有后端由 Gateway 拉起（00 第 8 节"插件、页面、启动器、CLI 都只通过 Gateway HTTP API 操作，不直接拉 Python"）。
- 【决策】Kernel 的 Host 插件可以用 ctx.subprocess 做"受控辅助进程"（如 ffprobe 探测、诊断采集），但不承载推理服务。

### 3.2 Kernel 内部分层

~~~text
Electron 壳（apps/desktop 改造）
├─ 主进程：窗口/菜单/托盘/单实例/崩溃恢复/AMS 控制面（新增）
├─ Host 子进程（Electron Node 模式，apps/desktop-host 改造）
│   └─ DSH 运行时（fork，app.asar/dsh，含全部 @deepseek-ai/dsh-* 包）
│        └─ profile：AMS_HOME/profiles/music
│             ├─ bundles：dsh-base → dsh-web-app → @ams/music-bundle（launcher 安装）
│             └─ patch：用户层 → home 层 → 内核 product.patch.yml（顺序见 §5.5）
└─ 渲染进程：DSH Web 客户端（dsh.client 插件由 profile 提供）
     └─ @ams/plugin-*（Client 半侧）：整页/导航/设置/工具卡片
~~~

## 4. Fork 策略与最小 diff

### 4.1 基线选择

| 项 | 值 | 说明/证据 |
|---|---|---|
| 上游仓库 | https://github.com/deepseek-ai/deepseek-harness | 【事实】MIT；默认分支 master；文档站 https://deepseek-harness.github.io/deepseek-harness/ |
| 基线 tag | dsh-v0.2.1-rc.2（2026-10-17，prerelease） | 【事实】GitHub Releases 最新；本机 Desktop 0.2.1-rc.2 同版本 |
| 对应 commit | 332895e0f7c9d4dbfb29729f5eb367fa263ff986 | 【事实】本机 app.asar 构建记录（unpacked/package.json:25） |
| 运行时组件 | Electron 44.7.0；内置 Node 24.21.0；pnpm 11.28.5；Python 3.12.14（计划裁剪） | 【事实】安装目录 version 文件与 runtime/versions.json |
| 包数量 | 304 个 @deepseek-ai 包 | 【事实】desktop-runtime.json sharedPackages |
| 许可 | MIT（代码）；第三方见 THIRD_PARTY_NOTICES（LibreOffice MPL-2.0、sharp/sherpa Apache-2.0 等） | 【事实】LICENSE、THIRD_PARTY_NOTICES.md |
| 上游节奏 | developer preview，破坏性变更明示；近两月 6 个 upgrade-guide 版本、近 3 天 5 个 prerelease | 【事实】README:8-14、docs/upgrade-guide |

**【决策】基线锁定 dsh-v0.2.1-rc.2**，理由：

1. 与本机已逆向验证的安装一致（我们已有完整解包与证据）；
2. 上游 rc 已带我们要用到的全部机制（profile/bundle/patch、jobs、subprocess、client slots、dsh.client、内置 pnpm、Desktop 命令运行时）；
3. 避免在 alpha 之间反复重定基线。

**【决策】重定基线策略**：

- 开发期（M0–M2）：每 2 周评估一次上游；仅当出现"安全修复/我们依赖的破坏性 bug 修复"时整体升级；
- Beta 封板前：若上游出现 stable（0.2.x stable 或 0.3.0），做一次整体重定基线（一次性成本预估 5–8 人日，见 §13）；
- GA 后：维护分支只 cherry-pick 安全修复；季度评估一次 minor 升级。若上游破坏性变更过大，允许长期停在上一个稳定基线（风险见 §14 R1）。

### 4.3 最小 diff 原则（约束）

**【决策】只允许以下 5 类改动**，其余一律以 profile/插件/启动器实现：

| 类别 | 允许内容 | 典型文件 |
|---|---|---|
| A. 品牌 | 产品名/appId/图标/协议/欢迎文案/菜单/关于/安装器文案/托盘 | apps/desktop/src/locale.ts、apps/desktop/src/main.ts、apps/desktop/resources/*、apps/desktop/scripts/electron-builder-config.mjs、installer/* |
| B. 构建 | electron-builder 配置、签名、产物命名、CI、版本/upstream.json | apps/desktop/scripts/*、.github/workflows/ams-*.yml、package.json |
| C. 裁剪 | 可选组件（Office/LibreOffice/Python/浏览器/实验功能）从运行时或 profile 移除（env 开关驱动） | apps/desktop/scripts/prepare-dsh.ts、prepare-primary-runtime.ts、runtime-file-policy.ts、apps/desktop-host/src/* |
| D. 组合 | music profile 模板、内核级 product.patch.yml、插件 payload 清单 | packages/boot/app-boot/src/profile.ts、ams/product/*、vendor/ams/* |
| E. 壳级契约 | AMS 控制面、profile 名 music、patchFiles 注入、CLI reserved profile、默认 home/workspace | apps/desktop/src/ams-control.ts（新增）、apps/desktop/src/paths.ts、apps/desktop-host/src/index.ts、apps/cli/src/{args,plugin}.ts、packages/util/home-paths |

**禁止**：修改 Agent 循环/工具流水线/会话格式/slot 语义/权限模型/上游 bundle 的 cordis.patch.yml 内容；禁止把业务逻辑写进 @deepseek-ai 包；禁止在 ASAR 内放 @ams 插件（可更新性要求，见 §6.1）。

### 4.4 上游同步流程

~~~text
每周一（CI 定时）        每两周（人工）
+--------------+        +--------------------------------------------+
| 检查 upstream |        | dev 合并 upstream/master（--no-ff 保留历史）|
| 新 tag/commit |------->| 解决冲突 -> 重放 ams/* 改动 -> 本地门禁测试 |
+--------------+        +----------------------+---------------------+
                                               |
                                               v
                        产品断言门禁（必须全绿）：
                        1) profile 组合快照（music 行/禁用行）
                        2) 无遥测/无账号/无内置更新器断言
                        3) 构建 + 未签名安装包冒烟
                        4) 启动器契约测试（控制面）
                                               |
                                               v
                              PR 合入 dev -> 打 kernel 版本候选
~~~

冲突处理规则：

| 冲突类型 | 处理 |
|---|---|
| 品牌字符串（locale/main/欢迎页） | 以 AMS 品牌映射为准；尽量把文案集中到 ams/brand/brand.json + 构建时注入，减少逐条手改（P1 改进） |
| electron-builder/构建脚本 | 我们的改动以"新增 env 开关行 + 独立函数"形式存在，冲突时优先保留上游代码结构，把 AMS 逻辑移到 ams/ 下独立模块并调用 |
| profile 模板/app-boot 小改 | 冲突概率低；若上游重构模板机制，改为在 desktop-host 用 fromDefaultProfile+patch 实现（兜底方案） |
| CLI reserved profile | 上游若新增 profile 保留逻辑，跟随其模式把 desktop->music 映射重构；必要时用 --profile music 单独 wrapper |
| 大范围重构（如桌面打包重写） | 启用"重放 diff"流程：git format-patch origin/main..upstream-merge-base -- ams/ apps/desktop... 逐条重放；本册附录 A 的清单即重放清单 |

**【决策】同步频次**：Beta 前每两周；发版前 2 周冻结（只 cherry-pick 安全修复）；GA 后每月。

### 4.5 版本号与上游对应关系

### 5.4 隐私 / 遥测 / 账号 / 内置更新器的关闭（内核层强制）

【事实】上游默认行为（必须关闭）：

- dsh-base 默认挂 session-log-deepseek：随 DeepSeek 请求上传未接受的日志事件（单次上限 8 MiB，见 04_DSH架构 报告与 sdk-minimal README）；
- session-telemetry-otel：默认 FEEDBACK_ONLY，可用 DSH_TELEMETRY_DISABLED 关闭；
- Desktop 产品埋点（host-product-telemetry-otel / product-analytics）；
- deepseek-account-platform：官方账号登录链路；
- electron-updater：官方更新 feed（download.deepseek.com）+ 强制更新策略（policy origin harness.deepseek.com）。

【决策】四重关闭（任何一重生效即可，测试覆盖）：

| 层 | 手段 |
|---|---|
| 组合层 | product.patch.yml 对上述行 disabled: true；删除/隐藏账号设置页与欢迎页登录区 |
| 配置层 | 对可配置行写 enabled: false / DSH_TELEMETRY_DISABLED；session-log-deepseek.enabled: false |
| 构建层 | 删除 package.json 的 dshMandatoryUpdatePolicy；electron-builder 强制 publish: null（不生成 app-update.yml，内置 updater 的 enabled() 自动为假）；移除检查更新菜单项 |
| 环境层 | Kernel 启动时注入 DSH_TELEMETRY_DISABLED=1、DO_NOT_TRACK=1（若有消费者） |

【决策】出站网络白名单（产品承诺"无自动上传"）：

| 允许 | 触发 |
|---|---|
| 用户配置的模型端点（DeepSeek/自定义 baseURL） | 仅会话请求（用户/Agent 行为） |
| GitHub Releases / 自建更新 feed / 镜像 | 仅启动器更新检查/下载（内核自身不主动联网） |
| 模型/组件下载 URL | 仅用户在启动器/页面显式点击 |
| 用户显式开启的 web 搜索/抓取工具 | 默认禁用，开发/高级模式可开 |

【决策】产品断言测试（CI 必跑，见 §11.4）：静态扫描 profile 组合 + 运行时出口探测（无遥测/账号请求）。

#### 5.5.5 首次启动与 profile 初始化时序

~~~text
启动器: 安装/校验组件(内核+插件+服务) -> 写 AMS_HOME 目录 -> 启动 Gateway -> 健康检查
   -> 启动 Kernel（env: AMS_* / DSH_HOME）
Kernel 壳:
   1) 解析 AMS_HOME、DSH_HOME
   2) DesktopProjectManager.applyRelease()（profile 目录、patch 模板、锁）
   3) 启动 Host 子进程（cwd=AMS_HOME/projects；product.patch 作为 --patch）
   4) Host: loadProfileDirectory(music) -> runProfile（L1~L6 组合）-> ready URL 上报壳
   5) 壳: 写 kernel.json（控制面端口/token/版本/状态）-> 启动控制面 -> 显示主窗口
   6) 若 profile 无 @ams/music-bundle（首次/损坏）: Host 跳过该 bundle 并告警；
      壳在 kernel.json 标记 profileReady=false；首页显示"等待组件安装"卡片；
      启动器收到后安装插件 payload -> 重启 Kernel（或调用内核"重载 profile"）
~~~

- 【决策】"插件 payload 由启动器安装，且启动器必须先于 Kernel 完成首次安装"；内核允许在缺插件时启动（可诊断/可修复），但不呈现不完整工作台。
- 【待定】内核内"重载 profile"（不重启进程）能力：DSH 有 HMR 但 Electron 客户端插件不走 SSE；首版用重启，P1 评估。

| runtime/kernel.json | Kernel（壳） | 启动器共享状态（§9.3） | 写 | 非备份（易重建） |
| runtime/ports.json、runtime/gateway.token | 启动器/Gateway | 端口与 token | 内核只读 | 非备份 |
| config/ui-state.json（P1） | Kernel 插件 | 上次页面/项目/窗口状态 | 读写 | 可清理 |
| skills/ | 启动器同步 + 用户 | AMS skills（ams-*） | 内核只读（skill-filesystem watch） | 可重建 |
| logs/kernel/ | Kernel | 运行日志/崩溃报告 | 写 | 按天滚动，保留 14 天 |
| logs/launcher/、logs/gateway/、logs/services/ | 启动器/Gateway/服务 | 各自日志 | 内核只读（诊断包收集） | 各自策略 |
| sessions/（DSH 数据） | Kernel（DSH） | 会话日志/投影 | 读写（DSH 管理） | 用户删除；格式升级走 DSH 迁移 |
| .credentials.yaml | Kernel（DSH 凭据） | 用户 API Key 引用 | 仅设置页写入 | 用户删除；不进备份/诊断包 |
| projects/ | 用户 + Gateway | 工程目录（project.json/stems/...） | 内核只读（页面经 Gateway 操作） | 用户备份 |
| voices/、tts_voices/、svs_voicebanks/、models/、cache/、updates/、backups/ | 用户/启动器/Gateway | 见 00 第 4 节 | 内核只读（音色库展示经 Host 服务扫描） | 各自策略 |

数据模型要点：

- 单一事实来源：任务（Job）在 Gateway SQLite；会话在 DSH session log；音源在文件系统 voices/<name>/<name>.pth(+index)（00 第 6 节）；工程元数据在 projects/<id>/project.json。Kernel 只做展示与编排，不复制权威数据。
- 配置分层：DSH settings（模型/权限/插件配置）存于 profile 凭证/设置文档；AMS 产品级设置（路径/并发/默认通道）通过插件 Config 自动表单写入 profile patch；启动器设置存 config/state.db（01 分册）。
- 内核不写 home patch（L5 层）：避免与用户/支持手工修改冲突；内核权威层只走 resources/ams/product.patch.yml（L6，随内核版本更新）。
- 删除策略：内核只承诺"清除日志/缓存/会话（用户确认）"；工程/音源/模型的删除属于 Gateway/启动器能力。
- 备份：更新前快照（§10.8）只覆盖 profile 与配置，不备份用户资产（00 第 13 节）。

## 6. 插件系统落地

### 6.1 决策：业务插件全部在 profile，内核不含 @ams 代码

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 插件打进内核 ASAR（随内核版本） | 首次启动即完整；离线天然 | 插件不能独立更新（DSH 运行时解析"安装优先"，profile 同名包无法覆盖）；内核每次发版变大；ASAR 签名与热修冲突 | 不采用 |
| B. 插件放 profile（启动器安装/更新） | 与 00 第 5/11 节"插件独立版本、独立更新"一致；内核小、可回滚；开发模式灵活 | 首次启动前必须由启动器完成安装；profile 损坏需修复 | 【决策】采用 |
| C. 混合（核心插件在内核、可选在外） | 折中 | 两套更新语义，复杂 | 首版不采用 |

实现要点：

- 内核 ASAR 只含 @deepseek-ai 运行时 + 我们的 product.patch.yml + 控制面代码；
- 所有 @ams 包通过启动器安装到 %AMS_HOME%/profiles/music/node_modules；
- profile 的 dsh.profile.bundles 含 @deepseek-ai/dsh-base、@deepseek-ai/dsh-web-app、@ams/music-bundle；
- 行插件（@ams/plugin-*）作为普通依赖被 music-bundle 的行引用；运行中由 DSH 运行时解析（profile 映射）；
- 【决策】@ams/music-bundle 的 package.json 不声明运行时 dependencies（只写 peerDependencies 供文档/校验），启动器一次性安装 bundle + 全部插件 tarball，避免首次安装时访问 npm registry（离线可用）。

### 6.3 安装来源、生命周期与启用/禁用

| 来源 | spec 形式 | 校验 | 使用场景 |
|---|---|---|---|
| 官方 payload（随启动器安装包/首装组件） | 本地 tarball file:<AMS_HOME>/components/plugins/<pkg>.tgz | 启动器校验 sha256 + Ed25519 清单（ams-release） | 首次安装、离线安装 |
| 官方更新 | 同上（新版本） | 同上 + 兼容矩阵 | 稳定通道更新 |
| 市场/第三方 | 本地 tarball 或 @ams/...（需 allowlist） | sha256 + 签名/allowlist；首次使用权限提示 | P2 |
| 开发模式 | link: 本地目录 / file: tarball | 无签名（需 AMS_DEV=1 显式开启） | 插件开发/内测 |

安装/更新流程（与 00 第 11 节一致，内核侧只负责"下一次启动生效"）：

~~~text
1) 启动器下载/定位 tarball -> sha256/签名校验 -> 兼容性预检（读包 manifest engines.*）
2) 快照: 备份 profiles/music/package.json + pnpm-lock.yaml + cordis.patch.yml
3) 调内核自带 CLI（resources/runtime/cli/bin/dsh.cmd）:
   dsh plugin --profile music add file:<bundle.tgz> file:<plugin1.tgz> ...（一次性安装全部）
4) 校验 profile manifest / 依赖锁定 / 禁用状态保留
5) 重启 Kernel（P0）；健康检查通过 -> 提交；失败 -> 恢复快照并提示
~~~

- 启用/禁用：由启动器写 profile 的 cordis.patch.yml（行级 disabled 覆盖，带备份与写锁），内核启动时生效；Host 行在 HMR 可用时可能热生效，Client 行需要重启。决策：统一按"重启生效"提示，避免不一致。
- 卸载：启动器先取消选中/移除行覆盖，再 dsh plugin remove，最后可选彻底删除包文件。
- 【决策】稳定模式禁用 DSH 插件管理器（tool/UI 行 disabled）；开发者可在 AMS_DEV=1 时打开（product.patch 条件）。

### 6.4 版本与兼容（engines）

| 维度 | 声明方 | 检查点 | 失败行为 |
|---|---|---|---|
| Kernel API | 内核 AMS_KERNEL_API=1 + kernel 版本 | 插件 manifest engines.kernel / engines.ams | 启动器安装前阻止；内核启动时告警并禁用不兼容行 |
| DSH API | 内核写入 upstream.json（dsh 版本） | 插件 engines.dsh（DSH 自身也会检查） | 同上 |
| Gateway API | 启动器/内核读 Gateway /health 版本 | 插件 ams.services 版本约束 | 插件行静默不可用 + 任务创建时报错 code |
| 插件间 | 依赖插件版本（peer） | 安装/启动 | 启动器预检并提示升级顺序 |
| 启动器 | Kernel 声明 minLauncherVersion | 启动器启动前/更新前 | 阻止启动并提示升级启动器 |

- 【决策】Kernel 版本语义：0.x 期间 minor 允许破坏（插件同步升级）；1.0 后遵守 SemVer。
- 【决策】兼容矩阵文件在 ams-release：compat/kernel-<ver>.json 列出"内核版本 -> 允许的插件版本范围/服务版本范围"，启动器与内核都可读取。

### 6.5 签名 / allowlist / 安全

| 对象 | 校验 | 存储 |
|---|---|---|
| 内核包 | sha256 + Ed25519 清单签名 + Windows Authenticode | ams-release / 启动器 |
| 官方插件 payload | sha256 + Ed25519 清单签名（随启动器公钥） | ams-release |
| 第三方/开发插件 | sha256 + allowlist（AMS_HOME/config/plugins.allowlist.json）；首次安装弹权限说明 | 本地 |
| 插件权限声明 | 包 manifest ams.permissions（network/files/process/gpu/audio） | 启动器展示/用户确认 |
| 插件运行 | Host 插件在宿主进程内、不受工作区沙箱限制（DSH 事实） | 因此只允许签名/allowlist 插件；开发模式显式开启 |

- 【风险】Host 插件无沙箱：恶意插件可读 Key/文件/网络。策略：默认仅允许官方签名插件；第三方需用户显式"允许未签名插件（开发者模式）"；所有插件安装记录审计日志。
- 【决策】内核不提供从任意 URL 直接安装插件的能力（避免供应链）；安装入口只允许"签名的 payload/本地文件（用户显式选择）"。

| 波形编辑 | WebAudio（decode/preview）+ Canvas 分层（波形/选区/包络/播放头）；编辑操作只存操作序列，渲染由 Gateway 执行 | peaks 预计算（ffmpeg/服务）分块加载；>30 min 降采样多级；requestAnimationFrame | 本地 SPA iframe（P2） |
| piano-roll（填词） | Canvas/SVG 虚拟滚动；音符/歌词/音素分层；参考 04 分册 | 可视区渲染；编辑历史 undo；增量重渲染 | 独立 SPA iframe |
| 混音台 | WebAudio 多轨播放（预览）+ Canvas 电平/频谱；离线渲染/导出交 Gateway | 只缓存短片段；大工程只读 peaks；导出异步 Job | 专业场景交外部 DAW（导出 stems） |
| 训练曲线/评测 | Canvas/SVG 轻量图表 | 采样点降采样 | 表格/图片 |
| 视频/大文档预览 | 不内嵌 | — | 打开系统应用 |

【决策】首版编辑器用"Client 插件内 React + Canvas/WebAudio"实现；不把复杂编辑器做成 iframe 主路径，iframe 仅作为兜底（DSH sidebar browser 在 Web=iframe、Desktop=webview，loopback 允许；但跨源隔离，状态需 postMessage）。

### 7.5 性能预算（首版目标）

| 指标 | 目标 | 备注 |
|---|---|---|
| Kernel 冷启动（到主界面可交互） | ≤ 8 s（SSD） | 含 Host 启动、profile 组合、首屏 |
| 页面切换（已加载） | ≤ 300 ms | panel 切换不重建会话 |
| 任务列表 1000 条 | ≤ 200 ms 首屏 | 虚拟滚动 + 分页 |

| SSE 进度延迟 | ≤ 1 s | Gateway 事件 -> 页面 |
| 内核安装体积 | ≤ 650 MB | 见 §5.3 |
| 空闲内存（Kernel 进程组） | ≤ 900 MB | Electron + Host；继续优化 |

### 7.6 交互与视觉一致性

- 遵循 DSH 现有 UI 语义（暗色/亮色主题、slot 布局、快捷键、命令面板）；AMS 页面使用同一主题 token，不引入新组件库。
- 文案全部中文（可留英文 fallback）；错误信息 = 用户可行动作（"显存不足：请关闭 xx 或降低 batch"，而非堆栈）。

### 8.3 Job 镜像与长任务（核心机制）

【决策】Gateway 是唯一任务真相；Kernel 把 Gateway Job 镜像为 DSH job，以获得 DSH 的进度/通知/取消体验：

| Gateway 事件/状态 | DSH 镜像动作 |
|---|---|
| POST /jobs 成功 | Host 注册 DSH job（kind=music，owner=sessionId，label=任务名），记录 job_id 映射 |
| SSE progress | DSH job updateProgress（百分比 + 阶段），并把关键日志 append 到 job output |
| SSE log | append 到 log 通道（模型可见输出做截断/摘要） |
| succeeded/failed/cancelled | DSH job 结算（含 detail/error code），触发会话内完成通知 |
| 用户 job_kill | 调用 Gateway cancel（杀进程树），等待结算；超时标记失败 |
| Kernel 重启 | core 插件启动时 GET /jobs?status=running，重建镜像（标记"恢复的任务"）；模型只在当前会话任务上收到通知 |
| Gateway 重启 | 网关自身持久化 SQLite；Kernel SSE 重连 + 状态对账；断线期间任务继续 |

- 【待定】镜像粒度：仅镜像"AI 创建的 job"还是"AI + 页面创建的 job"？建议镜像当前会话可见的、与当前项目相关的 job，避免任务中心噪音；页面直接读 Gateway 列表。
- 【风险】双重 job 状态不一致：以 Gateway 为权威，DSH 侧只做展示与通知；对账逻辑在启动时与每 30 s 校验一次（孤儿镜像自动清理）。

### 8.4 审批/权限策略

| 操作 | 默认策略 | 说明 |
|---|---|---|
| 创建训练/分离/换声/合成/导出任务 | 允许（不弹审批） | 任务本身可取消；写输出在项目目录 |
| 训练启动（耗时长/占 GPU） | 需确认（工具内一次确认或 DSH 审批卡） | 显示预计时间/显存；用户可"本次允许/总是允许" |
| 覆盖已有产物/音色/模型 | 需确认 | 目标已存在时 |
| 删除工程/音色/数据集 | 需确认（二次） | 可回收站策略 P1 |
| 组件安装/修复（启动器 RPC） | 必须用户确认（启动器 UI） | 内核不直接装 |
| 任意 shell/文件写入（非 AMS 工具） | 禁止（行禁用） | 降低风险 |
| 插件安装 | 启动器确认 + 签名校验 | 开发模式例外 |
| 文件读取 | 项目/音色库/日志范围内允许 | DSH fs 工具限制在工作区；跨目录需显式选择（目录选择器） |

- 【待定】DSH 审批 API 的具体接入方式（dsh-user-approval 服务 / tools/pre-execute ask 决策）需 spike 验证；兜底方案：工具内部先返回"需要确认"卡片，用户点击后再执行。

### 8.6 提示词与上下文约定

| 段 | 内容 | 约束 |
|---|---|---|
| 身份 | "你是 AMS 音乐工作站的 AI 助手，帮助用户完成音乐制作流程" | 不透露内部实现/上游名；可说明"基于 DSH"如被问 |

- 【待定】上下文注入上限与频率需在 S1/S2 spike 后调参；避免破坏 KV cache（固定段放前、动态段放后）。

### 8.7 AI 可靠性与错误处理

| 场景 | 约定 |
|---|---|
| 模型要求不存在的工具/参数 | 工具错误码 E_TOOL_INVALID，返回可用参数枚举 |
| Gateway 未就绪 | E_GATEWAY_DOWN，提示"启动器正在启动服务/请重试"；不自动重试超过 2 次 |
| 任务失败 | 返回 { code, message, log_tail, suggestion }；引导"诊断"入口 |
| 进度谎报 | 系统提示禁止；UI 只显示 Gateway 真实进度 |
| 用户中断 | 取消任务 -> 状态 cancelled；模型收到结算事件 |
| 长时间无响应 | 工具超时（默认 30 s，训练类返回 job id 立即成功）；长任务不阻塞模型 |
| 显存不足 | 错误码 E_GPU_OOM + 建议（降低 batch/关闭其他任务/排队） |
| 重复任务 | 工具参数含 project_id + 输入 hash；重复提交返回已有 job（幂等键） |
| 模型幻觉结果 | 工具结果与 Gateway 产物为唯一事实；最终展示必须引用 artifact id |

### 8.8 模型与配额

- 默认 deepseek-flash（低成本、快）；训练/长文场景可由用户切换 deepseek-pro（按用户 Key 计费，产品不代付）。
- reasoning effort 默认 medium（可在设置调整）；上下文压缩用 DSH compaction；单会话 token 预算与提示由 DSH token-meter 展示。
- 【决策】不内置任何模型代理/共享 Key；不采集用户 token 用量到远端（0 遥测）；本地记录仅用于 UI 展示。

## 9. 与 Gateway / 启动器 / 服务的集成契约

### 9.1 进程启动顺序与就绪语义

~~~text
Launcher                            Kernel（Electron）                     Gateway
  |                                   |                                      |
  |-- 1. 启动 Gateway --------------->|                                      |
  |-- 2. GET /health（重试 <=60s）----|------------------------------------->|
  |<-- 3. {status:ok,version,...} ----|                                      |
  |-- 4. 启动 Kernel（env 见 9.2）---->|                                      |
  |                                   |-- 5. Host 启动 -> profile 组合       |
  |                                   |-- 6. 壳读 ready URL -> 写 kernel.json|
  |                                   |-- 7. 控制面监听 127.0.0.1:port       |
  |<-- 8. 轮询 kernel.json/健康检查 ---|                                      |
  |-- 9. GET /ams/healthz ----------->|                                      |
  |<-- 10. {status:ready, gateway:ok} |                                      |
  |-- 11. 显示/聚焦窗口（启动完成）    |                                      |
~~~

- 超时：Gateway 60 s；Kernel 首启 90 s（首次 profile 初始化 + 插件扫描）；超时后启动器展示诊断（日志尾部 + 重试/修复按钮）。
- 【决策】启动器不直接操作 Kernel 窗口（不注入 UI）；只通过控制面与进程信号。

### 9.2 启动参数与环境变量

| 变量 | 必填 | 示例 | 用途 |
|---|---|---|---|
| AMS_HOME | 是 | C:/Users/x/AppData/Local/AMS | 数据根 |
| DSH_HOME | 是（由壳设置） | 与 AMS_HOME 相同 | DSH 数据根；profile 在 profiles/music |
| AMS_GATEWAY_URL | 是 | http://127.0.0.1:51234/api/v1 | Gateway API 基址 |
| AMS_GATEWAY_TOKEN | 是 | 64 hex | Bearer token |
| AMS_LAUNCHER_RPC | 是 | http://127.0.0.1:51235 | 启动器本地 RPC 基址 |
| AMS_LAUNCHER_TOKEN | 是 | 64 hex | RPC token |
| AMS_SKILLS_DIR | 是 | %AMS_HOME%/skills | Skills 根 |
| AMS_PROJECTS_DIR | 是 | %AMS_HOME%/projects | 默认工作区根 |
| AMS_LOG_DIR | 是 | %AMS_HOME%/logs/kernel | 日志 |
| AMS_KERNEL_CONTROL_TOKEN | 是 | 64 hex | 控制面鉴权（由启动器生成并注入） |
| AMS_KERNEL_CONTROL_PORT | 否 | 0（默认动态） | 固定端口调试用 |
| AMS_DEV | 否 | 1 | 开发模式（启用插件管理器等） |
| AMS_CHANNEL | 是 | beta / stable | 更新通道（只读展示） |
| AMS_LOCALE | 否 | zh-CN | 默认语言 |
| AMS_LAUNCHER_VERSION | 是 | 1.4.2 | 版本注入（展示/兼容检查） |

- 参数传递：全部通过环境变量（启动器 spawn 时注入）；命令行只保留上游既有参数（调试用 --profile web 等）。
- 【决策】token 只放环境变量与内存，不写日志/不落盘（除 runtime 目录受 ACL 保护的 kernel.json；见 9.3）。

### 9.3 kernel.json（启动器与内核的共享状态文件）

位置：%AMS_HOME%/runtime/kernel.json（原子写：临时文件 + rename；仅当前用户可读）。

~~~json
{
  "schema": "ams-kernel/status/1",
  "pid": 12345,
  "startedAt": "2026-10-19T20:00:00+08:00",
  "kernelVersion": "0.1.0-beta.1",
  "kernelApi": 1,
  "upstreamDshVersion": "0.2.1-rc.2",
  "profile": "music",
  "profileReady": true,
  "control": { "host": "127.0.0.1", "port": 51236, "token": "<64hex>" },
  "state": "ready",
  "hostReady": true,
  "windowVisible": true,
  "gateway": { "url": "http://127.0.0.1:51234/api/v1", "ok": true, "version": "1.0.0" },
  "plugins": { "installed": 15, "enabled": 15, "incompatible": [] },
  "lastError": null
}
~~~

- 字段更新时机：启动中（state=starting）-> Host ready（hostReady=true）-> gateway 探测（gateway.ok）-> 控制面就绪（state=ready）。
- 启动器以"文件 mtime + GET /ams/healthz"双通道判断，避免文件竞争。

### 9.4 内核控制面（Launcher -> Kernel）

| 方法 | 路径 | 作用 | 返回 |
|---|---|---|---|
| GET | /ams/healthz | 健康检查 | { status, state, hostReady, gatewayOk, uptimeSec, version } |
| GET | /ams/version | 版本/兼容矩阵（kernel/kernelApi/dsh/gateway） | JSON |
| GET | /ams/status | 同 kernel.json 的完整状态（进程内实时） | JSON |
| POST | /ams/quit | 优雅退出：先关 Host 再退 Electron；带 reason | { accepted: true } |
| POST | /ams/focus | 显示并聚焦主窗口 | { ok: true } |
| POST | /ams/open | 打开页面/工程（P1，deeplink 用）：{ page, projectId? } | { ok: true } |
| POST | /ams/diagnostics | 生成诊断包（日志/版本/profile/最近错误；不含 Key） | { path, bytes } |
| POST | /ams/reload-profile | 重新加载 profile（P1；首版用重启替代） | { accepted: boolean } |

- 鉴权：Header Authorization: Bearer <AMS_KERNEL_CONTROL_TOKEN>；token 由启动器生成，通过 env 注入；内核只监听 127.0.0.1。
- 错误统一：{ ok:false, error:{ code, message } }。
- 短超时：healthz 2 s；其它 10 s；diagnostics 60 s。

### 9.5 启动器 RPC（Kernel -> Launcher）

| 方法 | 路径 | 作用 | 请求要点 | 用户确认 |
|---|---|---|---|---|
| GET | /rpc/health | 启动器存活/版本 | — | 否 |
| GET | /rpc/components | 组件清单与状态（内核/插件/服务/工具/模型） | — | 否 |
| POST | /rpc/components/install | 请求安装/修复组件 | { componentId, version?, reason, requestId } | 是（启动器 UI） |
| GET | /rpc/components/status | 查询安装进度 | { requestId } | 否 |
| GET | /rpc/updates/check | 检查更新 | { channel } | 否 |
| POST | /rpc/updates/apply | 应用某个组件更新 | { componentId, version, requestId } | 是（启动器 UI） |
| POST | /rpc/diagnostics/collect | 请求启动器侧诊断（环境/驱动/服务） | { requestId, includeServices } | 否 |
| POST | /rpc/open-dir | 打开目录（日志/音色库/工程/模型） | { kind, path? } | 否（受限白名单） |
| POST | /rpc/restart-service | 重启某个后端服务 | { serviceId } | 是 |
| POST | /rpc/shell/open-url | 用系统浏览器打开白名单 URL | { url } | 否 |

- 幂等：所有 POST 带 requestId（UUID）；启动器按 requestId 去重并返回同一结果。
- 超时：内核侧 5 s（install/update 返回"已受理 + requestId"，进度用轮询或启动器 SSE）。
- 【决策】内核不直接调用启动器的内部文件/命令；所有系统级操作都走"请求-确认-执行"。

### 9.6 健康状态机（Kernel）

~~~text
starting -> host-booting -> host-ready -> gateway-checking -> degraded/ready
                                                   |-> failed（不可恢复：Host 崩溃/端口占用/profile 损坏）
ready --(gateway down)--> degraded --(gateway ok)--> ready
ready --(plugin crash)--> degraded（插件可选）
failed -> 启动器展示恢复选项（重试/禁用第三方插件/备份 profile）
~~~

- 启动器展示：starting/host-booting 显示"启动中"；degraded 显示黄色原因清单（如"网关未启动"）；failed 显示诊断与恢复按钮（与 00 第 11 节更新/回滚衔接）。

### 9.7 退出、重启与崩溃恢复

| 场景 | 行为 |
|---|---|
| 用户关闭窗口 | 最小化到托盘（00/上游行为）；任务继续；启动器保持 Gateway 运行 |
| 用户"退出" | DSH 原生退出确认（有运行任务时提示）-> 壳 /ams/quit -> Host 优雅关闭（shutdown-complete）-> Electron 退出 -> 启动器按策略决定是否停 Gateway（默认保持，任务继续） |
| Kernel 崩溃 | 启动器检测退出码/健康失败 -> 收集 crash-report（%AMS_HOME%/logs/kernel）-> 尝试重启 <=2 次（指数退避）-> 仍失败则提示"修复/回滚内核" |
| Gateway 崩溃 | 启动器保活重启 Gateway；Kernel 进入 degraded，SSE 重连后恢复；任务由 Gateway SQLite 持久化 |
| 强制结束 | 启动器终止进程树（Electron + Host）；清理 profile lock；下次启动自检 |
| 升级内核 | 启动器先退出 Kernel（空闲时）-> 应用新版本 -> 启动 -> 健康检查 -> 失败回滚（§10.8） |

### 9.8 版本注入与兼容检查

- 注入：启动器把自身版本/通道通过 env 注入 Kernel；Kernel 在 kernel.json 与控制面报告 kernelVersion/kernelApi/dshVersion/gatewayVersion。
- 检查：启动器启动前读 manifest（requires.launcher/requires.kernel）与已安装插件 manifest（engines）；内核启动时由 core 插件复核插件 engines 与 Gateway /health 版本；不兼容：
  - 启动器：阻止安装/启动，给出升级建议（升级插件/内核/启动器）；
  - 内核：禁用不兼容行（可诊断），首页显示"不兼容插件"卡片；
  - 强制覆盖：仅在用户确认"我了解风险"后允许（记录审计）。

### 9.9 Gateway API（内核侧最小契约）

| 项 | 约定 |
|---|---|
| 基址 | http://127.0.0.1:<port>/api/v1（bind 127.0.0.1） |
| 鉴权 | Authorization: Bearer <64hex>；token 文件 %AMS_HOME%/runtime/gateway.token |
| 健康 | GET /health -> { status, version, services:[{id,status,version}], gpu:{...} } |
| 任务 | GET /jobs?status=&type=&project_id=&limit=&cursor=；POST /jobs {type,params,project_id?}；GET /jobs/{id}；POST /jobs/{id}/cancel；GET /jobs/{id}/events（SSE：progress/log/status/artifact）；GET /jobs/{id}/artifacts |
| 产物 | GET /artifacts/{id}/download（Range 支持，供大文件） |
| 项目/音色 | GET/POST /projects；GET /voices；POST /voices/scan；POST /voices/validate |
| 目录/文件 | GET /files?path=（受 AMS_HOME 白名单限制） |
| 错误 | { ok:false, error:{ code, message, detail? } }；常用码见 §8.7 |
| 版本 | /health 带 apiVersion（如 1）与 service versions；内核校验 >= 最低版本 |

- 超时/重试：GET 5 s；POST /jobs 10 s；SSE 长连接（心跳 15 s）；幂等键：POST /jobs 支持 client_request_id，重复返回同一 job。
- 【决策】Kernel 不直连后端服务端口；所有访问走 Gateway（00 第 8 节）。

### 9.10 安全要点（契约层）

- 所有本地端口 bind 127.0.0.1；token >=32 字节随机（启动器生成）；
- token 文件/状态文件权限：仅当前用户（Windows ACL）；
- 控制面/RPC 不使用浏览器 CORS（非浏览器客户端）；对浏览器来源拒绝；
- 日志中禁止出现 token/Key/用户音频路径（脱敏）；
- kernel.json 的 token 字段建议只给控制面用，启动器也可用；文档与诊断包中不包含。

### 10.6 内核更新包格式（AMS Kernel Package v1）

zip 结构（launcher 安装/更新用）：

~~~text
AMS-Kernel-<ver>-win-x64.zip
├─ AMS Kernel.exe              # 应用主程序（品牌化后名称）
├─ resources/                  # app.asar / app.asar.unpacked / runtime / ams/product.patch.yml
├─ ...（Electron 应用目录其余文件）
└─ kernel-package.json         # 包自描述（见下）
~~~

kernel-package.json（包内自校验；与 ams-release 清单互为印证）：

~~~json
{
  "schema": "ams-kernel/package/1",
  "kernelVersion": "0.1.0-beta.1",
  "kernelApi": 1,
  "upstream": { "tag": "dsh-v0.2.1-rc.2", "commit": "332895e0...", "dshVersion": "0.2.1-rc.2" },
  "runtime": { "electron": "44.7.0", "node": "24.21.0", "pnpm": "11.28.5" },
  "requires": { "launcher": ">=1.0.0", "gateway": ">=0.5.0" },
  "files": [{ "path": "AMS Kernel.exe", "size": 246343144, "sha256": "..." }],
  "signature": { "scheme": "ed25519", "keyId": "ams-release-1", "value": "base64..." }
}
~~~

- 校验顺序：下载 -> 校验 zip sha256（清单）-> 校验清单 Ed25519 签名 -> 解压到 staging -> 校验 kernel-package.json 文件清单 -> 兼容检查 -> 应用。
- 【决策】P0 只做全量包（约 250–320 MB）；差分（P2）用 zstd/bspatch 或"按文件差分 + 复用本地已有文件"，由启动器实现，内核只需提供完整包与文件哈希清单。

### 10.7 内核更新流程（启动器状态机）

~~~text
idle -> checking -> available/none
available -> user-confirm -> downloading（断点续传/镜像）-> verifying
 -> staging（解压/校验）-> snapshot（profile+config+当前版本引用）
 -> [等待空闲：无运行任务/无活动会话/网关空闲] -> applying（原子切换 current 指针）
 -> starting（健康检查 <=90s）-> committed（清理 staging/记录版本）
失败（任一步）-> rollback（切回旧版本 + 恢复 profile 快照）-> 报告
~~~

- 【决策】内核更新默认"非必要不更新"（00 第 11 节）：稳定通道只在内核空闲且用户确认时提示；紧急安全更新可强提示但仍需确认。
- 【待定】自动更新策略（全自动/仅提示/手动）在设置中提供，默认"仅提示"。

### 10.8 回滚与快照

| 对象 | 保留 | 说明 |
|---|---|---|
| 内核版本目录 | 最近 2 个（current + previous） | Kernel/<ver>/ + current.json 指针 |
| profile 快照 | 更新前一份（zip，含 package.json/pnpm-lock/cordis.patch.yml/compatibility.json） | 应用失败恢复；保留最近 3 份 |
| 配置快照 | AMS_HOME/config（state.db + settings） | 更新前自动备份（轻量） |
| 回滚操作 | 启动器 UI"回滚内核" | 切回上一版本 + 启动 + 健康检查；profile 是否回滚由用户选择 |
| 数据兼容 | profile/session 格式由 DSH 管理；跨版本升级走 DSH 的 upgrade-guide 流程（本册要求内核 manifest 声明 sessionFormat 版本） | 【风险】降级可能不兼容新 session 格式 -> 回滚时提示"恢复旧版本快照" |

### 10.9 兼容检查（更新前）

1. 内核 manifest.requires 与启动器/Gateway 版本；
2. 已安装插件 engines.kernel/ams/dsh 与目标内核；
3. 内核 kernelApi 与插件平台；
4. 不兼容列表展示（插件名/当前版本/要求），用户可选"跳过不兼容插件（禁用）"或取消；
5. 强制执行需二次确认并写审计日志。

### 10.10 发布流程（内核）

~~~text
开发者: PR -> dev -> main（受保护）
发布: 1) 版本号 bump（ams/scripts/version.mjs）+ CHANGELOG + upstream.json
      2) 打 tag kernel-v<ver> -> CI ams-release.yml
      3) 构建（signed）-> 产物 -> kernel-package.json
      4) 生成 ams-release 清单条目（组件 id: kernel, requires/compat）
      5) Ed25519 签名清单 -> 上传 GitHub Release（ams-harness）
      6) 更新 ams-release 仓库 manifests/<channel>.json 并推送
      7) 冒烟：干净 VM 用启动器安装/升级/回滚
      8) 公告（可选）
~~~

- 版本节奏：dev（每次合并自动 unsigned 构建，不发布）；beta（每周可选）；stable（每月或按需）。
- 发布门禁见 §11.4；发布清单见 05 分册 Release Checklist。

## 12. 安全 / 隐私 / 许可 / 性能

### 12.1 威胁模型与对策

| 资产 | 威胁 | 对策 | 残余风险 |
|---|---|---|---|
| DeepSeek API Key | 恶意插件读取/日志泄露/诊断包外传 | 只存 DSH 凭据文件；日志脱敏；诊断包白名单；插件签名/allowlist；Key 不进启动器/Gateway | 用户安装未签名插件（需显式开发者模式） |
| 用户音频/工程 | 插件或页面越权读取；意外上传 | 本地优先；无自动上传；文件访问经 Gateway/Host 白名单；AI 上下文不含原始音频 | 用户主动分享/导出 |
| 系统执行 | 恶意插件执行任意命令 | 默认禁用 shell/terminal 工具；Host 插件仅签名/allowlist；安装需用户确认+审计 | Host 插件无沙箱（DSH 事实） |
| 本地端口 | 本机其它程序访问控制面/RPC/Gateway | 127.0.0.1 绑定；32+ 字节 token；token 文件 ACL；拒绝浏览器 CORS | 本机恶意程序（同用户权限）可读 token 文件 |
| 更新链路 | 中间人/伪造更新包 | HTTPS；sha256 + Ed25519 清单签名；Authenticode；公钥内置 | 私钥泄露（轮换流程） |
| 模型提示注入 | 页面/文件名/日志诱导 AI 执行危险操作 | 危险操作需确认；工具白名单；系统提示约束；上下文注入来源标注 | 用户确认了危险操作 |
| 供应链 | npm 依赖投毒；第三方插件 | 锁定 pnpm-lock；CI 校验；仅签名 payload；Dependabot 提示 | 上游依赖漏洞（需跟进） |

### 12.2 隐私与数据流

【决策】产品承诺：**默认零遥测、零自动上传**（与 00 第 12 节一致）。

| 数据 | 去向 | 触发 | 保留 |
|---|---|---|---|
| 用户 API Key | 仅本机 DSH 凭据文件；请求时发往用户配置的模型端点 | 用户配置 + 每次模型请求 | 用户可删（设置） |
| 会话文本（提示/回答） | 本机会话日志（%AMS_HOME%/sessions）；同时作为模型请求发送给用户配置的端点 | 会话 | 本地；用户可删 |
| 音频/工程文件 | 本机；不自动上传 | 用户显式操作（模型请求不携带音频字节，仅文本描述/路径） | 本地 |
| 任务/日志/诊断 | 本机；诊断包仅用户导出 | 用户点击"导出诊断" | 本地；用户可删 |
| 更新检查 | 启动器访问 GitHub/自建 feed | 用户检查/自动检查（可关） | 无用户数据 |
| 崩溃报告 | 本机 %AMS_HOME%/logs/kernel | 崩溃时 | 最近 10 份；用户可删 |

- 日志脱敏规则：token/Key/Authorization/用户目录绝对路径 → 打码；音频二进制不入日志。
- 诊断包内容白名单：内核版本/upstream/OS/CPU/GPU 名称/驱动版本/组件状态/最近 200 行日志/配置模板（不含 Key、不含用户文件内容）。
- 删除/导出：设置页提供"清除会话/清除日志/导出诊断/打开数据目录"；卸载默认保留/删除用户数据由启动器询问（00 第 11 节）。
