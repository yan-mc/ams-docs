# AMS 便携式安装与运行时方案 v1.3（冻结稿）

> 状态：已由产品负责人确认，作为后续实现基准。
> 取代：06_方案设计/00_总体设计与约定.md 第 4 节“安装目录与数据目录分离”的默认形态；本文采用“安装根/data”唯一形态。

## 1. 总原则

1. 安装根是唯一产品边界：程序、运行时、模型、音源、资产、工程、缓存、日志、临时文件全部位于安装根内。
2. 不在安装根之外写任何 AMS 数据；不创建用户/系统环境变量指向 AMS。
3. 启动器只通过安装根相对路径和受管组件定位依赖；禁止把任意外部路径写进 runtime/config。
4. 用户素材默认复制到 `data/projects`；原始外部文件只作为导入来源，不作为运行依赖。
5. 显卡驱动和 CUDA 驱动只检测、提示，不自动安装；NVIDIA 驱动是系统前提，torch 的 CUDA 运行库随运行时组件分发。
6. 启动器负责所有受管组件的安装、修复、更新、回滚；安装完成的用户不安装 Python/Node/ffmpeg/CUDA toolkit。

## 2. 安装根布局

~~~text
<安装根>                                默认 F:\AMS-Studio
  ams-launcher.exe
  uninstall.exe
  data\
    config\
      connection.json                    网址 + Key（两个输入）
      runtime.json                       仅存 data 内相对路径
      state.db                           组件/任务/更新状态
    kernel\                              Electron + DSH + 内置 Node/Python
    components\
      downloads\                         下载缓存（可清理）
      <component-id>\                    解包后的组件载荷
    runtime\
      rvc\<version>\                     RVC Python/torch/HuBERT/RMVPE/ffmpeg
      pymss\<version>\                   pymss Python/torch/models
      tts\<version>\                     后续 GPT-SoVITS/Qwen
      ports.json, gateway.token, kernel.json
    tools\
      ffmpeg\<version>\bin\              ffmpeg/ffprobe（受管，不进 PATH）
    models\                              基础模型/索引缓存
    voices\                              音源库（安装后默认已有曼波）
    assets\voicepack.manbo\              曼波资产包解包/校验区
    projects\                            用户工程（素材复制到这里）
    artifacts\                           Gateway 任务产物
    logs\                                按组件/日期滚动
    cache\                               可清理缓存
    updates\                             更新暂存/回滚
    backups\                             备份/回收站
~~~

## 3. 文件与目录规则

- 所有路径以安装根为基准；配置中禁止出现安装根以外的绝对路径。
- 启动器启动 Gateway/Kernel 时只注入 data 内路径；`AMS_HOME` 仅作为进程内环境传给子进程，不写入用户环境。
- `data\runtime.json` 保存相对路径，例如 `runtime/rvc/0.1.0`；解析失败时按组件状态修复。
- 用户选择输入音频时，启动器/插件先复制到 `data\projects\<id>\source`；输出只写 `data\projects` 或 `data\artifacts`。
- 清理缓存只允许 `data\cache`、`data\components\downloads` 中登记的临时项；不得递归删除安装根之外。

## 4. 运行组件清单

| 组件 ID | 内容 | 安装位置 | 体积级 | 必需 |
|---|---|---|---|---|
| launcher |  Tauri 启动器 | 安装根 | 2.4MB | 是 |
| kernel | Electron + DSH + Node + Python | data/kernel | 1.1GB | 是 |
| plugin.ams.music.bundle | 插件 tgz | data/components | 22KB | 是 |
| service.gateway | PyInstaller Gateway（含 Python） | data/components | 33MB | 是 |
| runtime.rvc | RVC Python/torch/HuBERT/RMVPE/ffmpeg | data/runtime/rvc | 7-10GB | 是（换声/炼制） |
| runtime.pymss | pymss Python/torch/models | data/runtime/pymss | 6-8GB | 按需（分离） |
| tool.ffmpeg | ffmpeg/ffprobe | data/tools/ffmpeg | 约 100MB | 是（音频/RVC） |
| asset.voicepack.manbo | 曼波 pth/index | data/assets，自动到 data/voices | 188MB | 是（随组件下载） |
| catalog.models | 模型索引 | data/models | 小 | 是 |
| runtime.tts | GPT-SoVITS/Qwen | data/runtime/tts | 4-6GB | 后续 |

### 4.1 曼波资产

- 作为 `asset.voicepack.manbo` 组件，与 kernel/gateway/plugin 一起下载。
- 安装完成即解包到 `data\voices\曼波\曼波.pth` + `.index`；用户无需单独处理。
- 校验 sha256；已存在时默认保留用户文件，损坏则提示修复。

## 5. 空系统安装流程

1. 启动器安装（检测 WebView2/VC++；缺失给安装引导）。
2. 检查 Windows 版本、磁盘、NVIDIA 驱动/CUDA 驱动（只读提示）。
3. 选择安装根（默认 F 盘；所有数据在其 data 内）。
4. 下载并安装 kernel + gateway + plugin + tool.ffmpeg。
5. 下载并安装 runtime.rvc + asset.voicepack.manbo；自动扫描曼波。
6. 按需安装 runtime.pymss；后续 TTS。
7. 启动内核、Gateway，验证 HTTP/health/音源/页面/RVC 冒烟。

## 6. 运行环境检测

- 检测项：Windows 版本、WebView2、VC++、磁盘、GPU/驱动、CUDA 驱动版本。
- 组件项：kernel 内置 Node、Gateway 内置 Python、RVC runtime、pymss runtime、ffmpeg、曼波。
- 系统 Node/Python/Git/ffmpeg 不再作为必需项；仅显示“开发工具/可选”。
- 驱动/CUDA 缺失只给提示，不自动安装。

## 7. 更新与回滚

- 组件独立版本目录 + current 指针；更新失败回滚。
- 大组件（RVC/pymss）按分卷包下载，全部 sha256 校验后解包。
- 离线包 `.amsupd` 与在线 feed 共用签名校验。

## 8. 验收

- 干净 Windows VM（无 Python/Node/ffmpeg/Git/CUDA toolkit，保留 NVIDIA 驱动）。
- 安装后 data 内包含 kernel、gateway、plugin、ffmpeg、RVC runtime、曼波。
- 全盘搜索启动器/网关日志中的外部路径：不得出现 `F:\ai歌曲`、源码工程目录或用户环境变量。
- 5 秒 RVC 任务成功；pymss 分离按模型可用；卸载只删安装根。
