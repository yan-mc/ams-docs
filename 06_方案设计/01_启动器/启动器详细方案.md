## 0. 摘要与决策速览

AMS Launcher 是 Windows x64 独立 AI 音乐工作站（代号 AMS）的**系统级管理面**：负责安装、环境检测、组件与运行时管理、音色库索引、服务编排、**分模块更新中心**、**MSVC→pth 转换器**、诊断与托盘常驻；它**不承载 AI 会话、不做推理、不分发音源**。启动器与「内核（fork DSH）」和「网关（Python FastAPI）」共同构成三层：启动器装/修/更新/起，内核负责 Agent + 页面，网关负责任务/服务/产物（见 00 第 3 节）。

### 0.1 核心决策清单

| # | 决策 | 说明 | 依据 |
|---|---|---|---|
| D1 | 【决策】独立 Tauri 2 启动器（Rust + Vue3/TS），常驻托盘 | 不把启动器做成 DSH 插件：系统级安装/更新/服务启停/提权不适合放在插件宿主内；可独立于内核自愈 | 04 报告 §7.2 推荐「C. 混合」；可行性 §3.2 首选 Tauri |
| D2 | 【决策】更新按「组件」独立勾选，签名+快照+回滚；内核默认不自动更新 | 组件：launcher / kernel / 每个 plugin / 每个 service / 每个 tool / catalog.models | 00 第 11 节、task 要求 |
| D3 | 【决策】更新清单 Ed25519 签名 + sha256 + 防降级（版本单调 + 清单时间戳 + key_id 轮换） | 公钥内置启动器，私钥仅 CI；镜像只做下载源不改信任链 | 00 第 11/13 节、Git 发布流程 §7/§9 |
| D4 | 【决策】MSVC 转换器输出严格遵循 00 第 6 节音源库格式：voices/&lt;名称&gt;/&lt;名称&gt;.pth；MSVC **不含 index**，因此**不生成** .index，UI 与清单显式标注「无检索增强（index_rate=0）」 | 不伪造 index、不猜测检索特征；用户如另有 index 可手动放入同名文件 | 05 心月格式深拆/格式.md §3；00 第 6 节 |
| D5 | 【决策】转换核心由 Rust 内置实现（解析/校验/写盘），转换结果登记为 Gateway msvc.convert 任务（统一进度/审计/AI 可见） | 启动器自包含、无 Python 依赖；Gateway 只做任务登记与产物索引 | 00 第 8 节任务类型；本文 §7.3 |
| D6 | 【决策】无遥测、默认不联网；联网仅用于用户显式触发的「检查更新/下载/模型市场」 | 与内核侧关闭 session-log/telemetry 的链路分开，启动器自身零上报 | 00 第 12 节 |
| D7 | 【决策】状态外置：SQLite AMS_HOME/config/state.db（WAL）+ 配置 TOML；安装目录只放程序 | 删除安装目录不丢用户资产；支持便携模式 | 00 第 4 节 |
| D8 | 【决策】提权仅限「驱动/虚拟声卡/系统工具」安装，独立提权 helper 进程，逐次用户确认（UAC） | 日常运行不提权；提权动作有白名单与审计 | 00 第 12 节、可行性 §3.1 |
| D9 | 【决策】离线更新包 .amsupd（zip + 内嵌签名清单）与在线更新同校验链 | 无网/企业环境；导入前验证签名与渠道 | 00 第 11 节 |
| D10 | 【待定】转换核心是否也提供「命令行/服务」形态给 CLI 与自动化 | P1 可暴露 ams-launcher-cli msvc-convert | 本文 §10/§15 |

### 0.2 与「心月工具盒子」的关系（参考而非照搬）

【事实】心月工具盒子（Electron 1.0.0）实际具备：系统优化（64 项注册表/启动项/DNS/TCP/Windows Update/GPU 改名/PresentMon FPS 浮层）、云端音色市场、VIP/钻石充值、强制登录与版本闸门、服务端下发的强制更新包（见 03_心月套件/报告.md）。本方案的取舍：

| 心月能力 | AMS 采纳 | 理由 |
|---|---|---|
| 环境/组件安装、服务启停、更新（好用的部分） | 采纳，重做并组件化 | 真需求 |
| 分模块更新 + 服务端版本闸门 | 采纳「更新」但**移除强制登录/强制更新** | 本地优先、用户可控 |
| 64 项注册表优化/内存清理/DNS/TCP/显卡改名/FPS 浮层 | 不做 | 与音乐工作站定位无关，风险高（见可行性 §3.1「去掉」） |
| 云端音色市场/VIP/充值/微信登录 | 不做 | 应用不分发/售卖音源；音源由用户自备（00 第 1 节） |
| 私有 MSVC 模型格式 | 仅做「用户本地文件→标准 pth」转换工具 | 互操作需求，见 §7 |

## 1. 定位、范围与非目标

### 1.1 定位【决策】
- 面向 **Windows 10/11 x64**（首发仅 x64；NVIDIA 优先、CPU/DirectML 降级，见 00 第 1 节）的桌面启动器。
- 是 AMS 的**唯一安装入口**与**唯一系统级写操作入口**：驱动/虚拟声卡、系统组件、Python 运行时、7z/ffmpeg、内核与插件、后端服务，全部由启动器安装/修复/更新。
- 是 AMS 的**本地控制面**：启动/停止/保活内核与网关；暴露受限本地 RPC 供内核/AI/CLI 请求安装、查更新、服务启停、MSVC 转换。
- 常驻托盘，关闭窗口=最小化到托盘；提供「完全退出」。

### 1.2 非目标
| 非目标 | 说明 |
|---|---|
| 不做 AI 会话/Agent 循环/工具编排 | 归内核（DSH）与插件；启动器只提供系统级能力 |
| 不做音频推理/训练 | 归后端服务（Gateway 拉起与监管） |
| 不内置、不分发、不上传音源与模型权重 | 00 第 1/6 节；仅本地导入/校验/转换 |
| 不提供账号体系/VIP/充值/云端市场 | 本地优先；无遥测 |
| 不做系统优化/注册表清理/显卡改名 | 与产品定位无关，风险高 |
| 不做 .cyd 解密、不绕过任何第三方授权 | 见 §7.2 授权边界 |
| 不做 macOS/Linux 首发 | 00 第 1 节 |

### 1.3 职责边界表（与内核/网关/服务）

| 能力 | Launcher | Kernel（fork DSH） | Gateway | 后端服务 |
|---|---|---|---|---|
| 安装/卸载/修复 | 唯一执行者 | 不参与 | 不参与 | 不参与 |
| 环境检测/运行时装 | 负责 | 只读展示 | 只读 | 提供运行时约束清单 |
| 组件/更新管理 | 负责 | 只读/触发检查 | 只读 | 版本自报 |
| 音色库（voices）扫描/校验/转换 | 负责（文件系统） | 页面展示（经插件） | 提供 /voices/scan、/voices/validate 服务端实现 | RVC 服务解析 pth 元数据 |
| 任务队列/产物 | 只读镜像（任务总览） | 页面展示 | 唯一权威 | 执行任务 |
| 服务进程拉起/保活 | 负责（网关/服务） | 不参与 | 业务层拉起后端服务，Launcher 监控网关 | 自报健康 |
| AI 工具/页面/技能 | 不参与 | 负责 | 提供 API | 不参与 |
| 更新文件下载/校验/回滚 | 负责 | 不参与 | 不参与 | 不参与 |
| MSVC 转换 | 解析/校验/写盘（D5） | 页面入口（插件） | 任务登记/审计 | 可选校验（Python 交叉验证） |
| 日志/诊断包 | 汇总打包 | 自报日志路径 | 自报日志/端口 | 自报日志 |

## 2. 用户与场景

### 2.1 人（普通用户）
| 场景 | 目标 | 关键交互 |
|---|---|---|
| S1 首次安装 | 3 步内可用；明确磁盘/显卡/网络要求 | 首启向导：许可与隐私 → 目录选择（AMS_HOME）→ 环境体检 → 推荐组件安装 → 内核/网关拉起 → 完成 |
| S2 日常启动 | 双击即用；托盘常驻；失败可一键修复 | 首页状态卡 + 一键启动/停止；服务异常红点；托盘菜单快捷操作 |
| S3 组件缺失/损坏 | 自愈 | 环境检测 →「修复」；组件页状态与一键修复 |
| S4 更新 | 只更需要的组件；可回滚 | 更新中心：按组件勾选、变更说明、下载进度、应用与回滚历史 |
| S5 音色库管理 | 扫描 pth+index、校验、标签、打开目录 | 音色库页：拖拽导入、校验报告、缺失 index 提示、重命名 |
| S6 心月模型迁移 | 把本地 .msvc 转成标准 pth 放进 voices | MSVC 转换器页：选择文件/目录 → 预检 → 转换 → 验证 → 写入 voices |
| S7 故障 | 自助诊断 | 诊断页：日志、端口、进程、GPU、磁盘、生成诊断包 |
| S8 离线/弱网 | 可安装可更新 | 离线包导入、镜像设置、断点续传 |
| S9 低配/CPU | 可用降级 | 环境检测给出 DirectML/CPU 建议；性能档位 |

### 2.2 AI（经内核工具调用）
【决策】AI 不直接操作文件系统做安装；一切经**启动器本地 RPC**（§9.1），由 Host 插件工具封装（§10），并遵守审批：

| AI 场景 | 调用 | 审批/限制 |
|---|---|---|
| 查询环境/组件/更新状态 | launcher.status / launcher.env.get / launcher.update.check | 自动（只读） |
| 请求安装缺失组件 | launcher.component.install | 需用户确认（UI 弹窗），AI 只能提交申请并等待 |
| 启动/停止服务 | launcher.service.start/stop | 需用户确认；实时变声会话独占时拒绝 |
| 触发更新检查/下载 | launcher.update.download | 需用户确认；内核更新仅提示 |
| MSVC 转换（用户自有文件） | launcher.msvc.convert | 需用户确认；只写 AMS_HOME/voices |
| 生成诊断包 | launcher.diag.bundle | 自动（本地生成，不联网） |
| 打开目录/浏览器 | launcher.shell.open | 白名单路径 |

### 2.3 开发者/运维
- dev 通道 + 本地源（file:// 或本地 HTTP）；强制指定组件版本用于回归；启动器日志级别与调试 RPC 开关（仅 dev）。
- 企业/离线：.amsupd 离线包 + 内网清单镜像；禁用所有外网 URL 的策略项【待定：是否首发提供】。

## 3. 功能清单与验收标准

优先级：**P0 = 首发必须**；P1 = 首发后 1–2 个版本；P2 = 规划项。

### 3.1 环境与安装
| ID | 功能 | 优先级 | 验收标准 |
|---|---|---|---|
| F-ENV-01 | 系统/硬件检测（OS 版本、CPU、内存、磁盘、GPU/驱动/CUDA、WebView2、VC++ 运行库） | P0 | 检测项全部有明确结果/修复建议；耗时 <3 s；离线可用 |
| F-ENV-02 | 目录选择与空间预检（AMS_HOME、安装盘） | P0 | 空间不足或路径非法时阻止并给出最小/推荐空间；支持便携模式 |
| F-ENV-03 | 运行时安装/修复（Python 便携运行时、7z、ffmpeg、VC++、WebView2） | P0 | 组件独立安装；失败可重试；安装后自检通过 |
| F-ENV-04 | 虚拟声卡/驱动安装（VB-Cable、可选 ASIO） | P0（变声场景） | 仅经提权 helper；安装/卸载可回滚；无静默安装 |

### 3.2 更新中心（详见 §6）
| ID | 功能 | 优先级 | 验收标准 |
|---|---|---|---|

### 3.5 明确不做

### 4.1 页面地图【决策】

~~~text
AMS Launcher
~~~

### 5.2 进程与线程模型

~~~text
AMS Launcher.exe（Tauri，非提权，常驻托盘）
├─ Rust 主进程（tokio runtime）
│  ├─ core：config/state.db/log/crash
│  ├─ env：系统与硬件探测（WMI/PowerShell/注册表只读/nvml 或 nvidia-smi）
│  ├─ components：安装/卸载/校验（调用 7z/安装器 sidecar）
│  ├─ update：清单/签名/下载/暂存/应用/回滚
│  ├─ services：网关与后端进程监管、端口分配、健康检查
│  ├─ kernel：内核启动/停止/版本注入/profile 管理
│  ├─ voices：voices 目录扫描/解析/校验
│  ├─ msvc：MSVC 解析/转换/验证（纯 Rust）
│  ├─ rpc：本地 HTTP/命名管道（127.0.0.1 + token，见 §9.1）
│  └─ diag：诊断包/脱敏打包
├─ WebView2（前端 Vue3，IPC 走 tauri command/event）
└─ 子进程（按需，带 Job Object 管理生命周期）
   ├─ ams-elevate.exe（提权 helper，UAC 后执行白名单动作）
   ├─ 7zr.exe（解压）/ 安装器（VC++/WebView2/VB-Cable，静默参数受控）
   ├─ AMS Kernel.exe（Electron 壳 + dsh 运行时）
   └─ 网关与后端服务（Python，按端口/token 拉起）
~~~

要点：
- 【决策】所有子进程用 Windows Job Object 绑定，启动器退出/崩溃时按策略终止（内核/网关默认优雅关闭，服务强制终止）。
- 【决策】提权动作只发生在 ams-elevate.exe（独立清单、独立签名、白名单参数）。
- 【决策】启动器自身永不加载第三方插件代码；前端只渲染本地 bundle（无远程页面，除用户点击的 http(s) 外部链接走系统浏览器）。
- 【风险】WebView2 缺失/过旧（Win10 需 Evergreen Runtime）；启动器安装包需检测并安装。

### 5.4 与内核（fork DSH）的关系

| 项 | 方案【决策】 |
|---|---|
| 启动 | 启动器用固定 profile（music）拉起 kernel：AMS_KERNEL_EXE + --profile music；或在已安装 Desktop 模式下用 dsh CLI |
| 工作目录 | kernel 的 DSH_HOME/profile 目录在 AMS_HOME/profiles/music（00 第 4 节） |
| 版本注入 | 通过环境变量与 profile patch 注入：AMS_HOME、Gateway 端口/token 文件路径、组件版本 JSON（runtime/versions.json）、启动器 RPC 端口/token |
| 健康检查 | kernel 暴露本地健康探针（由 Host 插件上报 Gateway /health 或 launcher RPC），超时 60 s 失败提示诊断 |
| 生命周期 | 启动器退出时默认不杀 kernel（可选「退出时同时关闭」）；kernel 崩溃不触发启动器重启循环（最多 3 次/10 分钟） |
| 更新 | kernel 整包更新（非必要不更）；更新前要求 kernel 空闲、无 job/实时会话；更新后跑兼容性检查（插件 API 版本、profile patch 应用成功、健康探针） |
| 配置边界 | 启动器只写 kernel 的 profile patch 与 versions.json；不写用户 key/会话/项目数据 |

### 5.5 与网关（Gateway，Python FastAPI）的关系

| 项 | 方案【决策】 |
|---|---|
| 启动 | 启动器拉起网关：独立便携 Python 运行时 + uvicorn；端口动态分配；写 AMS_HOME/runtime/ports.json + gateway.token（32+ 字节随机） |
| 保活 | 进程监管 + 健康检查（GET /health，5 s 超时，退避重启 1/5/15/60 s，5 次后停止并告警） |
| 权限 | 启动器持有一个「管理 token」（与用户/插件 token 区分，见 §9.1）；网关 API 需 Bearer token（00 第 8 节） |
| 用途 | 任务镜像（GET /jobs + SSE）、音色扫描/校验（POST /voices/scan、/voices/validate）、模型目录（/catalog/...）、MSVC 转换任务登记（POST /jobs type=msvc.convert） |
| 降级 | 网关不可用时：启动器仍可安装/更新/诊断；音色库退化为本地文件扫描（不解析 pth 元数据，标记「待网关解析」） |
| 版本约束 | 网关与后端服务带版本；启动器将 service 版本写入 Gateway 配置；不匹配时提示更新 |

### 5.6 本地 RPC（launcher-ipc）

【决策】启动器暴露**仅本机**的 RPC，供内核 Host 插件、CLI 调用：
- 传输：HTTP over 127.0.0.1（随机端口，写入 runtime/launcher.json）为主；命名管道（lpc:\\.\pipe\ams-launcher）为备选【待定】。
- 鉴权：令牌文件 runtime/launcher.token（0600 等价权限），启动器启动时生成；每次安装/更新后轮换；调用方带 Authorization: Bearer。
- 方法命名：launcher.<域>.<动作>；全部 JSON；统一错误 {ok:false,error:{code,message,detail?}}。
- 白名单参数校验（路径必须在 AMS_HOME/安装目录内）；所有写操作方法记录审计（SQLite audit_log）。
- 速率限制：只读 100 req/s，写操作 5 req/s；防本机恶意进程滥用。
- 方法清单见 §9.1；AI 审批策略见 §2.2。

### 5.7 提权边界（ams-elevate.exe）

| 允许（白名单） | 禁止 |
|---|---|
| 安装/卸载 VB-Cable、ASIO 驱动 | 任意 exe/脚本执行 |
| 安装 VC++ Redistributable / WebView2 Runtime | 修改注册表（除驱动安装必需项） |
| 安装系统级服务（仅 AMS 自有服务，如有） | 关闭防火墙/杀软/Windows Update |
| 安装/升级 NVIDIA 驱动（可选，P2；默认只检测不安装） | 显卡改名、隐藏进程、内核驱动加载 |
| 修复文件权限/长路径 | 提权运行用户提供的任意文件 |

机制：提权 helper 只接受「动作 ID + 已签名/已哈希的安装器路径 + 受控参数」，由启动器生成任务文件；helper 校验任务文件签名/哈希与动作白名单后执行；执行完记录结果。UAC 每次确认，不保留常驻提权。

### 5.8 关键流程时序（摘要）

~~~text
启动：Launcher → 读 state.db/config → 环境快检 → 若启用：拉起网关（分配端口/token，等 /health）
      → 拉起内核（注入 AMS_HOME/ports/token/versions）→ 等健康 → 托盘就绪
更新：检查清单（GET manifest + 验签）→ 依赖求解 → 用户勾选 → 下载（断点/校验）
      → 暂存 updates/staging → 快照 → 应用（按组件策略）→ 健康检查 → 成功/回滚
转换：MSVC 文件 → Rust 解析（TLV/JSON/FP16）→ 顺序推断 → 写 .pth 到 voices/<名称>/
      → 结构校验 → 调 Gateway 登记 msvc.convert（结果/哈希）→ UI 展示并可「加入音色库」
~~~

## 6. 更新系统（重点）

### 6.1 设计目标与不变量

| 目标 | 不变量（实现必须满足） |
|---|---|
| 分模块独立更新 | 任一组件可单独升级/回滚，不影响其它组件（除显式依赖） |
| 可信 | 清单与包均验签；任何签名/哈希失败必须拒绝且不留半安装状态 |
| 可回滚 | 每次「应用」前有快照；失败/健康检查不通过自动回滚；回滚不依赖网络 |
| 不打断用户 | 有运行中任务/实时会话时禁止应用内核/网关/服务更新；启动器自更新不静默重启 |
| 内核稳定优先 | 内核默认不自动更新；只有用户确认 + 兼容性通过才允许 |
| 可离线 | 离线包与在线更新共用同一清单与校验链 |

### 6.2 组件模型与颗粒度【决策】

组件 ID 规范（与 00 第 5 节一致）：
- launcher（启动器本体）
- kernel（Electron 壳 + dsh 运行时，整包一个版本单元）
- plugin.<pluginId>（如 plugin.ams.music.trainer，tarball）
- service.<name>（如 service.rvc-train，wheel/便携 zip + 运行时约束）
- tool.<name>（如 tool.ffmpeg、tool.7z、tool.vbcable，独立版本）
- catalog.models（数据版本，清单+下载索引，不含大文件本体）

组件元数据（state.db + 清单共用）：id、kind、name、version、channel、size、sha256、url[]、dependencies{requires}、install_path、installed_at、source(在线/离线/内置)、signature_key_id、rollback_available、notes。

| 组件 | 更新单位 | 是否可热更 | 需要重启 | 说明 |
|---|---|---|---|---|
| launcher | 全量安装包（NSIS） | 否 | 是（自更新后重启自身） | 独立 updater；任务运行时只提示 |
| kernel | 全量整包（Electron 壳+运行时同版本） | 否 | 是（重启内核） | 非必要不更（§6.10） |
| plugin.* | npm tarball | 是（DSH 插件管理器，运行中可热装；失败回滚） | 否（页面刷新） | 依赖 kernel/engines 声明 |
| service.* | wheel 或便携 zip（含运行时依赖声明） | 否（先停服务） | 服务重启 | 版本需与网关/内核兼容矩阵匹配 |
| tool.* | zip/exe | 否 | 工具级重启 | ffmpeg/7z/VB-Cable 安装器 |
| catalog.models | JSON 清单 + 文件包 | 是（增量下载） | 否 | 模型文件独立下载/校验 |

### 6.4 签名与信任链【决策】

| 层 | 机制 |
|---|---|
| 清单签名 | Ed25519（ed25519-dalek），私钥仅 CI Secret；公钥内置启动器（编译期常量 + 可热更新 key 集，见下） |
| 包完整性 | sha256（每个 URL 内容必须一致）；下载后先哈希再验签清单声明 |
| 可执行文件 | Windows Authenticode 签名（EV/云签名）作为第二道防线；启动器校验安装包签名 subject 与清单 key 一致 |
| 密钥轮换 | 内置 key 集合 {key_id, public_key, not_before, not_after}；签名带 key_id；过期密钥不再接受；轮换需一次启动器版本更新 |
| 防降级 | 版本单调（semver 比较 + sequence 单调）；禁止安装低于已装版本的组件，除非 dev 通道显式「允许降级」且二次确认 |
| 防重放 | sequence + generated_at/expires_at；本地记录已见最大 sequence |
| 时间 | 不依赖本机时间：以 sequence 为主，时间仅提示；时钟异常不影响校验 |

【风险】若私钥泄露需紧急轮换：发布新启动器（内置新 key）+ 在旧清单中声明 revoke；离线用户可能暂时无法更新（提供官方公告与手动包）。

### 6.5 通道与灰度
- 通道：stable（默认）、beta（提前验证）、dev（开发者，可选允许降级/本地源）。通道在设置页切换，切换后重新检查。
- 灰度：清单按通道生成，服务端可对特定版本发 withdraw；更细的按机器灰度由服务端清单变体实现【待定：首版不做定向灰度】。
- 本地源：dev 可配置 file:// 或 http://127.0.0.1 的清单 URL（仅 dev，需显式开启并二次确认）。

### 6.6 检查流程
1. 读取本地所有组件版本/通道/上次清单 sequence。
2. GET 清单（带 If-None-Match/ETag；超时 8 s；失败→镜像/离线清单）。
3. 验签（失败→界面报「清单不可信」并停止）；校验 schema/sequence/channel/min_launcher。
4. 依赖求解（§6.9），生成「可更新 / 必须连带 / 被阻止」三组。
5. 展示结果（组件、版本、大小、说明、依赖）；缓存清单到 AMS_HOME/cache/manifests/（供离线比对）。
6. 用户勾选 → 下载。检查更新只读，不修改任何已安装文件。

### 6.7 下载
| 项 | 决策 |
|---|---|
| 断点续传 | 支持 Range；.part 文件 + sidecar .meta（URL/ETag/size/hash）；重启后校验已下载前缀再续 |
| 并发 | 最多 3 个组件并行；单组件内最多 2 连接（可配置） |
| 镜像 | url[] 顺序尝试；同一次下载失败 2 次换下一个镜像；全部失败→报错并保留 .part |
| 限速 | 可配置（默认不限；夜间模式可选） |
| 校验 | 完成后 sha256；不符删除并重试（最多 3 次）；仍失败报 E3015 |
| 磁盘 | 下载前检查目标盘剩余空间 ≥ 包大小×2.2（解压+快照余量） |
| 缓存 | 已下载包保留在 cache/downloads 直到安装成功 + 保留上一版本（回滚用） |

### 6.8 暂存、快照、应用、健康检查、回滚

**暂存（staging）**：下载校验后解压到 AMS_HOME/updates/staging/<component>/<version>/，做静态检查（文件清单、可执行签名、版本探测）。不触碰已安装目录。

**快照（snapshot）**：应用前创建 AMS_HOME/updates/snapshots/<txid>/：
| 组件 | 快照范围 | 大小预估 |
|---|---|---|
| plugin.* | 旧版本 tarball + profile patch 相关文件 | 1–20 MB |
| service.* | 旧版本目录（或指针到 cache 旧包）+ 服务配置 | 10–500 MB |
| kernel | 旧版本安装包路径记录 + profile patch + versions.json（不复制 800 MB 包，保留旧包 90 天） | < 5 MB + 旧包引用 |
| launcher | 旧安装包路径 + 自身版本记录（回滚=运行旧安装包） | < 5 MB |
| tool/catalog | 旧版本目录/清单 | 视组件 |

【决策】快照采用「旧包引用 + 小文件复制」策略：大包保留在 cache/downloads 至少 90 天；快照记录哈希与路径，回滚时校验旧包仍存在，否则提示重新下载旧版本。

**应用（apply）**：
| 组件 | 步骤 |
|---|---|
| plugin | 复制 tarball 到 profile 插件缓存 → 调 DSH 插件管理器安装（或直接 npm 安装到 node_modules）→ 应用 profile patch → 健康检查（插件加载无错误）→ 失败回滚 |
| service | 停止依赖该服务的任务（等待/取消）→ 停服务 → 原子替换目录（新目录 + 切换 current 符号链接/junction）→ 起服务 → 健康检查 → 失败回滚 |
| kernel | 等待内核空闲（无 job、无实时会话）→ 关闭内核 → 安装（NSIS /S 静默，受控参数）→ 迁移 profile patch → 起内核 → 健康检查（探针 + 插件 API 版本）→ 失败回滚旧包 |
| tool | 停用相关功能 → 替换目录 → 自检（ffmpeg -version 等）→ 失败回滚 |
| launcher | 自身下载 → 提示 → 运行新安装包 → 退出自身 → 新版本启动后完成标记；失败可手动回滚旧安装包 |
| catalog.models | 仅更新清单文件（原子写）；模型文件独立下载（可并发），不影响运行 |

**健康检查**：组件类型化检查表（见 §13.3），超时 90 s；内核/网关/服务二次检查（启动 2 次握手）；失败→自动回滚并保留现场日志。

**回滚**：txid 级回滚（回滚本次批次全部组件）或组件级回滚；回滚前再次健康检查；回滚后记录 update_history（result=rolled_back）。

### 6.9 分模块勾选与依赖求解【决策】
- 求解目标：用户勾选集合 S 必须闭包化（补齐 requires），并检测冲突（区间交集为空/内核 API 版本不兼容）。
- 规则：内核更新只能整包头；插件更新不能跨内核 API 大版本（除非内核一并更新且兼容矩阵允许）；服务更新需网关版本满足 requires.gateway。
- UI 表现：勾选组件 → 自动勾选必需依赖并标黄「将一并更新」；无法满足时标红原因「需先更新内核」「需要服务 X ≥1.1」。
- 冲突时允许「仅下载不安装」，先备份后统一维护窗口应用。
- 依赖清单缓存在 state.db（component_dependencies），离线也可求解（基于本地清单副本）。

### 6.10 内核「非必要不更新」策略【决策】
| 触发 | 行为 |
|---|---|
| 有内核新版本 | 仅在更新中心显示，不自动下载；首页不弹强提示 |
| 兼容性要求（插件/服务必须新内核） | 更新中心标「兼容所需」；用户确认后才进入安装流程 |
| 安全修复（清单标记 severity=security） | 首页黄色提示一次（不强制） |
| 用户点击「更新内核」 | 检查：无运行任务/实时会话；快照；安装；健康检查；失败回滚 |
| 内核版本低于要求且用户拒绝更新 | 对应插件/服务不允许安装（提示原因），其余功能不受影响 |
| 强制场景 | 无（【决策】不做强制更新闸门；仅当旧内核无法运行新协议时提示「不兼容」） |

兼容矩阵维护在 ams-release/compat.json（内核版本 × 插件 API × 服务版本 × 网关版本），随清单下发；启动器缓存矩阵用于离线求解。

### 6.11 插件/服务与内核版本依赖
- 插件 package 的 ams.engines 声明 {ams, kernel, services}；启动器读插件 manifest 与清单 requires 双重校验。
- 服务声明的运行时约束（Python 版本、torch/CUDA 版本）由启动器在安装前检查环境（§3.1 F-ENV-01），不满足则提示安装对应运行时组件或降级服务版本。
- 服务安装时记录 runtime 版本到 state.db，卸载/回滚时保留运行时（可能被其他服务共享）。
- 【决策】内核 API 采用语义化版本：kernel 0.3.x 提供 plugins_api 1.x；插件必须声明 kernel 区间；不满足时禁止安装。

### 6.12 并发与任务互斥【决策】
- 全局更新锁（文件锁 updates/.lock）：同一时刻只有一个更新批次在应用；下载可并行但「应用」串行。
- 与任务互斥：应用 kernel/gateway/service 更新前，查询 Gateway /jobs 是否存在 running/queued；实时变声会话视为运行中。存在则排队（提示「等待任务完成后应用」）或取消更新。
- plugin 热更允许在无对应插件任务时进行；失败自动回滚。
- 启动器自更新不与任何组件更新同批执行（单独事务）。

### 6.13 失败恢复与原子性
- 每个批次有 txid 与 journal（JSONL，fsync）在 updates/journal/；崩溃后启动器读 journal 恢复：继续/回滚/标记失败。
- 安装采用「新目录 + 切换指针」（junction/符号链接或 current.txt）实现近原子替换；Windows 上目录改名是原子的（同一卷）。
- 关键状态写入 SQLite 事务（update_history 与 component_state 同事务）；UI 以 DB 为准，不依赖内存状态。
- 断电/蓝屏后：启动器启动时做「一致性检查」（staging 残留、journal 未完成、当前版本哈希），必要时提示修复/回滚。

### 6.14 离线更新包（.amsupd）【决策】
结构（zip，不加密）：
~~~text
<name>.amsupd
├─ manifest.json              # schema=ams-update/1，channel 固定 offline，components 为包内组件
├─ manifest.sig               # Ed25519 签名（二进制 base64 或分离文件）
├─ packages/                  # 组件包原文件（gzip/tgz/zip/wheel/exe）
└─ README.txt                # 生成时间/来源/校验说明（人读）
~~~
- 导入流程：选择文件 → 校验 zip 完整性 → 验签 → 校验包内组件 sha256 → 显示可安装列表（含版本/大小/依赖）→ 用户勾选 → 走与在线相同的快照/应用/回滚流程。
- 导出：按当前已安装组件集合 + 通道生成离线包（dev/企业模式），不含用户资产。
- 离线包可含内核（体积允许时）；渠道标记 offline 不参与防降级检查（但仍校验版本与 min_launcher）。
- 【风险】离线包可被社会工程传播：README 与 UI 明示来源；导入时必须验签（无签名直接拒绝，dev 可临时允许但每次警告）。

### 6.15 更新中心 UI 流程（交互稿摘要）
1. 进入页面 → 自动检查（可关闭自动检查）→ 顶部通道切换 + 「检查更新」按钮。
2. 列表：组件名 / 当前版本 → 目标版本 / 类型图标 / 大小 / 依赖标记 / 说明展开 / 勾选框。
3. 底部操作栏：「全选可更新」「下载选中（n 个，xx MB）」「安装已下载」「稍后」；显示磁盘需空间。
4. 下载中：总进度 + 每项进度/速度/剩余时间；可暂停/取消单项。
5. 已下载：显示「安装」；应用前弹「变更摘要 + 快照说明 + 期间将暂停功能」。
6. 应用：逐项状态（准备/停止服务/替换/健康检查/完成）；失败项红色 + 「查看日志」「回滚」。
7. 完成后：摘要（成功/失败/回滚）+ 「重启内核」按钮（如需）；更新历史可查。
8. 回滚页：每个组件的历史版本（保留 90 天）+ 回滚按钮 + 影响说明。

### 6.16 更新系统风险与对策
| 风险 | 对策 |
|---|---|
| 供应链投毒（清单/包/镜像） | Ed25519 签名 + sha256 + 镜像同哈希 + CI 私钥隔离 + 发布审计 |
| 降级攻击（回到有漏洞版本） | 版本单调 + sequence + 禁降级（dev 显式） |
| 内核更新破坏插件 | 兼容矩阵 + 更新后健康检查 + 自动回滚 + 非必要不更新 |

| 时间/时区问题 | 以 sequence 为准，不使用本机时间做安全判断 |

## 7. MSVC 转换器（重点）

### 7.1 背景与格式摘要【事实，依据 05_新方案探讨/01_心月格式深拆/】
- MSVC（心月私有模型容器）文件结构：14 字节头（MSVC + 版本 01 00 + 标签 XINYU_AI）+ 3 条「u32 长度 + 整段字节反转 payload」记录 + 16 字节 trailer。
- 逻辑内容 = 4 份 metadata JSON（1692 B）+ 张量表 JSON（爱莉希雅样本 50,824 B）+ **明文 FP16 张量数据**（57,433,988 B）。
- 权重**未加密**（fp16 有效性实测 100%），仅做「反转 + 分片 + 分片重排」的容器混淆；张量表含 457 个张量的 key/dtype/shape/offset/length，与 RVC v2 SynthesizerTrnMs768NSFsid 完全对应。
- 已验证：转换出的 .pth 可被 RVC 运行时加载（unexpected=0，missing 仅 enc_q.*），并可跑通 infer()。详见 05 心月格式深拆/报告.md §0、格式.md §1–3。
- **重要限制**：MSVC 只包含 pth 权重与元数据，**不包含 RVC 的 .index 检索文件**（index 用于检索增强，不在权重内）。因此转换输出只能是 .pth，index 缺失属于格式事实。

### 7.2 授权与合规边界【决策】
| 允许 | 禁止 |
|---|---|
| 用户在本机转换**自己合法拥有**的 .msvc 文件 → 标准 .pth，写入本机 voices | 应用内置/分发/上传任何心月权重或转换后的权重 |
| 展示来源说明与「需用户确认拥有权」勾选 | 自动扫描用户磁盘上的心月安装目录并批量转换（需用户显式选择路径） |
| 记录转换审计（时间/文件 hash/来源路径/结果） | 提供 .cyd 解密、绕过登录/授权、破解云端校验 |
| 转换失败时保留原文件与错误码 | 修改原文件、写入心月安装目录 |
- 首次使用转换器显示一次性合规提示（用户自有文件、不得再分发、音色可能涉及人格权/著作权）。
- 【风险】转换能力可能被视为规避第三方保护措施；产品文案只做「本地格式互操作/数据迁移」，并要求用户确认权利；法务评审列为 P0 前置【待定】。

### 7.3 转换算法步骤（实现规格）【决策】
1. **预检**：读取文件头 20 字节；校验 magic=MSVC、version=1、tag=XINYU_AI；文件大小 ≥ 1 MB；判断是否已是 .pth（PK 头）或其它格式；计算源文件 sha256 记录。
2. **解析记录**：从偏移 14 起循环：读 u32 len（LE）→ 取 payload → 反转 → 分类：
   - 记录 0（metadata）：解析 JSON，取 model_unique_code/model_id/sr/f0/version/tensor_count，校验 4 份一致。
   - 记录 1（256 KiB）：保留原样（未知用途，不参与转换；记录 hash 备查）。
   - 记录 2（主体）：反转后扫描 JSON 片段与数据片段（可打印率 + JSON 结构 + fp16 统计）。
3. **重建张量表**：按片段内 offset 递增关系拼接碎片；修正片段边界（数据/JSON 边界处的可打印污染字节，1–2 字节级）；解析为 457 项张量表并校验：
   - key 无重复、offset 严格递增、length = prod(shape)*2、max(offset+length) = 数据总长。
4. **抽取数据**：按片段类型取全部数据片段，总长必须等于 sum(length)（闭合校验）；否则拒绝（E5021）。
5. **分片顺序推断**：对数据片段做排列搜索（片段数 n ≤ 8 时穷举；更大时启发式），以「与已验证参考模型/统计指纹的相关性」评分，取最优排列（详见 §7.4）。
6. **组装 state_dict**：按张量表顺序切分数据，构造 fp16 张量（key→tensor），并组装 checkpoint：{weight: state_dict, config: 张量表 config, info, sr, f0, version}。
7. **写出 .pth**：按 torch.save（zip + pickle）结构写入目标文件（见 §7.5 的两种实现路径）；写临时文件 → 校验 → 原子重命名。
8. **验证与登记**：结构校验（§7.6）→ 可选加载/推理冒烟（需 RVC 运行时服务）→ 写 voices 目录 → 调 Gateway 登记 msvc.convert 任务结果（哈希/时长/警告）→ 返回结果。

### 7.4 分片顺序推断算法（关键难点）
- 输入：数据片段数组 D[0..n-1]（长度已知），张量表 offsets。
- 目标：求排列 P 使拼接后各张量的统计特征与参考分布最一致。
- 评分信号（按可靠性排序）：
  1. 张量边界一致性（硬约束）：部分张量长度/位置使片段边界必须落在指定张量内 → 剪枝。
  2. 统计指纹：对每个张量计算 std/mean/分位数，与参考模型（同 config 的标准 RVC v2 模型，或本机已有同架构音源）对应张量的 std 做对数相关；取排列中相关最高者。
  3. 结构指纹：emb_g 等尾部张量维度（spk_embed_dim）、norm 层 gamma 均值接近 1 等先验。
  4. 可选：加载验证（把候选 .pth 交给 RVC 服务分别加载，全部成功仅证明结构；推理冒烟输出合理性作为二次筛选）。
- 本机实证：爱莉希雅样本 5 个数据片段，5! = 120 排列，最优排列 corr=0.686（参考为不同训练模型，故非 0.95+）；大片段（57 MB）必然在前的强约束使搜索空间极小。
- 【风险】片段顺序推断是小概率误判点：爱莉希雅已验证（加载+推理成功），法国赌神/曼波Pro 需交叉验证（P0 验收项）。UI 对结果给出置信度（高/中/低）与「人工复核」入口。

### 7.5 输出规则（严格遵循 00 第 6 节）【决策】

**目录与命名**：
~~~text
AMS_HOME/voices/
└─ <名称>/                     # <名称> 默认取 metadata.model_id 或源文件名（sanitize）
   ├─ <名称>.pth               # 必须：RVC v2 推理可加载
   └─ <名称>.index             # MSVC 无 index → 不生成
~~~
- 名称规则：去掉 Windows 非法字符 \ / : * ? " < > | 与首尾空格；保留中文；冲突时提示改名（默认追加 _2）。
- **index 说明**：MSVC 容器只含 pth 权重/元数据，**不含检索 index**。转换器不生成、不伪造 index；转换结果在 UI/清单中标注「无检索增强（index_rate=0）」，并提示：
  - 若用户另有该音色的 .index 文件，可手动放到同名路径（voices/<名称>/<名称>.index）；转换器提供「一并放入已有 index」选择（用户显式选择，校验维度 v2=768）。
  - 不自动扫描/复制心月安装目录中的 index（若存在也属于用户自行决定）。
- 旁车（可选）：voice.json {source:"msvc", source_sha256, converted_at, tool_version, model_unique_code, sr, f0, version, warnings[], index:"none"}；删除不影响使用（00 第 6 节）。

**.pth 生成实现路径（二选一，M1 spike 决定）**：
| 路径 | 说明 | 优点 | 风险 |
|---|---|---|---|
| A. Rust 纯实现 | 按 torch.save 的 zip+pickle 结构直接写：zip 内 data.pkl（pickle 协议 2/3 子集：dict/str/tuple/bytes/tensor 描述）、data/0..N（raw fp16）、byteorder、version；zip64 按需 | 无 Python 依赖、快、离线可用 | 与 torch 版本兼容性需实测；pickle 细节风险（§5.3 风险） |
| B. 调用内置 Python | 启动器把「张量表+数据」写入临时中间格式（如 .npz/自定义 bin），调用 AMS 服务侧 Python（torch）生成 .pth | 兼容性最好（torch 官方序列化） | 依赖服务运行时；转换慢；需确保不引入心月代码（只用 torch） |
【决策】优先 A（M1 spike 通过标准 RVC 运行时加载验证）；不通过则回退 B。两条路径都只产出标准 pth，不含任何心月代码/密钥。

### 7.6 验证策略【决策】
| 级别 | 检查 | 通过标准 |
|---|---|---|
| L1 结构 | 解析完整性：457 张量、key 集合、shape、length、offset 递增、数据闭合 | 全部通过，否则拒绝输出 |
| L2 格式 | 生成 .pth 可被 torch.load（RVC 服务侧）读取；zip 结构/字节序 | 读取成功，张量数量与 dtype 一致 |
| L3 加载 | RVC v2 SynthesizerTrnMs768NSFsid 加载：unexpected=0，missing 仅在 enc_q.*（正常） | 通过 |
| L4 推理冒烟 | 随机输入 infer() 输出有限、时长正确、幅度在合理范围（非 NaN/静音/削波） | 通过；异常则标记「需人工复核」 |
| L5 记录 | 源/目标 sha256、张量数量、排序排列、评分、耗时、工具版本写入审计 | 可追溯 |
- L3/L4 需要 RVC 服务或内置轻量校验器；若服务未安装，允许仅 L1/L2 并标「未运行时验证」。

### 7.7 性能与批处理
| 项 | 指标 |
|---|---|
| 单文件解析（57 MB） | < 3 s（Rust，SSD；含 JSON 拼接与顺序搜索） |
| 单文件写出 | < 2 s（路径 A）；< 10 s（路径 B，含 Python 启动） |
| 内存峰值 | < 200 MB（流式读数据片段，避免整文件多副本） |
| 批量 | 队列串行（默认）或并发 2；进度事件 per-file；失败继续其余文件并生成汇总 |
| 大文件保护 | > 2 GB 拒绝（MSVC 现实规模 ~55–60 MB）；磁盘预检 |

| R5 | MSVC 转换的合规争议 | 法务/品牌风险 | 仅本地用户文件、权利确认、不提供解密；法务评审前置 |
| R6 | 更新基建（清单/镜像/证书/密钥）运维成本 | 更新不可用/被劫持 | 清单仓库自动化、镜像同哈希、密钥管理流程、演练 |
| R7 | WebView2/VC++/驱动环境差异 | 启动失败 | 安装包前置检查 + 引导安装；降级提示；诊断包 |
| R8 | GPU 运行时（CUDA 版本）碎片化 | 服务安装失败 | 环境检测+运行时组件化+版本矩阵；CPU/DirectML 降级 |
| R9 | 大文件下载/磁盘占用 | 用户体验 | 断点、预检、清理工具、可选镜像 |
| R10 | 启动器与内核/网关三套状态不一致 | 状态错乱 | 单一权威（DB/Gateway）+ 一致性检查 + 事件驱动 |
| R11 | 用户误操作（卸载内核/覆盖音色） | 数据损失 | 二次确认 + 快照/回收站 + 保留配置选项 |
| R12 | 无遥测导致问题定位难 | 支持成本 | 诊断包 + 用户主动反馈；日志足够详细且脱敏 |
