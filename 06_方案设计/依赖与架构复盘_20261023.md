# AMS 依赖与整体架构复盘（2026-10-23）

> 性质：只读复盘 + 目标方案，不改代码。
> 目的：回答软件依赖什么、应该装在哪里、空系统能否自动装好、环境检测为什么乱/为什么 Node、FFmpeg 显示未安装。

## 0. 结论摘要

1. 当前安装能跑，但不是可分发形态：内核、插件、Gateway 已自带运行时；RVC、pymss、MSVC 仍指向 F:\ai歌曲 和源码工程目录。
2. 原方案要求空系统可安装：00 总体设计明确不依赖用户已安装 DSH，也不依赖系统 Python、Node、CUDA；每个后端独立便携运行时。M2 完成报告也明确写了 portable runtime 暂缓到 M3。当前版本仍是 M2 开发路径。
3. 用户最新要求的所有东西在 data 下应作为新硬约束：所有 AMS 管理的程序、运行时、模型、资产、日志、配置都放安装目录内；外部只允许用户导入的素材，且默认复制到 data/projects。
4. Node.js、FFmpeg 显示未安装的结论：
   - Node.js 对安装后的 AMS 不是必需。内核包内已有 node.exe（约 93.5MB），插件安装由内核自带 DSH CLI 完成；系统 Node 只用于开发构建。
   - FFmpeg 是 RVC、音频处理的真实依赖。当前 RVC 整合包内带 ffmpeg；空系统没有系统 ffmpeg 且 runtime 未带时，RVC 会失败。必须把 ffmpeg 作为受管工具放进 data。
5. 环境检测乱码是启动器调用 PowerShell 的编码 bug，不是字体问题：hidden_command 配合 CREATE_NO_WINDOW 时，Windows PowerShell 5.1 把中文按 GBK/ANSI 输出，Rust 按 UTF-8 解码，得到乱码。

## 3. 当前架构与代码逻辑

当前进程和调用链：

~~~text
AMS Launcher (Tauri/Rust/Vue)
  -> 组件安装: data/components/<id>
  -> 启动 AMS Kernel: data/kernel/AMS Kernel.exe
       -> DSH host (内置 Node/Python)
            -> @ams/plugin-core -> /ams/api/* -> Gateway
  -> 启动 Gateway: data/components/service.gateway/ams-gateway.exe
       -> RVC runner -> runtime.json 的 rvc_python/rvc_root（当前外部）
       -> pymss runner -> AMS_PYMSS_* 环境变量（当前为空或外部）
       -> MSVC runner -> AMS_MSVC_TOOL（当前为空或外部）
  -> 启动器配置: data/config/connection.json、runtime.json、state.db
~~~

关键代码事实：

- start_gateway 从 data/config/runtime.json 读取 RVC 路径并注入子进程环境。
- runtime.json 当前内容指向 F:\ai歌曲\RVC20260311。
- Gateway 的 rvc_convert.py 已支持自定义音源路径；公开组件曾缺少 weight_root 修复，现已重新打包为 service-gateway-0.1.0-fixed.zip。
- AMS_PYMSS_*、AMS_MSVC_TOOL 仍只有环境变量入口，启动器没有对应 UI 或配置项。
- get_environment 用系统 PATH 检查 node.exe、ffmpeg.exe、py.exe，没有检查内核内置 Node、Gateway 内置 Python、RVC 自带 ffmpeg。

## 4. 环境检测问题

### 4.1 乱码

实测：powershell.exe 在 CREATE_NO_WINDOW 和重定向 stdout 时输出中文为 GBK/ANSI 字节（例如专业版为 D7 A8 D2 B5 B0 E6），但 run_ps 用 String::from_utf8_lossy 按 UTF-8 解码，于是显示乱码。

- 影响：Windows 版本、磁盘或路径里含中文时可能乱码；英文和数字项正常。
- 修法：在每条 PowerShell 脚本前设置 [Console]::OutputEncoding=[System.Text.UTF8Encoding]::new(); $OutputEncoding=[Console]::OutputEncoding，或改用原生 Windows API 和显式编码读取；不要只靠 from_utf8_lossy。
- 这也说明环境探测不应通过拼接大量 PowerShell 文本来做；应逐步替换成结构化原生探测。

### 4.2 Node.js 未安装：不影响运行

- 内核包内已有 Node 24.21：data/kernel/resources/runtime/primary-runtime/dependencies/node/bin/node.exe。
- 插件安装调用内核自带 DSH CLI，不需要系统 Node。
- 系统 Node 只用于开发构建（pnpm workspace）。
- 所以环境页把 Node.js 标成未安装是误导，应显示内核内置 Node 24.21 和开发工具未安装。

### 4.3 FFmpeg 未安装：有影响，必须受管

- RVC 换声的音频解码和重采样依赖 ffmpeg；当前 RVC 整合包自带 ffmpeg.exe。
- 如果空系统没有 ffmpeg，且 RVC runtime 包里没带 ffmpeg，convert.rvc 会失败。
- 正确做法：新增 tool.ffmpeg 组件，装到 data/tools/ffmpeg/<ver>/bin，Gateway 和 RVC 子进程显式使用该路径；不依赖系统 PATH。

### 4.4 Python 和 Git：不是运行时硬依赖

- Gateway 是 PyInstaller，自带 Python 3.12；系统 Python 不是必需。
- RVC 和 pymss 需要各自的受管 Python 运行时，不应让用户自己安装。
- Git 只在更新和开发时用，不是运行必需；环境页可标可选。

## 5. 目标结构（建议作为 v1.3 基准）

### 5.1 安装根

~~~text
F:\AMS-Studio\                          安装根（可在任意盘）
  ams-launcher.exe
  uninstall.exe
  data\                                 所有 AMS 托管数据和运行时
    config\                             connection、runtime、state.db
    kernel\                            Electron、DSH、内置 Node/Python
    components\                        已下载组件包缓存和解包区
    runtime\
      rvc\<version>\                   Python、torch、HuBERT、RMVPE、ffmpeg
      pymss\<version>\                 Python、torch、models
      tts\<version>\                   后续 GPT-SoVITS 或 Qwen
    tools\ffmpeg\<version>\bin\       受管 ffmpeg 和 ffprobe
    models\                            基础模型和索引缓存
    voices\                            音源库
    assets\                            默认曼波等内置资产包
    projects\                          用户工程（素材导入后复制到此处）
    artifacts\
    runtime\ports.json、gateway.token
    logs\
~~~

规则：路径全部由 launcher 通过相对路径解析；任何可执行文件、Python、torch、ffmpeg、模型、音源、插件、日志、缓存都不允许指到安装根之外。用户选择的原始素材默认导入到 data/projects；如果保留只读外链，需要显式标注外部输入，不能作为产品依赖。

### 5.3 空系统安装顺序

1. 启动器安装（检测 WebView2 和 VC++；缺失则引导安装器）。
2. 硬件、磁盘、驱动检测；NVIDIA 驱动缺失只提示，不静默装。
3. 选安装根（默认 F 盘或用户选择；全部数据在安装根的 data 下）。
4. 安装 kernel、gateway、plugin（可离线组件包）。
5. 安装 runtime.rvc 和 tool.ffmpeg；再扫描曼波资产。
6. 安装 runtime.pymss（按需；体积大）。
7. 首启检查：内核 HTTP 200、Gateway health、插件页面、音源扫描、RVC 冒烟。

## 6. 空系统测试清单

- 干净 Windows VM，无 Python、Node、ffmpeg、Git、CUDA toolkit（仅 NVIDIA 驱动）。
- 安装启动器到 F 盘；启动后环境页不应因 Node、系统 Python、系统 ffmpeg 缺失而阻断。
- 组件安装后检查：kernel Node、gateway Python、RVC runtime、ffmpeg 都在 data 内；无外部路径引用。
- 断网：已安装组件仍可启动；安装缺失组件时提示离线包。
- RVC、pymss、TTS 冒烟；RVC 至少 5 秒样例；产物在 data/artifacts。
- 卸载：只删除安装根内 AMS；外部无写入（注册表、快捷方式除外）。
