### 2.4 关键发现：faiss index 在非 ASCII 路径下静默失效（【事实】）

- 现象：RVC runtime 的 faiss（Windows AVX2 wheel）**无法打开含中文的路径**：`faiss.read_index("F:\ai歌曲\...\manbo.index")` → `RuntimeError: ... could not open ... No such file or directory`；RVC `pipeline.py` 第 309-315 行 `try: faiss.read_index(...) except: traceback.print_exc(); index = big_npy = None` → **index 被静默忽略，index_rate 不生效**。
- 判定：不是文件损坏——用 `faiss.deserialize_index(np.frombuffer(open(path,'rb').read(), dtype=np.uint8))` 成功解析出 ntotal=44,750 / d=768；用 `subst X:` 映射为纯 ASCII 盘符后 `faiss.read_index("X:\\work\\manbo.index")` 也成功。
- 影响：00 §6 规定 voices 文件夹名允许中文（如“曼波”），因此**产品 Runner 不能直接依赖 RVC 原生路径加载 index**。
- 采用方案（已在 `rvc_smoke.py` 实现并验证 fallback_used=1）：monkeypatch `faiss.read_index` → 失败时 Python 读字节 + `faiss.deserialize_index`。备选方案：① 把 index 复制/链接到纯 ASCII 缓存路径；② 进程启动时用 subst/短路径映射。三种方案均记录在 `experiments/README.md`。

### 2.5 其它 RVC 集成注意点（【事实】/【推断】）

| 注意点 | 说明 |
|---|---|
| cwd 必须是 RVC 根目录 | `.env`、`assets/weights`、`assets/hubert`、`assets/rmvpe`、`ffmpeg.exe` 均按相对路径解析 |
| .env 需显式路径 | python-dotenv 的 `find_dotenv()` 在脚本模式下会从脚本所在目录向上找；需 `load_dotenv(dotenv_path=RVC_ROOT/".env")` |
| 模型名必须是 `<name>.pth` | `get_vc` 直接拼 `weight_root/sid` |
| index 自动发现不可靠 | `get_index_path_from_model` 只在 `index_root=logs` 目录里找；需传显式 `--index` |
| sid 是 int | `vc_single` 第一参数是说话人 id（0），不是模型名 |
| 输出是 int16 | pipeline 末尾 `*32768 → int16`；写文件前必须 /32768 归一为 float，否则会当作 int 值直接写导致爆音（本脚本已处理） |

| 4 轨 XL（不建议 12GB） | `mel_band_roformer_4stems_xl_ver1`（6.1GB） | 1 | 减 chunk 至 50%，overlap 5% | **10–15GB**（风险） | 12GB 大概率 OOM，改用 SCNet |
| 单乐器 mega-53 | `bs_mega_53stem_*`（74MB/个） | 1–2 | 默认 | 2–3GB | 一次一个模型 |

**通用规则**：默认 `batch_size=1`；OOM 时按「batch→chunk×0.75→overlap×0.5→关 TTA→换轻模型→CPU」降级（与插件方案 §9.2 一致）；启用 `torch.cuda.max_memory_allocated` 上报显存峰值到任务产物。

## 5. 接入 Gateway Runner 的接口建议

> Gateway MVP 已有 `RunnerRegistry.register(type, factory, gpu=...)` 注册点（`08_项目代码/ams-services/gateway/app/jobs/runner.py`）。建议分别新增两个服务进程；Runner 以子进程/JSONL 或 HTTP 调用后端，进度与取消由 Gateway 统一管理。

### 5.1 `convert.rvc`（RVC 换声，GPU 串行）

| 项 | 建议 |
|---|---|
| 参数（params） | `{input_path, model_name:"manbo.pth" 或 voice_id 映射, index_path?:string, f0_method:"rmvpe", f0up_key:int, index_rate:0..1, protect:0..1, rms_mix_rate:0..1, filter_radius:0..7, resample_sr:0|16000..48000, is_half:bool, device:"cuda:0"|"cpu", output_format:"wav", wav_bit_depth:"PCM_24"}` |
| 进程要求 | 用 RVC 自带 runtime（Python 3.9）；**cwd=RVC 根目录**；env：`weight_root/index_root/rmvpe_root/outside_index_root`（或显式 dotenv 路径）；`PYTHONDONTWRITEBYTECODE=1`；TMP/TEMP 指向 AMS_HOME/cache |
| 关键补丁 | **faiss 非 ASCII 兼容**：启动时 monkeypatch `faiss.read_index`（失败→读字节+`deserialize_index`），否则中文 voices 路径下 index 静默失效（§2.4） |
| 进度 | RVC 无进度回调：按阶段映射 load_model 5% → preprocess/npy 15% → f0 40% → infer 40–90%（按音频长度估算）→ save 100%；产物 JSON 写入实测 `npy/f0/infer` 秒数 |

| GPU | 注册 `gpu=True`；实测显存需求 ~1.3GB，12GB 下可与其它小模型共享，但按 Gateway GPU 锁串行 |

### 5.2 `separate.pymss`（pymss 分离，GPU/CPU）

| 项 | 建议 |
|---|---|
| 参数（params） | `{model:string, inputs:string[], stems?:string[], inference_params:{batch_size,chunk_size,overlap_size,use_tta,standardize,normalize}, output_format, target_sample_rate?, device:"auto"|"cuda"|"cpu", model_dir, download_missing:bool, source:"modelscope"|"huggingface"|"hf-mirror", auto_degrade:bool}` |

| 进度 | 用 pymss `progress_callback(done_seconds,total_seconds,message)` → Job progress%；保存阶段单独上报；产物事件含每 stem 路径/采样率/时长 |
| 取消 | 默认「杀服务进程树+重启」（M0）；M1 改为任务级子进程隔离（与插件方案 §9.1 一致） |

| 产物 | 每 stem wav/flac/mp3/m4a + `manifest.json`（模型/参数/rtf/vram 峰值/输入 sha256），路径 `projects/<id>/stems/<stem>/` |
| GPU/CPU | `device=auto`：有 CUDA 用 GPU（`gpu=True`；实测 SCNet RTF 0.03–0.08、BSR 0.06–0.28，较 CPU 快 7–35×）；无则 CPU 降级。`vram_estimate_mb` 按模型+chunk 估算：SCNet≈5.5GB、BSR 默认≈9.3GB、BSR chunk240k≈2.6GB（§8.5） |

### 5.3 公共建议

1. **后端服务独立运行时**（00 §3）：RVC 服务（py3.9）与 pymss 服务（py3.12）各一个进程，互不污染。
2. **产物 meta 统一字段**：`engine{name,version,torch,device}`、`timings{load,infer,rtf}`、`vram_peak_mb`、`params`、`warnings[]`（含 index fallback）。
3. **路径兼容**：RVC 相关产物/索引路径优先放纯 ASCII 缓存目录（或用 deserialize 补丁）；pymss 对路径无此限制。
4. **GPU 锁**：两个任务类型都属显存型，统一走 Gateway GPU 队列；实测 RVC 1.3GB / pymss（GPU 待测）可据此设置显存预估字段 `vram_estimate_mb`。
5. **日志脱敏**：本次实验日志含用户本地路径，接入后按 00 §12 脱敏。

### 8.2 SCNet 4 轨（40MB）：CPU vs GPU

输入：20.00s / 44.1kHz 立体声（同 §3 的 `input_music_20s.wav`）；模型 `scnet_checkpoint_musdb18`（42.4MB）；batch=1 除特别注明。

| 设备 / 场景 | batch | 墙钟（进程） | pymss RTF | 显存峰值 alloc / reserved | 进程峰值工作集 | CPU 时间 / 核比 |
|---|---|---:|---:|---:|---:|---:|
| CPU（task-21 run6） | 1 | **19.75s** | **0.50** | — | 928MB | 220.4s / 11.2 |
| GPU 冷进程 | 1 | **5.64s** | **0.06** | **5,425 / 5,572MB** | 1,664MB | 2.56s / 0.45 |
| GPU 同进程第 2 次（热） | 1 | 5.03s | **0.03** | 491 / 576MB（分配器复用） | 1,688MB | 1.34s / 0.27 |
| GPU 冷进程 | 2 | 5.26s | 0.05 | 5,555 / 5,828MB | 1,678MB | 0.37 |
| GPU 冷进程 | 4 | 5.75s | 0.08 | 5,811 / 6,040MB | 1,683MB | 0.55 |

**结论**：
- 端到端 **19.75s → 5.6s（≈3.5×）**；推理 RTF **0.50 → 0.03–0.06（约 8–16×）**；
- 冷进程显存 5.4–6.0GB 主要是 **CUDA context + cuDNN workspace + PyTorch 缓存分配器**（模型仅 42MB），batch 1/2/4 显存仅差 ~0.4GB；同进程热跑时 allocator 复用，增量峰值仅 491MB；
- 输出：`验证/audio/pymss_scnet_20s_gpu/`（4 stems）+ b1/b2/b4 对比目录。

### 8.3 BSR HyperACE（275MB，人声/伴奏）：CPU vs GPU

模型 `bs_roformer_voc_hyperacev2`（289MB 下载 80.6s，hf-mirror）；输入同上 20s。

| 设备 / 场景 | batch | chunk / overlap | 墙钟 | RTF | 显存峰值 alloc / reserved | 进程峰值工作集 | CPU 时间 / 核比 |
|---|---|---:|---|---:|---:|---:|---:|
| CPU 冷进程 | 1 | 默认 480000 / 24000 | **50.63s** | **2.11** | — | 3,179MB | 887.2s / 17.5 |
| GPU 冷进程 | 1 | 默认 480000 / 24000 | **10.15s** | **0.28** | **9,226 / 9,300MB** | 2,257MB | 6.9s / 0.68 |
| GPU 同进程第 2 次（热） | 1 | 默认 | 3.65s | 0.06 | 1,457 / 1,774MB | 2,257MB | 1.0s / 0.27 |
| GPU 冷进程 | 1 | **240000 / 12000** | **6.27s** | **0.15** | **2,617 / 2,640MB** | 2,097MB | 3.6s / 0.57 |

**结论**：
- CPU→GPU 端到端 **50.6s → 10.2s（冷，≈5×）→ 3.65s（热，≈13.9×）**；RTF **2.11 → 0.28（冷）/0.06（热）**；

- 输出 2 stems（vocals + instrument）：`验证/audio/pymss_bsr_20s_gpu/`、`pymss_bsr_20s_gpu_smallchunk/`、`pymss_bsr_20s_cpu/`。

### 8.4 CPU/GPU 输出一致性

| 对比 | stem 数 | corr 最小 / 平均 | max abs diff | 时长差 |
|---|---:|---|---:|---:|
| SCNet CPU vs GPU(batch1) | 4 | **0.999136 / 0.999784** | 2.42e-4 | 0ms |
| SCNet CPU vs GPU(batch4) | 4 | **0.999125 / 0.999781** | 2.55e-4 | 0ms |
| BSR CPU vs GPU(batch1) | 2 | **0.999980 / 0.999983** | 2.08e-3 | 0ms |

**结论**：GPU 与 CPU 输出在数值上几乎一致（相关性 ≥0.9991、时长完全一致），差异来自 FP16/批次/浮点累加；**GPU 不改变分离结果语义**，可放心作为默认路径。drums 轨因能量极低（rms≈8.9e-05），相关性略低但绝对差 <4e-5。

### 8.5 12GB 参数结论（GPU 实测回填）

| 模型 | batch | chunk / overlap | GPU 显存峰值（冷） | GPU RTF | 12GB 建议 |
|---|---:|---|---:|---:|---|
| `scnet_checkpoint_musdb18`（40MB） | 1 | 485100 / 363825（默认） | **5.4–6.0GB** | 0.03–0.08 | ✅ 默认可用 |
| `bs_roformer_voc_hyperacev2`（275MB） | 1 | 480000 / 24000（默认） | **9.3GB** | 0.28 | ⚠️ 偏紧：**建议 chunk 240000 / overlap 12000 → 2.6GB、RTF 0.15** |
| BSR 其它变体（610MB viperx 等） | 1 | 参考上条降 chunk | 估计 8–11GB | — | 建议 chunk ≤240k 并开自动降级 |
| Mel-Band / 4stems XL（0.9–6.1GB） | 1 | 默认降到 50–70% | 估计 10–15GB | — | 12GB 不建议；用 SCNet 4 轨替代 |
| HTDemucs 4/6 轨（52–80MB） | 1 | 默认 | 估计 3–5GB | — | 可跑（未实测） |

**通用建议**：
1. **默认 batch=1**；SCNet 可 batch 2–4（显存仅 +0.4GB，收益不明显）。
2. 服务启动设置 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`，降低碎片与 OOM 概率。
3. 冷启动显存包含 CUDA context/cuDNN workspace；**长驻服务只常驻 1 个模型**，避免 BSR 默认 chunk 与其它模型共存。
4. 输入长音频时按总时长预计显存（分块数增加主要影响速度，不线性增加显存）。
5. OOM 降级顺序保持：batch=1 → chunk×0.75 → overlap×0.5 → 关 TTA → 换轻模型（SCNet/HTDemucs）→ CPU。
