# MSVC / XINYU_AI 模型容器格式规范（逆向结果 v1.0）

- 分析对象：`F:\ai配音\心月-变声器\心月变声\_internal\modules\爱莉希雅\爱莉希雅.msvc`（57,748,698 B）
- 对照样本：`法国赌神.msvc`（55,389,446 B）、`曼波Pro\苏苏.msvc`（57,748,717 B）
- 结论标记：【事实】= 实测/解析；【推断】= 基于证据判断

## 1. 顶层结构

```
[14B 文件头][记录0][记录1][记录2][16B 尾部 trailer]
每记录 = u32 little-endian 长度 + payload（payload 按整段字节反转存储）
```

### 1.1 文件头（14 字节）【事实】
| 偏移 | 长度 | 内容 | 值 |
|---|---|---|---|
| 0 | 4 | magic | `MSVC` (4D 53 56 43) |
| 4 | 2 | 版本 | `01 00`（u16 LE = 1） |
| 6 | 8 | 品牌标签 | `XINYU_AI` |

### 1.2 记录区【事实】
| # | 偏移 | u32 长度 | 内容（反转还原后） |

| R0 | 14 | 1692 | metadata JSON **×4 份**（每份 423 B；还原后为 4 份完全相同的 forward JSON）。对应 1692=4×423 |
| R1 | 1710 | 262,144 (256 KiB) | 未确认块：payload 全段二进制，fp16 可信度≈0.57（随机/混合水平），既不是 metadata 也不是 JSON；【推断】保留块/索引/校验块或另一种编码块 |

## 2. 逻辑内容（还原后）

```
[metadata JSON ×4 : 1692 B][张量表 JSON : 50,824 B][FP16 张量数据 : 57,433,988 B]
```

- 数据总长【事实】：sum(tensor.length) = 57,433,988 = 物理数据分片总长（逐字节闭合），因此数据区**无缺失、无额外加密膨胀**。

### 2.1 metadata JSON（423 B/份，共 4 份）【事实】
```json
{"original_format":"rvc_private_runtime","storage_mode":"private_runtime",
 "runtime_format":"RVC_PRV1","encryption_level":"enhanced",
 "timestamp":<unix>,"checksum":"<sha256>","size":<int>,"version":"v2",
 "sr":"48k","f0":1,"tensor_count":457,
 "model_unique_code":"<uuid>","model_id":"<中文名>"}
```
- `size` = 57,516,040（【推断】原始 plain .pth 字节数；与 torch 版本相关，未经原文件验证）
- `checksum` = sha256（【推断】原始 plain .pth 或权重数据的校验；未取得原文件，未能复验）
- 4 份重复【推断】为冗余/防截断标记，读取端可任取其一。

### 2.2 张量表 JSON（50,824 B）【事实】
```json
{"runtime_format":"RVC_PRV1",
 "config":[1025,32,192,192,768,2,6,3,0,"1",[3,7,11],[[1,3,5],[1,3,5],[1,3,5]],
           [12,10,2,2],512,[24,20,4,4],109,256,48000],
 "f0":1,"version":"v2","info":"alxy","sr":"48k",
 "model_unique_code":"<uuid>","spk_embed_dim":109,
 "tensors":[{"key":"enc_p.emb_phone.weight","dtype":"float16","shape":[192,768],
             "offset":0,"length":294912}, ... 共 457 项]}
```
- `config` = RVC v2 `SynthesizerTrnMs768NSFsid` 构造函数参数（18 项，含 spk_embed_dim=109、sr=48000）【事实：与开源 RVC 代码构造签名一致】
- `tensors` 按 `offset` 严格递增排序【事实】
- dtype 全部 `float16`；`length = prod(shape)*2` 全部 457 项通过校验【事实】

### 2.3 FP16 张量数据【事实/部分推断】
- 编码：little-endian IEEE754 half（`float16`），明文，**未加密、未 XOR、未量化压缩**：
  - 大块数据（57,428,987 B，占 99.99%）按 fp16 解释，有限且 |v|<10 的比例 = **1.0**（随机字节仅 ~0.54）
  - 高字节分布集中在 0x2C/0xAC/0x2D/0xAD/0xA8（fp16 小幅值典型），符合神经网络权重
- 物理分片【事实】：R2 反转后为 10 段 "JSON 碎片/数据片段" 交错：
  | 段 | 类型 | 长度 |
  |---|---|---|
  | P0 | JSON 碎片 | 500 |
  | D0 | 数据 | 2,508 |
  | P1 | JSON 碎片（文档首） | 994 |
  | D1 | 数据 | 997 |
  | P2 | JSON 碎片 | 45,833 |
  | D2 | 数据 | 57,428,987 |
  | P3 | JSON 碎片 | 1,002 |
  | D3 | 数据 | 999 |
  | P4 | JSON 碎片（文档尾） | 2,501 |
  | D4 | 数据 | 497（原始 run 499，修正 2B 边界污染） |
- 分片顺序【事实/推断】：数据片段的**逻辑顺序与物理顺序不同**，本报告用统计相似度搜索（与开源 RVC 爱莉希雅.pth 逐张量 std 的对数相关）确定最佳排列为 **(D2,D4,D0,D1,D3)**（相关 0.686，参考为不同训练模型故非 1.0）；该顺序下 457 张量全部落位且推理成功。**小分片顺序的置信度中等**（仅影响末尾少数张量，如 emb_g）。

## 3. 与 .pth 的关系
- .msvc = 私有重打包容器：把标准 RVC v2 inference .pth（含 `weight/config/info/sr/f0/version`）拆成 (元数据 + 张量表 + 明文 fp16 数据) 后，做 **整段反转 + 分片 + 分片重排** 的"增强"混淆；**没有对权重做密码学加密**。
- 转换等价性【事实】：还原后 `load_state_dict(strict=False)` → 0 unexpected keys，唯一 missing 为 103 个 `enc_q.*`（RVC 推理模型本就不含后验编码器），0.8 秒完成；随机输入 `infer()` 输出 1×1×48000 音频、数值有限（-0.338..0.373）→ **可加载、可推理**。

## 4. 与 .cyd / encrypted-pth 的区别（重要）
- `.cyd/.bgx/.json(加密)/.vclc.json`：magic + 高熵 AES/Fernet 级密文，**无密钥不可解**（见报告 §4）。
- `encrypted pth`（另一机制，来自客户端内嵌 Python 脚本字符串）【事实】：
  - 文件 = 加密数据 + 末尾追加身份牌 `b"XINYU_OFFICIAL_IDENTITY_CARD_2024"`
  - 解密函数：`infer.lib.encode.smart_pth_decrypt_data_with_identity(raw, path)` / 旧版 `smart_pth_decrypt_data(raw)`
- `.msvc`（本文件）不需要上述函数，仅需容器解码 + fp16 还原（本文档）。
