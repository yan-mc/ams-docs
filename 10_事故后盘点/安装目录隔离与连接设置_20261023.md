# AMS 安装目录隔离与连接设置改造（2026-10-23）

## 结果

- 新安装目录：`F:\AMS-Studio`
- 所有 AMS 数据：`F:\AMS-Studio\data`（旧 `F:\AMS-Studio-Data` 已无）
- 旧安装 `F:\AMS Studio` 已移除；旧数据整体移到 `F:\AMS-Studio\data\_legacy-20261023` 保留取证
- 用户/系统环境变量中没有 `AMS_HOME`、`AMS_RVC_*`、`AMS_PYMSS_*`、`AMS_MSVC_TOOL`
- AMS Kernel 从自身 `AMS Kernel.exe` 所在位置推导 `data`，不再读 `AMS_HOME`
- 插件 core 从 `DSH_HOME` 推导 AMS 数据根，不再回退到 `%LOCALAPPDATA%\AMS`
- 启动器按安装目录识别数据，不再持久写环境变量

## 登录/引导

- DSH welcome window 被移除：`amsKernelMode = true`，直接进工作区
- profile 禁用 `ui-settings-account`、`ui-settings`、`llm-deepseek-account`
- 页面 boot graph 不再包含 welcome；标题为 `AMS Kernel`
- 启动器新增“连接设置”，只有两个输入：
  1. 网址（baseURL）
  2. Key（API Key）
- 保存后写 `data\config\connection.json`、`data\kernel\dsh\.credentials.yaml` 和 profile patch；不使用环境变量

## 实测

- 内核页面：HTTP 200，`<title>AMS Kernel</title>`，`plugin=True`，`welcome=False`
- `/ams/api/session`：HTTP 200
- 插件包：`@ams/plugin-core`、`@ams/plugin-ui`、`@ams/music-bundle` 已在新 profile
- C 盘 `AMS` / `AMS Studio` 数据目录不存在
- 当前 DSH 的 `.dsh` 与 AMS 数据完全分离；AMS 新进程路径均在 F 安装目录内

## 剩余

- Gateway 组件启动/健康检查仍需在 F 安装目录内复测。
- 插件侧栏的实际点击回归（用户已观察到侧栏出现，当前 boot graph 也已加载）。
- 成功保存连接设置后需要重启 AMS Kernel 使 provider patch 生效。
