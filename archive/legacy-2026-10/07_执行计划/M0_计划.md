# M0 执行计划（技术验证 + 工程骨架）

> 版本：v1.0（2026-10-19）｜基于 `06_方案设计`（00 v1.2）
> 目标：在投入正式开发前，用 2–3 周验证所有高风险假设、打通最小闭环、建立仓库与构建/更新基础设施。

## 1. 范围

**做**：环境工具链、Git/仓库骨架、DSH fork 构建、Tauri 启动器骨架、Gateway MVP、音色库+默认曼波、MSVC 转换器收尾、DSH 音乐插件最小闭环、RVC/pymss 冒烟、更新清单签名工具。
**不做**：完整 UI、全部插件、实时变声音频服务、训练/分离产品化、安装包签名发布（放到 M1+）。

## 3. 任务分解

### M0.0 环境与账号（0.5 天）
- 安装 Node 24 / pnpm / Rust+MSVC / uv / ffmpeg /（可选 gh）。
- `git config --global user.name/email`；确认 GitHub 登录。
- 在 `github.com/yan-mc` 创建 6 个私有空仓：`ams-launcher`、`ams-harness`、`ams-plugins`、`ams-services`、`ams-release`、`ams-docs`。
- 验收：`node -v`/`pnpm -v`/`rustc -V`/`uv --version`/`ffmpeg -version` 全部正常；`git ls-remote` 可达。

### M0.1 DSH fork 与构建（2–3 天）
- fork/clone `deepseek-ai/deepseek-harness` 到 `ams-harness`；保留 upstream remote；锁定 0.2.1-rc.2。
- 建立 `branding/` 与 `patches/`：productName/appId/icon/protocol/更新源/telemetry 关闭/裁剪清单；只改配置与构建脚本。
- 跑通 `pnpm install`、`pnpm run build`、`pnpm dsh web`。
- 验收：本地 Web 可打开；`session-log-deepseek`/OTel 不生效；内核 ASAR 不含任何音乐业务代码。

### M0.2 启动器骨架（2–3 天）
- `create-tauri-app`（Vue3+TS）；实现：首启页、环境检测（GPU/磁盘/Python 组件）、组件状态、更新中心（假数据）、启动/停止内核占位。
- 与内核启动契约：env 注入 `AMS_HOME`/Gateway URL/token/版本；健康检查；退出清理。
- 验收：可打包未签名 exe；能检测/展示环境；能拉起一个占位进程并回收。

### M0.3 Gateway MVP（3–4 天）
- `ams-services/gateway`：FastAPI + SQLite + job 状态机 + SSE + token 鉴权 + 日志。
- 任务类型先支持 `ping` 与 `mock.long`；GPU 锁字段；取消杀进程树（mock 用 sleep 子进程）。
- `/voices/scan` 先返回目录与 pth 基础元数据（调用 `ams-tools` 的读取器）。
- 验收：curl/单测覆盖创建→SSE→完成/取消；重启后历史可查。

### M0.4 音色库 + 默认曼波（2 天）
- 实现 `voices/` 扫描器：校验命名、pth/index 同名、重复/损坏；解析 pth 的 info/sr/f0/version（用 RVC runtime 子进程）。
- 首次启动把 `assets/voices/manbo.zip` 解到 `voices/曼波/`（安装包内置；不进 Git）；校验 hash。
- 页面/CLI 展示音色列表；默认音色选中曼波。
- 验收：本机曼波 pth+index 可被识别；伪造/缺 index 的目录给出明确提示。

### M0.5 MSVC 转换器收尾（2–3 天）
- 已完成：容器/TLV/反转、张量表通用拼接、键集校验、爱莉希雅转换 + RVC 推理 PASS。
- 待完成：40k 两个模型的数据分片边界校准（用参考模型 log-std 相关 + 边界小范围搜索）；把校准结果固化为算法。
- 输出 UI/CLI 契约：启动器页面“选择 .msvc → 选择输出目录 → 转换 → 校验 → 写入 voices/<名称>/”。
- 验收：3/3 pth `unexpected=0` + `infer` 有限；无 index 明示；转换报告可追溯。

### M0.6 DSH 音乐插件闭环（3–4 天）
- 建 `ams-plugins` pnpm workspace；`@ams/plugin-core`（Host）：Gateway 客户端 + `music_ping`/`music_job_submit`/`music_job_status` 工具 + 设置 schema。
- `@ams/plugin-ui`（Client）：`main` 整页 + `sidebar.panellist` 入口，页面调 Gateway 创建/展示 job。
- 打包成 bundle 安装到测试 profile；验证 AI 能调用、人能在页面操作。
- 验收：Agent 一句“跑个测试任务”能创建 job 并在页面看到进度；人工点击同样能创建。

### M0.7 后端冒烟（2 天）
- RVC：用本机曼波 pth 对 1 分钟干声做换声，记录耗时/显存/输出。
- pymss：安装独立环境（uv + Python 3.12 + torch cu128），对 1 首歌做人声/伴奏分离，记录耗时/显存。
- 产出 `07_执行计划/验证/后端冒烟报告.md`；确认 12GB 显存下的参数边界。

### M0.8 更新清单工具（1–2 天）
- 脚本：扫描构建产物 → 生成 `ams-update/1` 清单 → Ed25519 签名 → 校验器；篡改/回滚测试。
- 验收：清单可被启动器模拟器验证；sequence 回退被拒绝。

### M0.9 工程基线与备份（1 天）
- 6 仓 README/LICENSE/.gitignore/CI 骨架；初始 commit + push；`git bundle --all` 备份脚本。
- 验收：任一仓库新 clone 可构建（至少能安装依赖/跑空测试）。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| DSH 构建依赖 Node/pnpm 版本敏感、首次安装慢 | 按官方 dev 指南钉版本；先跑官方 web 再改；保留失败日志 |
| 客户端插件构建链（clientBundle/Typert）未发布 | M0.6 先复刻官方示例构建；失败则用“Host 插件 + 本地 HTTP + iframe 页面”兜底 |
| 12GB 显存不足 | 训练/分离串行、降 batch、分块；M0.7 实测后定参数 |
| 40k MSVC 数据边界校准 | 用参考模型相关 + 边界搜索；预留 1 天缓冲 |
| Windows 非 ASCII 路径/旧 torch | 工具先写 ASCII 临时文件再移动（已实现） |
| 代码签名/更新源未定 | M0 只做未签名内部包；正式签名在 M1 决策 |
