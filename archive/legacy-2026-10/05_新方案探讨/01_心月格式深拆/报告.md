## 0. 硬结论（Lead 要求优先回答）

### ① MSVC 里的 457 个张量能否还原成标准 RVC v2 state_dict？能否被 RVC20260311 runtime 加载/推理？
**结论：能 —— 已完整还原 457/457 张量，标准 `SynthesizerTrnMs768NSFsid` 加载成功（0 unexpected keys），并成功跑通一次 `infer()` 推理。**
证据链（均为本次实测）：
1. **格式解析**：`MSVC` + `01 00` + `XINYU_AI` 头（14B）+ 3 个「u32 长度 + 反转 payload」记录 + 16B trailer；逻辑内容 = 4×metadata(1692B) + 张量表 JSON(50,824B) + FP16 数据(57,433,988B)。详见 格式.md。
2. **张量表完整恢复**：R2 块反转后含 5 段 JSON 碎片，按文档偏移顺序拼接并修正边界污染字节后得到**合法 JSON**，457 个 tensor 条目，字段 key/dtype/shape/offset/length 齐全，`length=prod(shape)*2` 全部通过，offset 严格递增。
3. **与标准 RVC v2 key/shape 对比**：457 keys 全部属于 `SynthesizerTrnMs768NSFsid`（enc_p/dec/flow/emb_g 系），shape 与 RVC 结构一致；`spk_embed_dim=109`、config=[1025,32,192,192,768,2,6,3,0,'1',[3,7,11],[[1,3,5]×3],[12,10,2,2],512,[24,20,4,4],109,256,48000]。
4. **数据闭合**：sum(tensor.length)=57,433,988 = 5 个数据分片长度之和（逐字节闭合），证明权重数据**明文、无缺失、无加密膨胀**（fp16 有效性 99.99% 区段为 1.0）。
5. **分片顺序**：物理顺序≠逻辑顺序；用「与开源 RVC 爱莉希雅.pth 逐张量 std 对数相关」搜索 5! 排列，最优 (D2,D4,D0,D1,D3)（corr=0.686；参考为不同训练模型，非同模型故<0.9）。小分片置信度中等（仅影响 emb_g 等尾部张量）。
6. **生成样本**：`samples\爱莉希雅.msvc_reconstructed.pth`（57,575,599 B，含 weight/config/info/sr/f0/version，457 张 fp16）。
7. **加载日志**（RVC20260311 runtime 3.9.13 + torch，CPU）：`load_state_dict(strict=False)` → `unexpected=[]`，`missing=103` 且**全部为 `enc_q.*`**（RVC 推理模型本就不含后验编码器，属正常）。
8. **推理日志**：`net.eval().float()` 后 `net.infer(phone[1,100,768], len, pitch[1,100], pitchf[1,100], sid[0])` 返回 tuple(len=3)，audio shape `(1,1,48000)`、数值有限（min -0.3384 / max 0.3733 / std 0.0592）；输出已写 `samples\infer_test.wav`（48 kHz，96,044 B）。
（CPU 无法做 fp16 addmm，故转 fp32 验证结构与推理；GPU 上用 fp16 为原生产路径。随机输入≠真实音质验证，仅证明模型可运行。）

**结论评级**：结构级「可加载」= 100% 证实；「数值一致性」= 高置信但未与原权重逐值比对（原件不可得）；「可分片规则通用化」= 部分（3 个 .msvc 应同构，需对另两个文件套同一流程验证，本次时间不够）。

### ② .cyd / Fernet 是否找到可用密钥或派生方式？能否解密？
**结论：不能。未在明文产物中找到密钥或派生逻辑；密钥/算法实现都在 `.cyd` 加密模块内部（自引用）或服务端。**
- 【事实】`.cyd/.bgx/.json(加密)` magic：`CYD1`、`VCLC1`、`BGX1`、`CFG1`、`FXJ1`，香农熵 7.9–8.0（接近随机），PCA 无可见结构。
- 【事实】服务入口 `main.pyc`（PyInstaller 解包可读）import `cryptography.fernet`；但明文代码里**只有调用**，无密钥常量；`configs\vcon.json` = `enc-v1:<32hex>:<32hex>`（密文不可解）。
- 【事实】客户端内嵌 Python 脚本（从 Electron `main\index.jsc` 的 V8 字符串中恢复，约 3 KB）显示的另一套机制：**encrypted-pth** = 加密 pth + 文件末尾身份牌 `b"XINYU_OFFICIAL_IDENTITY_CARD_2024"`，解密入口 `infer.lib.encode.smart_pth_decrypt_data{,_with_identity}`——这两个函数位于 `infer\lib\encode.cyd`（加密），无法读取。
- 【事实】客户端收集机器指纹（`HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid`、Win32_BaseBoard/BIOS/ComputerSystemProduct SerialNumber/UUID、`wmic csproduct get vendor`）→【推断】`unique_code`/许可证/云模型校验与机器绑定；"enhanced" 的额外层 = 容器级（整段反转 + 记录 TLV + 分片重排 + 机器相关唯一码），**不是**对权重内容的强加密。
- **卡点**：解密实现与密钥都在 `infer/lib/*.cyd` 自身和/或服务端下发逻辑里，属"自锁"；需动态调试服务进程（本任务禁止运行）或从内存 dump 出解密后的模块才有下一步。

## 1. 方法（只读、可复现）
1. 解析 PE/PyInstaller/asar 既有产物（上一阶段 task-3 的 extract\）。
2. 对 .msvc：文件头/记录扫描 → 反转 → 文本片段与数据片段分类（可打印率、fp16 统计）→ JSON 碎片拼接（按 offset 递增 + 边界污染字节修正）→ 得 457 张量表。
3. 用开源 RVC 运行时（`F:\ai歌曲\RVC20260311\runtime\python.exe`，`-B`，cwd=输出目录）加载参考模型 + `infer.lib.infer_pack.models.SynthesizerTrnMs768NSFsid` 做加载/推理验证；未写 RVC 目录。
4. 数据分片顺序：对 5! 排列，用"逐张量 std 与参考模型 std 的对数相关"打分选优。

## 2. 与开源生态的互操作 / 是否建议支持 .msvc 只读导入
- **技术上可行**：MSVC 只是标准 RVC v2 推理权重的容器化重打包，解析后与开源 RVC 完全等价（本次已验证加载+推理）。
- **建议**：开源栈可实现 **只读导入器（import only）**：
  1) 解析 MSVC 头/TLV；2) 还原 metadata；3) 拼接 JSON 碎片得张量表；4) 按 offset/length 抽取 FP16；5) 组装 state_dict（.pth）。
  - 注意：JSON 碎片边界与分片顺序是"增强"混淆的一部分，需要为每个文件做**布局推断**（本次用文本连续性 + 统计相关完成）；建议做成"通用 + 人工校验"流程，而非硬编码偏移。
- **不导出/不打包其权重**：仅在用户本地把用户自有文件转成开源格式；不得把心月模型权重随开源项目分发。
