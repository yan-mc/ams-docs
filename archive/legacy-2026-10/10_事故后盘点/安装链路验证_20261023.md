## 步骤与结果

1. **启动器安装**：NSIS 安装到 F 盘，生成 `ams-launcher.exe`、`uninstall.exe`、`data`；注册表 InstallLocation=`F:\AMS-Studio`。
2. **组件安装（启动器 UI）**：点击“检查组件清单”识别 4 个组件，点击“下载并安装全部”，4/4 成功：
   - `kernel.ams.dsh 0.2.1-rc.2`（388,510,583 B）
   - `plugin.ams.music.bundle 0.3.0`（21,999 B）
   - `service.gateway 0.1.0`（16,503,831 B）
   - `catalog.models 2026.10.19`（707 B）
3. **内核初始化（启动器 UI）**：点击“启动内核”，生成 `kernel/dsh/profiles/desktop`、`sessions`、`runtime/kernel.json`、`runtime/kernel.log`；通过 URL 打开页面标题 `AMS Kernel`，`welcome=False`。
4. **插件安装（启动器 UI）**：停止内核后点击“安装音乐插件到内核”，profile 生成 `node_modules/@ams/{plugin-core,plugin-ui,music-bundle}`；package.json bundles 包含 `@ams/music-bundle`。
5. **插件重启与页面**：重启内核，页面 `plugin=True`；Gateway 通过启动器 UI 启动，health/ok；`/ams/api/session`、`/ams/api/connection`、`/ams/api/summary` 正常；侧栏显示“AMS 音乐”。
6. **插件任务桥**：经 `/ams/api/jobs` 提交 `ping` 成功；提交 `mock.long` 后取消，最终 `cancelled`。

## 修复的问题

- 启动器原先只有组件下载，没有插件安装入口：新增“安装音乐插件到内核”按钮，调用 DSH CLI 安装 3 个插件包。
- 连接设置写入空 profile 时，把 `- id` 追加到已有 `[]` 后导致 YAML 解析失败：现在会移除空数组标记、规范 patch，并补上标准 profile 项。
- 首次启动仍弹“添加一个 API Key”：原因是使用了非标准 entry id `llm-deepseek-ams`；改为标准 `llm-deepseek` + `DEEPSEEK_API_KEY` 凭据引用，模型自动选中 `DeepSeek-V4.1-Flash`，弹窗消失。
- profile 初始化补上 `agent-default-model`、隐藏账号/设置/旧账号 provider。
