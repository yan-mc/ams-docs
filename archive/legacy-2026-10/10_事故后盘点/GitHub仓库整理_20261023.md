# GitHub 仓库整理与 submodules（2026-10-23）

## 结果

- 删除遗留 GitHub 身份 `x-access-token`：GCM、`.git-credentials`、Windows 凭据均不再包含它，只保留 `yan-mc`
- 新建总仓库：`https://github.com/yan-mc/AMS-Studio`（private）
- 7 个 AMS 子仓库以 Git submodules 接入：

| 目录 | 仓库 | 职责 |
|---|---|---|
| `launcher/` | ams-launcher | 桌面启动器、安装/更新、内核/Gateway 生命周期 |
| `kernel/` | ams-harness | AMS Kernel（DSH fork），无登录直接工作区 |
| `plugins/` | ams-plugins | 音乐工作台 UI、Host 工具桥、SSE |
| `services/` | ams-services | 本地 FastAPI Gateway + RVC/pymss/MSVC 任务 |
| `tools/` | ams-tools | MSVC/XINYU_AI → RVC pth 等转换 |
| `docs/` | ams-docs | 方案、计划、测试、发布、事故记录 |
| `release/` | ams-release | 签名更新 feed、Release 资产、打包脚本 |

- 每个子仓库的 README 顶部都加了“这是干什么的”封面说明；GitHub About 描述和 topics 也逐个写好
- 7 个 submodule 都指向各自最新 `main`，并在 `.gitmodules` 中设置 `branch = main`

## 验证

- `git clone --recurse-submodules --depth 1 https://github.com/yan-mc/AMS-Studio.git` 成功
- fresh clone 中 7 个子模块全部 checkout 成功，README 正确渲染
- umbrella README 可通过 GitHub 正常读取
- `GCM_INTERACTIVE=never` 下 `ls-remote`/`push` 不再弹账号选择

## 注意

- 总仓库与源码子仓库保持 private；`ams-release` 仍 public
- 如果以后把总仓库改为 public，private 子模块对未登录用户不可见；需要同时公开源码仓库或改为“发布镜像”模式
- submodule 指针固定到本次整理时的提交；子仓库后续更新后，在总仓库执行 `git submodule update --remote` 并提交指针
